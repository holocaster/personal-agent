# One Call Log file per Session, not one file for all history

The Call Log was a single `router_log.jsonl` that every Session appended to forever. Making it capture a Session's full flow (`session_start`/`session_end`, answers, Tool executions) forced the question of where those lines go. We considered keeping the single file and relying on the new `session_id` field to separate Sessions within it, and rejected it: a reader wanting "what happened in the run I just did" would still have to find where it began inside every run that came before, and the file's unbounded growth — already a known wart, unrotated and untrimmed — would get worse now that each Session writes several times as many lines. Instead each Session mints a Session Id (sortable UTC timestamp plus a short random suffix) and writes its own file under a gitignored `logs/`. `ROUTER_LOG_PATH` keeps its role as the override but changes meaning from the exact file to the base path the Session Id is inserted into. Every line still carries its own `session_id` and a `type`, so a line pulled out of its file stays meaningful.

## Consequences

`grep` over all history is no longer one file — it is a glob over `logs/`, and any tool that hardcoded the old path breaks, including the test suite, which must resolve a Session's file through `call_log` instead of assuming a filename. We traded an unbounded file for an unbounded directory: this does not solve retention, it only bounds what one file holds. Rotation or pruning, if ever wanted, is now a directory-level problem and is deliberately not solved here. Revisit only if reading across Sessions becomes a routine need rather than an occasional one, and then by adding a reader over `logs/`, not by merging the files back.

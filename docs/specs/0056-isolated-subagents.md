# 0056: Isolated subagents

## Problem Statement

Personal Agent can load `sdd-main`, but cannot execute its named planner, implementer, and independent reviewer. Reusing the parent Conversation or invoking another REPL in the same process would share Session, Tool Registry, workspace, and Background Job state. Global Skill instructions can be loaded, but their relative support files have no bounded access path.

## Solution

Offer named Subagents through one native `agent` Tool. Each delegation runs the existing Router in a fresh process and Session, returns its answer or handoff to the parent, and keeps the parent task's Provider/model, Runtime Configuration, Agent Mode, and confirmation policy. Roles narrow available Tools. Only one child runs at a time; children cannot delegate or ask the user product questions.

Extend the existing `skill` Tool to read bounded relative support files. Make the installed SDD dependencies discoverable by linking their existing directories into the global Skills directory.

## User Stories

1. As a user, I want `sdd-main` to execute the named planner, implementer, and reviewer, so that its stages have independent context.
2. As a parent task, I want a catalog of actual named roles, so that I can delegate to the required role without guessing instructions.
3. As a user, I want valid workspace definitions to override installed definitions, so that a project can customize its agents.
4. As a user, I want each selected definition preserved as a complete unit, so that duplicate files cannot combine privileges.
5. As a user, I want children to use my selected Provider/model and existing credentials, so that role metadata cannot change my route or cost policy.
6. As a child, I want fresh Conversation, Summary, Todo and process state, so that my reasoning is independent of the parent.
7. As a child, I want the project rules, selected role, task and references, so that I can work without the original conversation.
8. As a user, I want role Tool restrictions enforced during execution, so that a forged Tool request cannot bypass the role.
9. As a user, I want the current Agent Mode and Tool Confirmations to apply to children, so that delegation preserves my execution boundaries.
10. As a parent task, I want product questions returned in the child's handoff, so that I remain the user's point of contact.
11. As a child, I want required Skill instructions and support files, so that installed workflows can be followed without broad filesystem access.
12. As a user, I want children to share my Workspace Root and Git checkout sequentially, so that artifacts and code are available to the next stage.
13. As a user, I want linked child Call Logs, so that I can distinguish parent and child evidence.
14. As a user, I want visible spend to include child work exactly once, so that delegation does not hide or duplicate costs.
15. As a user, I want Ctrl+C to stop the child and its Background Jobs, so that interrupted work does not continue unnoticed.
16. As a user, I want failures and missing roles to be explicit, so that a generic agent is never silently substituted.

## Implementation Decisions

### Requirements: bounded Skill resources

- **R01 — Preserve Skill loading.** Keep effective workspace/global precedence, global directory symlinks within the user's home, immutable advertisement checks, `/skills`, `/skill`, `skill(name)` and `skill(names)` behavior. Extend `skill` with optional `path`, legal only with singular `name`. `skill(name, path)` reads one support file relative to that Skill's resolved directory; it neither executes the file nor activates the Skill for later tasks. Existing instruction result shapes remain unchanged; a resource result identifies `name`, `path`, and text `content`.
- **R02 — Bound resource access.** Accept a nonempty relative path of at most 512 characters with no `..` components. Resolve it under the revalidated effective Skill directory, including a legitimate global directory symlink. Refuse absolute paths, escaping/retargeted links, nonregular/unreadable files, NUL/binary/non-UTF-8 data, `.env`, `*.pem`, `*.key`, and private recovery storage. Read at most 32 KiB plus an overflow sentinel; refuse oversized files rather than silently truncating instructions. Each resource result is bounded to 32 KiB of source content. Resources are not recursively included or executed. A changed advertised Skill identity/source/instructions requires a new parent task advertisement, as today. Read the requested resource's current bytes after validation; resource contents are not part of the Skill instruction snapshot.
- **R03 — Make installed dependencies reachable.** Preserve the existing `~/.agents/skills/sdd-main` link and add absent directory symlinks for `sdd-grill-with-docs`, `sdd-codebase-design`, `sdd-to-spec`, `sdd-to-tickets`, `sdd-implement`, `sdd-security-review`, `sdd-code-review`, and `sdd-diagnosing-bugs` to their existing `~/.codex/skills/<name>` sources. Verify the existing `grilling`, `domain-modeling`, and `tdd` dependencies and their referenced support files. Do not overwrite an unrelated existing directory/link, copy instruction bodies, add startup installation, or build an installer. This is a local setup action recorded in verification evidence; tests use temporary homes rather than depending on this machine.

### Requirements: named definitions and dispatch

- **R04 — Discover complete named roles.** Scan immediate `.md` and `.toml` files in each scope's `.agents/agents`, `.claude/agents`, and `.codex/agents`. Select the first valid definition per name: all workspace locations precede all global locations, and locations within a scope follow that order. Sort filenames for deterministic diagnostics/output. A valid lower-priority source may replace an invalid higher-priority candidate, with the invalid source reported. Never merge bodies, Tool lists, or metadata across duplicates. Names use the existing Skill-style lowercase/digit/hyphen convention, at most 64 characters; a declared name must match the filename stem. Reject ambiguous same-name candidates in one location rather than choose by extension.
- **R05 — Parse only explicit formats.** Markdown uses YAML frontmatter and a nonempty body; require a matching `name` and nonempty `description`. TOML uses a nonempty `developer_instructions` string, derives name from the stem when absent, and uses a nonempty `description` when supplied, otherwise the name as a catalog description. Both may declare `tools` as a comma-separated string or string array; absence differs from an empty explicit list. Ignore model-selection metadata for execution. Other metadata grants nothing. A natural-language instruction such as “Read and follow /some/role.md” remains literal text, never an import directive. In this installation, the complete global Claude Markdown SDD definitions therefore win over the Codex TOML pointers.
- **R06 — Bound and revalidate definition sources.** Definition files are regular UTF-8 text without NUL, at most 32 KiB. Workspace sources and resolved links must stay within Workspace Root; global sources and resolved links must stay within the resolved home directory. The named agent directories themselves must stay within their scope. Symlinked global SDD role files under home are supported. Revalidate selected origin, canonical identity and source fingerprint before spawning; a changed/removed/retargeted advertised role fails visibly rather than switching to another definition mid-task. No generic fallback or arbitrary role-file argument exists.
- **R07 — Expose one delegation Tool.** `agent(name, task, references?)` is advertised to parent tasks with the effective names, descriptions and origins, without embedding every role body. `name` is at most 64 characters; `task` is nonblank and at most 32 KiB of UTF-8; `references` is an optional array of at most 16 nonblank strings of at most 512 characters each. References are supplied context locators, not files automatically imported by the runner. The selected child can read permitted workspace references and load permitted Skills. Missing/invalid/unavailable roles and arguments produce Tool errors before any child Provider dispatch. Keep catalog diagnostics available in the Tool description/result without exposing credentials. No separate `/agents` command is needed.
- **R08 — Return a bounded handoff.** A successful Tool result identifies role and child Session Id, `status: completed`, and the child's final answer. Provider/child/protocol failures identify `status: error` and a concise error, with the Session Id when created. The answer may itself contain a role-specific structured handoff, including `questions_pending` or blocked status; preserve it as text rather than attempting to interpret arbitrary YAML as runtime control. Limit returned answer content to 32 KiB with an explicit truncation marker and child Session locator; retain the full final answer under existing Call Log/Conversation rules. An interrupted delegation records an interrupted outcome before interrupting the parent turn, when persistence is possible.

### Requirements: isolated execution and capabilities

- **R09 — Reuse the Router in a separate process.** A small Subagent runner starts a fresh Python worker process and calls the existing `route` function once for the delegated task. Use standard-library process/IPC facilities, not another REPL, thread-based child execution, external agent CLI, new dependency, or orchestration framework. Child initialization owns its own Call Log, Registry, Workspace configuration, shell/MCP/web configuration, Todo state and file checkpoint. Share only the Workspace Root/files/Git checkout and the explicitly transferred task configuration and context. Parent process state remains intact when the child returns or fails.
- **R10 — Keep the route immutable.** Transfer a serializable copy of the already admitted parent task's Runtime Configuration, including Provider/model, credentials, context budget/capacity overrides, offering/capacity snapshot, and Tool-round allowance. Do not reload dotenv, select a per-role model, fetch a new catalog, or reread changed environment settings to choose the child's route. Child retries, Tool follow-ups and Compression stay on this snapshot. Reconstruct optional Tool configuration only from the parent task's configured capabilities; an unset parent shell/websearch/MCP capability cannot appear in the child.
- **R11 — Start fresh context.** Give the child the existing bounded Project Instructions load, the selected role's instruction body, explicit isolation/permission rules, and the supplied task/references. Do not copy parent Conversation, Summary, Todo List, pending continuation, fetched URLs, provider replay, Memory Notes, or active Skills. In particular, an active parent `sdd-main` Skill is not active in the child. Advertise discoverable Skills normally; the child loads required Skills itself. Selected role instructions remain subordinate to execution gates and explicit task scope.
- **R12 — Intersect Tool permissions.** Begin with the Tools configured for the parent task, apply the selected role's explicit allowlist when present, always remove `agent` and `question` for children, and apply live Agent Mode at advertisement and execution. An absent list inherits only that parent set; an empty explicit list grants no Tools. Enforce the same restriction before argument validation, preparation, confirmation or side effects, even for fabricated Tool names. Tool-use guidance in the System Prompt reflects the effective available Tools rather than directing the child to an unavailable helper. Skills, role text and returned handoffs cannot add capabilities.

  Recognize native Tool names literally. Map the installed roles' vocabulary as follows; each expansion is still intersected with the parent's configured set:

  | Role token | Personal Agent Tools |
  |---|---|
  | `Read` | `read_file` |
  | `Grep` | `search_text` |
  | `Glob` | `list_files` |
  | `Write` | `write` |
  | `Edit` | `edit` |
  | `Bash` | `shell`, `job_status`, `job_stop` |
  | `Skill` | `skill`, including its bounded resource operation |
  | `TodoWrite` | `todo` |
  | `WebFetch` | `webfetch` |
  | `WebSearch` | `websearch` |

  Unknown plain tokens grant nothing and appear in diagnostics; an explicit list containing only unknown tokens remains empty. Reject unsupported parameterized/pattern permission syntax such as `Bash(git:*)` as an invalid definition rather than widening it to unrestricted Bash. `Edit` does not implicitly grant `apply_patch`, and `Read` does not grant arbitrary global filesystem reads. This is capability restriction within the existing Tool system, not a shell sandbox; a role that declares Bash retains the parent's ordinary shell behavior.
- **R13 — Keep one first-level child.** Synchronous dispatch completes or stops a child before another starts, including multiple `agent` calls in one Tool batch. A second concurrent/reentrant invocation fails before spawn. Children neither advertise nor execute `agent`, even when their role requests it, and never start nested children. No role-name special cases encode SDD stages in the runner.
- **R14 — Preserve live Agent Mode and confirmations.** The parent terminal remains the sole input owner. Relay child Tool Confirmation requests with role and child Session attribution through the existing preview/approval/Strong Confirmation path, then return the answer to the waiting child. Sync the parent's current mode at child Provider/Tool boundaries and recheck it after a pending confirmation: plan prevents mutation even after approval; switching to auto does not approve a pending prompt. Network and MCP confirmation rules and Dangerous Command rules remain intact. Closed input/IPC or missing confirmation support rejects the operation, never auto-approves it. Product questions are returned in the role's final handoff; fabricated `question` calls fail without prompting the user.
- **R15 — Preserve workspace and checkpoint boundaries.** Configure the child to exactly the captured Workspace Root and parent limits. Existing Workspace Tool path, secret-file and recovery-storage exclusions remain unchanged; only the bounded `skill` operation may read validated global Skill resources. Child path mutations use their own Session/execution file checkpoint with the existing prepare-confirm-revalidate ordering. Do not merge child checkpoint images into the parent or expose them through handoff text. Shared-file changes continue to trigger ordinary checkpoint conflict refusal. Shell effects retain the existing exclusion from file recovery.

### Requirements: lifetime, evidence and spend

- **R16 — Link distinct Sessions.** Each delegation mints a child Session Id, creates its own project-scoped Call Log v3 and Run, and records `session_kind: subagent`, `parent_session_id`, parent execution identity, parent Tool call id, and agent name in compact start metadata. The child has an ordinary explicit submission opening and one Turn End for its task. Its Conversation is self-contained and starts empty; it has no `conversation_forked` seed. Add parent start/finish delegation records attributed to that same execution/Tool call. Fork keeps its existing copied seed validation and behavior; distinguish kinds explicitly rather than weakening malformed-Fork checks. Existing normal/Fork v3 logs remain readable without migration.
- **R17 — Count physical Attempts once.** Physical Provider Attempts, including retry/failure/Compression usage and pricing provenance, live only in the child's Call Log. Forward compact cost receipts identifying the child Session and original Attempt id; persist parent attribution and credit each receipt once. Duplicate IPC deliveries and terminal completion must not add cost again. Parent visible Run spend, `/usage`, Status Footer and `session_end` total include known child costs, even on failure/interruption, without fabricating parent Attempt records. Extend `/report` with a bounded, separately labeled delegated-cost subtotal/coverage and linked child Sessions; preserve its existing own-Attempt counts, tokens and latency groups. Missing/invalid child cost remains visibly unknown, never asserted zero or repriced. Parent Resume resets current Run spend normally and does not recharge historical receipts; Session reports retain historical delegated evidence.
- **R18 — Survive incomplete child outcomes honestly.** Forward/record cost evidence as Attempts complete, not only on successful child return. On orderly or unexpected worker exit, reconcile against available child Call Log evidence with bounded reads and deduplicate by the original Attempt identity. Preserve known subtotal and label incomplete/unavailable coverage if a failure or scan bound prevents reconciliation. Report spawn failure, malformed/closed IPC, worker exception, persistence/audit failure and nonzero exit explicitly. Persistence or enabled-audit failure stops further dependent dispatch under existing fatal-write rules. Transfer credentials/configuration over private IPC, never command-line arguments or temporary plaintext config files; keep them out of catalog text, Tool results, Call Logs and detailed payloads through existing redaction.
- **R19 — Stop children and their work.** Ctrl+C during Provider work, Tool work, a confirmation or IPC wait cancels the active child, stops its foreground shell descendants and Background Job process groups, closes its checkpoint/Turn End/Run as interrupted where possible, and joins/reaps the worker before returning terminal control. Child success/error also stops its remaining jobs before handoff. Use bounded graceful shutdown followed by existing process-group termination/escalation; track child-owned groups so a failed worker cannot leave reported jobs running. Keep parent-owned Background Jobs separate and untouched by child cleanup. Unexpected parent-channel loss causes the child to stop rather than continue detached. A failed worker or cancellation must release the sequential-child guard.
- **R20 — Do not resume implicitly.** Persist an interrupted/failed delegation outcome in the parent pending Tool prefix so parent Retry/Resume cannot reconnect to or silently replay that old child execution. Interrupted children are never automatically resumed. A later new `agent` request creates a fresh child Session; no daemon, reattachment protocol or automatic recovery loop is added.
- **R21 — Prove the required named workflow offline.** Exercise planner, implementer and reviewer definitions selected through the approved discovery precedence. Show fresh child requests with the expected Tool sets and role bodies; each can load its required discoverable Skills and support resources. A fake Provider can return representative role handoffs and request allowed/forbidden Tools to prove these paths. Do not require paid Provider requests, execute external coding-agent CLIs, simulate children in the parent Conversation, or claim fake handoffs prove real model planning/review quality.

### Module and interface choices

Use a cohesive Subagent module (or small capability package only if needed) for definition discovery, a serializable invocation/result, process lifecycle and IPC. Integrate its dispatch into the Tool Registry and Router; the terminal supplies existing confirmation/mode/output callbacks. The caller supplies role name/task/references and task execution context; it does not manage a worker or mutate module globals. Keep protocol messages narrowly typed/validated and bounded, covering initialization, live mode, confirmations, Tool/progress output, cost receipts, job ownership and final outcome. No general RPC framework or public process-management API is warranted.

Extend `workspace_skills` for relative resources instead of broadening `read_file` or duplicating a new Skill subsystem. Reuse installed PyYAML and standard-library TOML parsing. Keep ordinary Provider contracts, request translation and Retry logic unchanged. See [ADR-0014](../adrs/0014-native-subagent-process-isolation.md), together with ADR-0002, ADR-0003, ADR-0005, ADR-0008, ADR-0010, ADR-0011, ADR-0012 and ADR-0013.

## Testing Decisions

- Primary seam: the production Router/Tool loop, invoked through `run_repl` where terminal interaction matters. Assert emitted Provider requests, user-visible Tool/handoff output, file effects, reader-visible Call Logs/Reports and surviving processes rather than internal object layout or helper call counts. Validate one increment at a time through the agreed seam.
- Skill seam: `skill` execution plus existing `/skills` and active Skill paths, using temporary workspace/home directories and real links/files. Cover a legitimate global support file, nested relative support path, traversal/absolute/escaping links, source replacement, invalid encoding/file type, excluded file, exact 32 KiB and overflow. Preserve single/multi instruction result shapes and advertisement revalidation. Prior art: `test_workspace_skills.py` and workspace boundary tests.
- Discovery/permission seam: capture advertised definitions and complete requests for conflicting valid/invalid workspace/global Markdown/TOML roles; verify full Claude definition selection over literal Codex pointer, inherited/empty/narrowed/unknown lists, parameterized syntax rejection, ignored model metadata and forged forbidden Tool calls with no side effects. Use synthetic role files; never require the developer's home for the test suite.
- Process seam: run a real fresh worker process through the production bootstrap/Router with a deterministic fake Provider installed inside the test worker. Standard test monkeypatches do not automatically cross a fresh process; allow one narrow injectable worker/bootstrap or process-launch seam for this purpose. Keep the fake in tests, without production environment flags, alternate fake-provider routes, or bypassing child policy/Session setup. Verify isolation by distinct process/Session identity and sent request content; run a second child to expose leaked Todo/Registry/Job state.
- Terminal/lifecycle seam: deterministic fake child Tool requests drive approved/rejected confirmations, EOF, dangerous shell confirmation and plan/build/auto switches while a prompt is pending. Use real bounded subprocesses/jobs and readiness synchronization for cancellation, cleanup and parent-job isolation; timeouts must fail with cleanup rather than leak test processes. Include worker crash and channel loss, a forged child `question`/`agent`, multiple sequential delegates and missing role. Prior art: Agent Mode, questions, Background Jobs, streaming and Fork tests.
- Accounting/persistence seam: known cost fixtures cover successful and failed Attempts, retry, Compression, missing cost, duplicate receipt, interrupted/crashed child, and parent Resume. Independently inspect child physical Attempt records versus parent attribution/receipts; assert parent totals and `/report` own versus delegated coverage. Test malformed Subagent metadata and unchanged malformed-Fork refusal. Preserve audit failure/redaction and checkpoint conflict tests. No tests may call a live paid Provider.
- Regenerate and review all three prompt-surface fixtures when schemas/system text intentionally change, following `tests/README.md`. Run focused tests for each increment and the full available suite at completion. Existing unrelated tests are not to be edited; fixture updates and directly affected assertions must reflect intentional behavior. Report sandbox socket/process restrictions accurately and rerun affected checks with authorized access when required.

## Out of Scope

Parallel children; nested delegation; per-role Provider/model choice; external coding-agent CLIs; automatic child recovery/reattachment; copied parent Conversation or orchestrator Skill activation; generic role substitution; worktrees or workspace sandboxes; changing shell's host-access policy; another installer product; automatic Skill dependency installation; paid evaluation; rewriting Provider contracts; a generic agent orchestration framework; changing unrelated feature 0050 work.

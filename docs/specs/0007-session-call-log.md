# 0007 - Session-scoped Call Log

Brief: `docs/briefs/0007-session-call-log.md`
Vocabulary: `docs/CONTEXT.md`
Constraints: ADR-0001 (technical-failure Escalation), ADR-0002 (hand-rolled REST Provider Contract), ADR-0003 (one Call Log file per Session).

## Problem Statement

Every run of the REPL appends to the same `router_log.jsonl`, forever. A user who wants to know what happened in the session they just ran has to guess where it started in a file that mixes every session they have ever run, and the file grows without bound with nothing to trim it.

Worse, what is in there is only half the story. Each line records that a Provider was called and what it cost, but not what the model actually answered, not which Tools it asked for, and not what those Tools returned when they ran locally. The Tool loop that feature 0005 added is invisible in the record: a session where a model called the calculator three times and then answered looks exactly like a session where it answered directly, minus an unexplained extra Attempt line. Reconstructing a session's flow from the Call Log is impossible today, even though the Call Log is the only durable artifact a Session leaves behind.

## Solution

Give each Session an identity and its own file. A Session Id is minted once when the REPL starts — a sortable UTC timestamp plus a short random suffix — and names that Session's Call Log file under a new gitignored `logs/` directory. `ROUTER_LOG_PATH` keeps its role as the override, but now names the base path that the Session Id is inserted into rather than the literal file.

Inside that file, the Session tells its whole story in order: a `session_start` line naming the tier configuration in force, one line per Provider Attempt — now carrying the assistant's answer text and any Tool calls it requested — one line per locally executed Tool call with its arguments and result, and a closing `session_end` line with why the Session ended and what it spent. Every line carries its own `session_id` and a `type` discriminator, so a line stays meaningful when it is grepped or concatenated out of its file.

Nothing about routing changes. The Router still classifies, retries, and escalates exactly as before; this feature only changes where the Call Log writes and how much of the Session it captures.

## User Stories

1. As a terminal user, I want each REPL run to write its own Call Log file, so that reading back what just happened does not mean finding my session inside a year of history.
2. As a terminal user, I want Call Log files named after a sortable Session Id, so that a plain directory listing already shows my sessions in the order I ran them.
3. As a terminal user, I want Session Ids to carry a short random suffix, so that two sessions started in the same second never overwrite each other's record.
4. As a terminal user, I want Session Ids to be filename-safe, so that I can pass a Call Log path to `jq`, `grep`, or a shell glob without quoting tricks.
5. As a terminal user, I want Call Log files collected under `logs/`, so that my repository root does not accumulate one JSONL file per run.
6. As a terminal user, I want `logs/` gitignored, so that local session records never land in a commit.
7. As a terminal user, I want `ROUTER_LOG_PATH` to keep working as an override, so that I can still put my Call Log somewhere other than the default.
8. As a terminal user, I want the log directory created on demand, so that a fresh clone does not fail its first run on a missing directory.
9. As a terminal user, I want a `session_start` line recording the tier to provider/model mapping in force, so that I can tell which configuration produced the rest of the file without remembering my environment from that day.
10. As a terminal user, I want `session_start` to record configuration without recording secrets, so that a Call Log file is safe to paste into a bug report.
11. As a terminal user, I want one line per Attempt, exactly as today, so that retries and Escalation stay visible as separate lines rather than being collapsed into a turn summary.
12. As a terminal user, I want each Attempt line to carry the assistant's answer text, so that I can read what the model actually said without replaying the session.
13. As a terminal user, I want each Attempt line to carry any Tool calls the model requested, with their ids, names and arguments, so that I can see what it wanted to do before anything ran.
14. As a terminal user, I want one line per locally executed Tool call, so that I can see what the calculator or clock was asked and what it answered.
15. As a terminal user, I want a Tool call that failed validation to be logged as a failed Tool line, so that the record matches what the model was told rather than silently omitting the rejection.
16. As a terminal user, I want Tool lines correlated to the Attempt that requested them by Tool call id, so that I can match a request to its result in a multi-call round.
17. As a terminal user, I want Tool lines written in execution order between the requesting Attempt and the follow-up Attempt, so that reading the file top to bottom replays the Session's real sequence.
18. As a terminal user, I want a `session_end` line, so that I can tell a completed Session from one whose process was killed mid-write.
19. As a terminal user, I want `session_end` to name why the Session ended, so that I can distinguish quitting on purpose from EOF, an idle Ctrl-C, or a crash.
20. As a terminal user, I want `session_end` written even when the REPL exits through an unhandled exception, so that a crashed Session still closes its own record.
21. As a terminal user, I want `session_end` to report total spend for the Session, so that I can see what a session cost without summing lines myself.
22. As a terminal user, I want total spend reported whether or not I set a Budget Guardrail, so that spending is visible in a default setup.
23. As a terminal user, I want every line to carry its own `session_id`, so that concatenating several Session files keeps each line attributable.
24. As a terminal user, I want every line to carry a `type` discriminator, so that a reader can select lines by kind instead of guessing from which fields are present.
25. As a terminal user, I want all lines of a given `type` to share the same keys, so that `jq` expressions do not break on optional fields.
26. As a terminal user, I want `/clear` to leave the Call Log and the Session alone, so that clearing my Conversation does not fork my record or reset my recorded spending.
27. As a terminal user, I want local commands to still make no Provider Attempt and run no Tool, so that inspecting my setup stays free and leaves no Attempt lines.
28. As a terminal user, I want an interrupted in-flight Attempt to still leave no Attempt line, so that the existing distinction between a completed and an aborted call is preserved.
29. As a terminal user, I want routing, retries, Escalation and Attempt numbering to behave exactly as before, so that this change to the record cannot change what I am charged for.
30. As a terminal user, I want the README to describe the new default path, the base-path meaning of `ROUTER_LOG_PATH`, and the four line types, so that I can read my own log files without reading the source.
31. As a maintainer, I want `call_log` to expose how a Session Id resolves to a file path, so that production code and tests agree on where the file is instead of each recomputing it.
32. As a maintainer, I want the test suite to locate a Session's file through that helper, so that a later change to the naming scheme is a one-line change rather than a repo-wide sweep.
33. As a maintainer, I want the in-process Session state resettable, so that tests stay independent of each other's Session Id and running totals.
34. As a maintainer, I want `route`'s public signature, the tier ladder, and every Provider untouched, so that this feature's blast radius is the Call Log and its call sites.
35. As a maintainer, I want no new dependency, so that the project's stdlib-only posture outside LiteLLM's pricing utility is preserved.

## Implementation Decisions

The numbered requirements below are normative. Helper and field names are given where a reader of the log depends on them; internal function decomposition is an implementation choice. Prefer small additions to the existing `call_log`, `router`, and `repl` modules over a new module.

### Session identity and file layout

- **R01 — Session Id.** One Session Id per Session, minted once at REPL start from the system UTC clock plus a short random suffix drawn from the standard library. Format: a compact sortable UTC timestamp, then a separator, then a 6-character lowercase alphanumeric suffix — for example `20260922T142233Z-3f9a2c`. The timestamp component uses no colons or other characters that are awkward in a filename or shell glob. Lexicographic order over Session Ids equals chronological order of their timestamp component. Do not use a bare UUID4 or a bare random id: the sortability is the point (brief, settled decisions).
- **R02 — Path resolution.** `ROUTER_LOG_PATH` keeps its name and its role as an optional override, but its meaning changes from "the exact Call Log file" to "the base path a Session Id is inserted into". The default base path is `./logs/router_log.jsonl`. The resolved file for a Session inserts the Session Id before the final extension, e.g. base `./logs/router_log.jsonl` plus Session Id `20260922T142233Z-3f9a2c` resolves to `./logs/router_log-20260922T142233Z-3f9a2c.jsonl`. A base path with no extension appends the Session Id instead. The parent directory is created on demand before the first write. `logs/` is gitignored; the obsolete `router_log.jsonl` entry is removed from `.gitignore` along with the checked-out file if present. The old single-file, all-Sessions behavior is deleted, not retained behind a flag (brief, settled decisions).
- **R03 — In-process Session state.** `call_log` owns the current Session as module-level state, because `route`'s public signature stays untouched (brief, out of scope) and the Router has no other way to learn the Session Id. It exposes: starting a Session (mints a fresh Session Id, resets the running total, writes `session_start`, returns the Session Id); reading the current Session Id; resolving the file path for the current or a given Session Id; ending a Session (writes `session_end`, leaves the Session Id readable so a caller or test can still resolve the path); and resetting the state. Appending any entry when no Session has been started lazily mints a Session Id without synthesizing a `session_start` line — a `session_start` needs Tier Config the Router does not hold. That lazy path exists so direct `route` callers still produce a usable file; the REPL always starts its Session explicitly, so a real Session's file is always bracketed.

### Entry schema

- **R04 — Common envelope.** Every line is one JSON object with `timestamp` (ISO 8601 UTC, `Z`-suffixed, millisecond precision — the existing format), `session_id`, and `type`, one of `session_start`, `attempt`, `tool_execution`, `session_end`. All lines sharing a `type` carry exactly the same key set, including keys whose value is `null`, so a reader never has to probe for a field's presence. Entries are appended one JSON object per line to the resolved file, opened in append mode and created on demand, as today.
- **R05 — `session_start`.** Written once, first, by the REPL at Session start. Beyond the envelope it carries the resolved Tier Config in force as a tier-keyed mapping of provider and model, for all three Complexity Tiers. It carries no API key, no environment dump, and no other secret.
- **R06 — `attempt`.** Keeps every field the current Call Log line has — `task`, `tier`, `provider`, `model`, `latency_ms`, `cost`, `prompt_tokens`, `completion_tokens`, `ok`, `error`, `attempt`, `cost_estimated` — with their current meanings, including 1-based `attempt` numbering continuing across exchanges within a tier and resetting on Escalation (spec 0005, R15). It adds `answer`, the assistant's text for that exchange (`null` when the Attempt failed or the response carried no text), and `tool_calls`, an ordered list of the Tool calls that response requested, each with `id`, `name`, `arguments` (the parsed object, or `null` when the Provider's arguments were not valid JSON) and `arguments_raw` (the raw string when parsing failed, otherwise `null`). `tool_calls` is an empty list when none were requested and `null` when the Attempt failed. One line per Attempt remains the unit for Provider exchanges; do not collapse an exchange chain into one turn line (brief, scope).
- **R07 — `tool_execution`.** One line per result returned by the Tool boundary for a requested batch, in execution order, including calls the Tool boundary rejected for an unknown name or invalid arguments — the record must match what the model was handed. Beyond the envelope it carries `tool_call_id` (the correlation id from the requesting Attempt), `name`, `arguments` (the object passed to the Tool, `null` when the call was rejected before execution), `ok`, `result` (the Tool's returned object when `ok`, else `null`) and `error` (the error text when not `ok`, else `null`). A batch rejected wholesale as a protocol failure — missing or duplicate Tool call ids (spec 0005, R12) — executes nothing and therefore logs no `tool_execution` line; the Attempt line that requested it already records what was asked.
- **R08 — `session_end`.** Written once, last, by the REPL. Beyond the envelope it carries `reason`, one of `exit_command` (bare `exit`/`quit` or `/exit`), `eof`, `interrupt` (Ctrl-C at an idle prompt), `error` (the Session ended through an unhandled exception); and `total_cost`, a float. `total_cost` is the sum of the non-`null` `cost` values this Session recorded on its `attempt` lines, `0.0` when none. It mixes real and Estimated Cost without distinguishing them, the same posture the Budget Guardrail already takes (`docs/CONTEXT.md`, Estimated Cost), and it under-reports when a Provider returned no cost at all. It is computed by `call_log` from what it logged, not read from the Budget Guardrail, which is optional and may be absent.

### Integration

- **R09 — REPL brackets the Session.** `run_repl` starts the Session before its first prompt and ends it in a `finally`, so a `session_end` line is written on every exit path including an unhandled exception. Determine the reason by initializing it to `error` and setting the specific value at each known exit path before leaving the loop; this adds no new control flow and swallows no exception. Do not restructure the REPL's existing exit handling to chase an exotic reason value. Ctrl-C during a request keeps its current behavior — a printed notice and a return to the prompt — and does not end the Session.
- **R10 — Router logs Tool executions.** The Router logs each Tool result from the Tool loop, after the batch executes and before the follow-up Attempt is made, so the file's line order matches the Session's real sequence. Tool execution is still not a Provider Attempt: it makes no Attempt line, does not advance the Attempt counter, and does not enter Budget Guardrail accounting (spec 0005, R15).
- **R11 — Unchanged behavior.** `route`'s public signature, the tier ladder, Escalation's technical-failure-only trigger (ADR-0001), retry counts and backoff, each Provider's implementation, and the Budget Guardrail's in-memory Session window are all untouched. An interrupted in-flight Attempt still produces no Attempt line. `/clear` still removes only Conversation turns: it does not start a new Session, rotate the file, or reset `total_cost` or recorded spending (`docs/CONTEXT.md`, Conversation lifetime). Local commands still make no Provider call and write no `attempt` or `tool_execution` line — but a Session that only ran commands still has its `session_start` and `session_end` lines, so "the Call Log file does not exist" is no longer the way to assert a command was free.
- **R12 — Documentation.** Update the README's Call Log section and its `ROUTER_LOG_PATH` example for the new default path, the base-path meaning, the per-Session file naming, and the four line types with their fields. Keep it concise — a reader should be able to write a `jq` filter from it. Update `.gitignore` for `logs/`. No new dependency: Session Id generation, path resolution, and JSON writing all use the standard library.

## Testing Decisions

A good test here asserts the artifact the user actually reads: the JSONL file on disk, produced by driving `run_repl` or `route` with the existing fake HTTP boundary. Do not assert on `call_log`'s internal state, do not mock `call_log` out of the Router, and do not test private helpers where the file already proves the behavior.

**Seams.** No new test seam is introduced. Tests keep driving `run_repl` and `route` and keep scripting Provider responses through the single `model_router.providers.http.urlopen` fake (`install_fake_urlopen`). What changes is how a test finds the file: instead of setting `ROUTER_LOG_PATH` to an exact filename and reading that filename, a test sets `ROUTER_LOG_PATH` to a base path under `tmp_path` and resolves the actual file through `call_log`'s path helper (R03) — the same helper production uses. Globbing the directory is acceptable only where a test is specifically asserting the naming scheme. Session Id generation needs no injected clock or random seam: assert its shape by pattern and its sortability by minting two ids, consistent with the project's preference for the fewest seams.

**Prior art.** `tests/test_call_log.py`, `tests/test_routing.py`, `tests/test_repl.py`, `tests/test_tools.py`, and the `install_fake_urlopen` / `tier_env` / `_isolate_router_log` fixtures in `tests/conftest.py`. New tests extend these files rather than introducing a parallel structure.

- Migrate every existing call site that assumes an exact Call Log filename: the `_isolate_router_log` fixture in `tests/conftest.py` now points `ROUTER_LOG_PATH` at a base path inside `tmp_path` and resets `call_log`'s in-process Session state so no Session Id or running total leaks between tests; the exact-path setups and reads in `tests/test_call_log.py`, `tests/test_repl.py` and `tests/test_routing.py` resolve through the helper instead. This migration is part of the work, not a follow-up.
- Prove the file layout end to end: a Session writes to `logs/` under the resolved name by default; `ROUTER_LOG_PATH` overrides the base path; the Session Id appears before the extension; a base path with no extension still resolves; a missing parent directory is created; two Sessions in one process write two distinct files and neither appends to the other's.
- Prove Session Id shape and ordering directly: the pattern, the filename-safety (no colon or path separator), and that an id minted later sorts after one minted earlier.
- Prove the envelope: every line of a driven Session carries `timestamp`, `session_id` equal to the file's Session Id, and the right `type`; all lines of one type have identical key sets, asserted as an exact set the way `tests/test_call_log.py` already asserts `EXPECTED_KEYS`.
- Prove `session_start` content: present exactly once, first, listing all three tiers with their provider and model, and containing no API key value from the environment.
- Prove Attempt content is a superset of today's: keep the existing Attempt assertions passing (fields, retry lines, Escalation chain, cost provenance, attempt numbering), and add that `answer` carries the model's text on success, is `null` on a failed Attempt, and that `tool_calls` carries id/name/arguments for a Tool-requesting response, is empty for a plain answer, and represents unparsable arguments through `arguments_raw`.
- Prove Tool execution lines through a scripted calculator round and a scripted clock round: one line per requested call in order, correlated by `tool_call_id` to the requesting Attempt's `tool_calls`, with the result object on success. Cover a multi-call batch, a rejected unknown-Tool call and an invalid-arguments call landing as `ok: false` lines with error text, and a malformed-correlation batch producing no `tool_execution` line at all. Cover line ordering: requesting Attempt, then its Tool lines, then the follow-up Attempt.
- Prove `session_end` on each reachable exit path by driving `run_repl`: bare `exit`, `/exit`, EOF from an exhausted input stream, and an idle `KeyboardInterrupt`, each recording the documented reason; plus an input stream that raises an unexpected exception, asserting the line is still written with reason `error` and the exception still propagates.
- Prove `total_cost`: sums the costs of the Session's Attempts including retried and escalated ones, is `0.0` for a Session that only ran local commands, and is reported with no `ROUTER_BUDGET_USD` set — it must not depend on a Budget Guardrail existing.
- Update, do not delete, the existing "commands are free" assertions: a command-only Session now yields a file containing exactly `session_start` and `session_end` and zero `attempt` or `tool_execution` lines, replacing today's `assert not log_path.exists()`.
- Prove `/clear` keeps one Session: after `/clear`, later Attempts land in the same file with the same `session_id`, and `total_cost` still includes pre-`/clear` spending.
- Run the full offline suite after each ticket. No live credentials or paid calls.

## Out of Scope

Log rotation, retention, pruning or archival — `logs/` grows unbounded across Sessions, the same posture as the old single file, just spread out. Migrating or importing old `router_log.jsonl` content. Any query, summary or analysis command over Session files; reading them is left to `jq` and `grep`. Changing the Budget Guardrail's source of truth, window, or its Escalation-only gating. Persisting the Conversation, or turning the Call Log into a resume/replay source. Changing `route`'s signature, the Classifier, the tier ladder, Escalation semantics, retry policy, or any Provider. Per-turn or per-Conversation log granularity. Configurable log formats, log levels, or a second log destination. New dependencies.

## Further Notes

This feature adds `docs/adrs/0003-call-log-per-session.md`. The decision clears the three-part bar: it is hard to reverse (the file layout, the `ROUTER_LOG_PATH` contract and every reader's expectation move together, and reverting means re-migrating the same call sites), it is surprising without context (an env var named like a file path that is not the file path), and it carries a real two-sided trade-off — per-Session boundedness and a self-contained record, bought by giving up `grep` over one file for all history and by trading an unbounded file for an unbounded directory. `docs/CONTEXT.md` already records the decision in its Decisions section; the ADR holds the rationale and the rejected alternative, matching how ADR-0001 and ADR-0002 are referenced from there. Adding the `See ADR-0003` reference to `docs/CONTEXT.md` belongs to the orchestrator, which owns that file.

The `call_log` module-level Session state in R03 is a deliberate trade-off against the brief's constraint that `route`'s signature stays untouched. Threading a Call Log object from the REPL through `route` into the exchange and Tool loops would be the cleaner shape and would need no reset helper for tests; it is not done here because it changes a public signature the brief put out of scope. If a later feature has reason to open that signature, collapsing this state into a passed object is the natural follow-up.

# 0052: Session report and terminal streaming

## Problem Statement

Ordinary model output appears only after the Provider returns its complete response. The user cannot see progress while text is generated, and interpreting latency, recorded cost, caching and failures requires reading JSONL manually. Existing Attempt numbers also include Tool follow-ups, so treating them as retries would produce a misleading report.

## Solution

Add a local `/report` for the current Session, including prior Runs after Resume. Stream ordinary assistant text through every existing Provider while retaining complete-response validation, Tool safety, accounting and continuation. Show partial text as provisional and stop after a failure following visible output; explicit `/retry` continues from the last completed prefix.

## User Stories

1. As a terminal user, I want text to appear during an ordinary task, so that I can read progress before completion.
2. As an OpenRouter user, I want streaming to retain my configured host preferences and reported usage, so that changing presentation does not change routing or accounting.
3. As an OpenAI user, I want streaming through Chat Completions, so that my current models and configuration continue working.
4. As an Anthropic user, I want ordinary text without thinking or Tool argument fragments, so that internal content does not become my answer.
5. As a Gemini user, I want native signatures and function correlation preserved, so that Tool follow-ups and resumed pending work remain valid.
6. As a Tool user, I want completed arguments validated before execution, so that a partial stream cannot cause a side effect.
7. As a terminal user, I want each text segment shown once, so that a final print or silent retry does not duplicate it.
8. As an interactive user, I want Ctrl+C and Shift+Tab while waiting, so that cancellation and Agent Mode switching keep working.
9. As a user answering a Question or Tool Confirmation, I want streaming output and keyboard ownership coordinated, so that my answer reaches the intended prompt.
10. As a piped-output user, I want flushed plain text without terminal animation, so that progress can be consumed incrementally.
11. As a user whose stream fails, I want an incomplete-response notice and `/retry`, so that partial output cannot be mistaken for a completed turn.
12. As a user resuming a Session, I want Retry to retain completed Tool results, so that already recorded effects are not repeated automatically.
13. As a user handling credentials, I want known keys masked even when split across chunks, so that streaming preserves existing protections.
14. As a terminal user, I want Provider control characters made visible safely, so that streamed data cannot forge terminal output.
15. As a Session user, I want `/report` without a model request, so that inspecting activity adds no Provider cost.
16. As a resumed user, I want the report to include every recorded Run in this Session, so that a Run spend reset does not erase historical activity.
17. As a user diagnosing delays, I want ordinary execution, tier evaluation and Compression distinguished, so that maintenance time remains visible without printing its content.
18. As a cost-conscious user, I want reported, estimated and missing costs distinguished, so that a subtotal does not pretend to be a complete bill.
19. As a user investigating failures, I want technical retries separated from explicit Retry and Tool follow-ups, so that counts describe the actual recorded behavior.
20. As a user investigating caching, I want missing token/cache fields distinguished from zero, so that missing evidence does not imply no cache use.
21. As a user comparing responsiveness, I want locally measured first-text and completed Provider duration with coverage, so that old or textless Attempts remain unknown.
22. As a user with a damaged or large log, I want the report to disclose incomplete inspection, so that bounded partial evidence is not presented as full Session totals.

## Implementation Decisions

### Local report and recorded evidence

**R01 — Current Session command.** `/report` accepts no arguments, participates in completion/help and follows ordinary local-command auditing. It reads the current project's current Session Call Log, including earlier Runs after Resume, without a Provider request, Tool execution, Conversation replay or mutation. Clear and Undo do not erase recorded activity from the report. Run spend and the Status Footer retain their current Run-only semantics. No historical selector or report configuration is added.

**R02 — Bounded source.** Reuse `session_logs.records` and Call Log's descriptor-based safe opens, captured project identity and Session Id. Validate initial Session/project metadata before trusting aggregation. Retain the existing 8 MiB scan-byte, 8,192-record and 256 KiB retained-record limits. Iterate once without retaining answers, tasks, snapshots or arbitrary group keys; aggregate only the four purpose groups defined below. Bound the rendered summary to 8 KiB UTF-8, including diagnostics, with explicit truncation if necessary. No new filesystem, cursor or index architecture is needed.

Missing/inaccessible/unsafe logs, malformed/oversized/incomplete records, wrong identity, invalid metric fields and exhausted scans are disclosed with source filename/physical line where available. Records with a reader warning are not trusted for metrics. A report based on incomplete inspection is prominently labeled partial, and its figures are recorded subtotals with incomplete coverage, never complete Session totals. The current active Run normally lacks `session_end`; that alone is not damage. Previously unclosed Runs and submissions lacking their Turn End are explicitly unresolved. Unknown event types are ignored for sums; recognized snapshots and audit copies are never counted again.

**R03 — Purpose groups.** Aggregate Attempt rows only, once per physical record, into ordinary execution, tier evaluation, Compression and unknown purpose. New dispatches record `purpose: execution | tier_selection | compression`. For legacy Attempts, `tier_selection` remains evaluation, explicit `compression` or absent purpose with task `/compress` means Compression, and absent purpose otherwise means ordinary execution. An unrecognized explicit purpose belongs to unknown purpose; do not reinterpret it as ordinary. Compression has its own purpose even when triggered while evaluating or executing an ordinary task. Run boundaries are counted from valid start/resume records; Turn End snapshots, upstream lookup records, Tool executions and audit copies do not add Attempts, cost or tokens.

**R04 — Metrics with coverage.** Present the Session Id and inspected Run count, then a compact purpose breakdown and whole-inspected-Session summary containing:

- Attempt count, successful Attempts, failed Attempts and interrupted Attempts; legacy `ok: false` without explicit outcome has a failed-or-interrupted category rather than a guessed cancellation classification.
- Technical retries, with transient and context-overflow counts distinguished, and unknown retry attribution coverage. Explicit user Retry is the count of valid `routed_task_retried` records, shown separately for the Session, including Retry of a previously successful task. It is not inferred from Attempts.
- Sum and mean recorded Provider duration, plus mean first-text latency for measured streaming Attempts; both include valid sample counts versus eligible Attempt counts. First-text coverage additionally distinguishes textless/unmeasured exchanges rather than converting either into zero latency.
- Prompt, completion, cache-read (`cached_tokens`) and cache-write tokens as separate recorded subtotals with known/missing/invalid coverage. No inferred cache-hit rate or token rate.
- Recorded cost subtotals separated into Provider-reported, estimated and unknown provenance, with missing/invalid cost coverage. A missing `cost_estimated` flag does not prove reported billing. Do not call a mixed/partial subtotal an actual bill or silently fill unknown cost with zero.

Only finite nonnegative real numbers count as duration/cost; booleans are invalid numbers. Token counts must be nonnegative integers excluding booleans. Outcome/retry values must match the recorded contract. Validate fields independently so an invalid cost does not discard otherwise valid token evidence. Explicit zero is a known sample; an empty Session has zero Attempts and spend, while no duration/first-text samples means unavailable mean. Sum only recorded values and label incomplete coverage. Provider duration does not identify network, queue or generation causes; do not add Tool duration or human waiting into it, or infer them from timestamps. Avoid percentile dashboards or per-model output.

**R05 — Explicit Attempt attribution.** Extend version-2 Attempt records additively; strict Resume must continue accepting existing logs. New Attempts have the R03 purpose, `outcome: ok | error | interrupted`, and `retry_kind: initial | transient | context_overflow`. Keep existing `ok`, `attempt`, usage and audit links intact. `initial` means the first dispatch of this exchange, including a Tool follow-up or an explicit Retry's resumed exchange. `transient` marks an actually dispatched automatic transient retry; `context_overflow` marks the actually dispatched reduced-input recovery, never a Compression Attempt or local assessment that did not dispatch. Cumulative `attempt` remains cumulative and is never repurposed. Timing begins immediately before Provider dispatch, after assessment/local preparation and busy input setup, and ends when the completed response or failure is available; retries/backoff, Tool execution, evaluator work and human confirmation waiting are not included in a single Attempt's duration.

### Streaming contract and transport

**R06 — Small extension at existing seams.** Add an optional text callback to each Provider's existing synchronous `call`; when provided, request streaming and emit only ordinary assistant text while still returning one completed `(AssistantMessage, usage)`. Without the callback, retain the buffered contract for internal maintenance and existing direct callers. Each real Provider supports this callback after the feature completes. Prepared input, credentials, output allowance, Tool definitions and replay continue through the existing interface. No new transport framework, SDK or dependencies.

The Router's optional stream callback has exchange `start`, `text` and `end` notifications, with text payload only for `text`. Start resets per-Attempt presentation before dispatch; end always settles output after a dispatched exchange, including failure/interruption. Provider callbacks are internal untrusted data; Router notifications carry safe text as defined by R10. The completed AssistantMessage remains authoritative for validation, Conversation, Call Log answer and replay. No streamed delta writes Conversation or counts as a Turn End. REPL ordinary execution and every ordinary Tool follow-up supply streaming callbacks by default; Evaluator and Compression do not.

**R07 — Incremental SSE reader.** Extend the existing urllib transport with a context-managed incremental SSE reader, keeping authentication, POST headers, HTTP timeout and error classification. Use bounded reads, incremental UTF-8 decoding and proper event framing: LF/CRLF/CR line endings, blank-line dispatch, optional `event` names, multiline `data` fields joined with newline, comments/heartbeats and ignorable non-data fields. Events and UTF-8 characters can span any read boundary. Never parse each network read as an independent JSON object or buffer the full HTTP body before the first callback.

Retain at most 256 KiB for an individual SSE event and 8 MiB of assembled response content/Tool arguments/native replay for a single exchange, excluding already prepared input history. Bound indices/block counts using existing Tool batch limits where applicable; avoid sparse unbounded arrays. Overflow, invalid UTF-8/JSON and contradictory/malformed required protocol fields fail visibly; they cannot return a successful AssistantMessage. SSE EOF does not dispatch an unterminated pending event. A cut-off UTF-8 sequence or pending nonempty event at EOF is failure, even if a termination frame was seen earlier. Always close the response on completion, cancellation, callback failure and parsing/Provider errors. No whole-stream background worker or unbounded output queue.

**R08 — Protocol completion, error and usage are separate.** Every Provider owns its final-message assembly and native completion requirements. A finish reason alone is insufficient until its terminal protocol is complete. Continue past finish reasons to collect accounting frames and native signatures. Complete with missing optional usage is permitted and stays unknown; malformed supplied usage fails visibly rather than becoming a zero-cost success. For known accounting fields, validate supplied counts/costs using R04's numeric rules, retain valid fields and prior valid usage if another field later fails, and preserve usage on errors and cancellation. Usage snapshots are cumulative replacements/merges of present fields, never totals summed per chunk. Do not discard a known zero because it is falsy. Error events inside HTTP 200 take the existing Provider error-classification path; expose latest trustworthy normalized usage on the exception. HTTP failures retain their existing behavior. Normal output truncation/termination classification remains available on the completed AssistantMessage for existing policy.

**R09 — Chat Completions Providers.** OpenRouter and OpenAI keep their current endpoints, schemas and configured output-token limits, with `stream: true`; OpenAI also requests `stream_options.include_usage: true`. Select the requested single choice, accumulate its text and indexed Tool id/name/argument fragments, and produce the existing ToolCall shape including complete `arguments_raw`. Parse arguments only after completion; invalid JSON remains a complete rejected Tool intent under the existing Tool boundary, never a partial execution.

Require a valid finish reason and `[DONE]` event. Missing finish, bare EOF, error termination and conflicting finish reasons fail; OpenRouter's content-free accounting frame may repeat the same finish reason without emitting text or becoming another completion. OpenAI's usage-only final frame can have an empty choices array. Preserve OpenRouter's usage/cost/cache data and optional generation-id diagnostics, `sort: price`, `preferred_min_throughput: 85` and `require_parameters` preference. No Responses API migration or extra generation lookup is introduced. Ignore reasoning/refusal/argument metadata as ordinary text rather than displaying it.

### Output safety and failure behavior

**R10 — Chunk-independent protection.** Before any streamed character reaches the terminal, use the task's existing known Provider/Tavily key snapshot plus keys protected across in-Run configuration changes. Incremental masking must produce the same full-secret protection regardless of fragmentation, overlapping keys or matching prefixes. Retain the undecidable suffix required to disambiguate a key prefix; whole-secret buffering or per-chunk `.replace` is insufficient. On failure/cancellation discard an undecidable secret prefix rather than flushing it unmasked. On success safely resolve remaining text before closing the exchange. Keep masking state separate per Attempt so a failed prefix cannot contaminate a retry. Run redaction before terminal control sanitization, and keep the completed-message/logging redaction path intact.

Reuse `sanitize_control_chars(..., multiline=True)` for every delivered string. A split ESC/OSC/CSI sequence, C0/C1/DEL, carriage return or Unicode boundary cannot introduce terminal control execution. Only presentation-owned terminal codes may reach the interactive renderer. Known keys must also remain masked in errors, report identifiers/diagnostics, normalized Tool content and Detailed Audit Payload; do not promise detection of unknown secrets. Native signature metadata remains opaque and is never displayed or reconstructed from sanitized text.

**R11 — Locally delivered first text.** New streamed Attempts record `streamed: true` and nullable `first_text_latency_ms`; buffered Attempts have `streamed: false` and no measurement. Start a monotonic timer at actual Provider dispatch. Record the elapsed milliseconds when the first nonempty safe ordinary text payload has been delivered through the synchronous terminal callback; header, Spinner, reasoning, Tool arguments and empty deltas do not count. Include local safety buffering/output delay. This is not the Provider's first generated token, network decomposition or whole-turn latency. Tool-only and never-delivered streams have null timing. Preserve a measured value on failed/interrupted Attempts. Measured zero milliseconds is valid. Existing logs lacking these fields have unknown streaming/timing evidence and remain resumable.

**R12 — Retry after partial text.** Before any safe ordinary text has been delivered in an exchange, retain the selected-route transient retry budget/backoff and one positive-evidence context-overflow recovery. Once safe text has been delivered, any Provider/protocol failure stops the exchange without automatic retry or context-overflow recovery; this includes final usage validation failure after visible output. Do not silently replay an answer or append its partial AssistantMessage to continuation. Settle the output and show `Incomplete response` with explicit `/retry` guidance. Ctrl+C similarly marks provisional output incomplete and records interruption, not success. Ordinary failures before visible text retain existing failure guidance.

The completed prefix of a failed routed turn still contains exactly the previously validated assistant/Tool messages and recorded results. Retry, including after Resume, continues from it under current configuration and mode; it never reconstructs a failed partial exchange or automatically repeats already completed Tools. A previously completed Tool round's visible text does not suppress transient retry for a later exchange that has not displayed text. Preserve original submission attribution, evaluator input/count, fetched-content warnings, Todo progress and continuation validation.

**R13 — Terminal ownership and exactly-once presentation.** Display streaming as plain sanitized text with an `llm>` label opened lazily on first delivered text per exchange, then flush incrementally. Use a single presentation owner to settle Spinner/busy redraws and text writes; an animated clear cannot overwrite a streamed line. Finish the streamed line before Tool results, Tool Confirmation, Question, Compression notices or errors. Do not render the complete answer a second time at successful Turn End. Text-bearing Tool rounds may display their ordinary text once before their subsequent Tool output; Tool-only rounds do not print `None` or fabricate text. Metadata/footer still updates on completed success. Buffered internal output remains internal; existing history rendering can retain Markdown.

Input Box's existing busy reader remains responsible for Shift+Tab, Ctrl+C and queued next-task typing. Integrate output using the installed prompt-toolkit Application's supported terminal-output/redraw primitives; schedule across its event loop with the correct Application context when required. The text callback must complete delivery without an unbounded queue or a UI-loop cancellation deadlock. Do not start a competing keyboard reader. Mode switches affect the existing next exchange/Tool confirmation policy without redispatching an in-flight request. Busy output drains/settles before confirmation/question ownership begins; callbacks cannot write after cancellation or after the prompt returns. Join the busy reader and close HTTP state on every exit. In noninteractive/NO_COLOR output, emit flushed plain text without new animation/control codes, and retain piped Confirmation behavior.

### Native Provider completion

**R14 — Anthropic Messages.** Stay on `/v1/messages`, API version `2023-06-01`, with `stream: true`. Accumulate indexed content blocks, text and complete Tool JSON deltas. `message_start` input/cache usage plus present `message_delta` cumulative values produce final normalized usage without double counting. Respect block start/delta/stop ordering; valid `message_stop` and completed required blocks/message termination finish an exchange. Handle ping and stream error events; EOF without required stop fails. Thinking/redacted-thinking/signature deltas stay out of visible and normalized ordinary text. Track them only as needed for valid native assembly; do not enable a new thinking mode or add new replay behavior. Preserve the existing Messages Tool serialization, correlation, termination classification and completed-response contract.

**R15 — Gemini GenerateContent.** Use existing GenerateContent `v1beta` request/auth/schema/output limits via `:streamGenerateContent?alt=sse`. Assemble the selected candidate from all chunks, concatenate only ordinary text fragments without inserting a newline between transport chunks, preserve native ordered parts and functionCall ids/args, and omit parts marked `thought` from ordinary text. Native functionCalls in this API arrive as completed objects; do not reinterpret them as OpenAI argument deltas or migrate to Interactions. Preserve `thoughtSignature` exactly on its original part, including an empty-text signature part; do not coalesce signed/unsigned parts, synthesize signatures or normalize signed parts from displayed text.

Gemini has no Chat Completions `[DONE]`: clean SSE EOF after a valid candidate finish reason completes, provided no malformed/truncated event remains. Consume through EOF rather than stopping at finishReason, retaining final usage/signature-only data; latest present `usageMetadata` fields replace earlier cumulative values. Blocked/error/absent usable candidate evidence follows existing failure behavior, never a guessed successful empty answer. Preserve normalized internal generated-id flags without sending generated ids onto the wire, active native replay across Tool rounds, context reduction/rebase, failed-turn continuation and Resume validation. A completed replay prefix, including thought-only/empty signature parts permitted by the API, must validate without weakening function-call/result correlation. No new durable replay schema or migration of old Sessions.

### Delivery and regression constraints

**R16 — Accounting and completed state.** One dispatched Attempt writes one Attempt entry with final available usage even on failure, preserving Run spend and detailed attempt correlation. Only one successfully completed routed turn writes its successful Turn End and enters Conversation. Failed partial exchanges contribute no completed answer/Tool intent to ordinary history or pending replay. Do not log every delta or create a second transcript. Preserve current Tool batch limits, raw-argument validation, confirmation policy, context prevention/recovery, evaluator isolation, Compression, `/usage`, routing selection, Retry and Resume. Report observes recorded Attempts across Runs without changing any of those policies.

**R17 — Isolation and user documentation.** Add concise `/report` help/README documentation and explain normal streaming, partial failure/Retry, locally measured first text, evidence coverage and retained internal buffered maintenance. No new setting or `.env` secret/example is needed. Tests use isolated temporary home/cwd, fixture credentials and simulated streams. No paid live request, credential printing, new dependency, push or unnecessary code comments. Validate small increments and focused tests first; run the full installed suite once all slices integrate, using a permission context that permits existing local-socket fixtures when necessary.

## Testing Decisions

- Highest behavioral seam: `run_repl` with a simulated HTTP response through the real Provider/Router, plus Call Log/Resume. Assert safe text has been written and flushed before the fixture allows its final event; avoid real sleeps and timing-only assertions. A controllable monotonic clock verifies dispatch-to-delivered-text and complete Attempt duration independently of implementation details.
- Reuse `test_provider`, `test_routing`, `test_repl`, `test_input_box`, `test_call_log`, `test_session_logs`, `test_continuation`, `test_context_overflow`, `test_preventive_compression`, `test_session_tier` and `test_detailed_audit` patterns. Add focused streaming/report tests only where they clarify distinct external behavior. Enhance existing fake HTTP responses to script byte fragments/errors and record close/flush order; retain buffered fixtures for maintenance.
- Report fixtures span two Runs, one resumed Session, ordinary Tool follow-ups, tier evaluation, manual/automatic Compression, transient retries, context recovery, explicit Retry, failed/interrupted Attempts, Clear/Undo and duplicated snapshots/audit rows. Independently calculated expected counts/sums must demonstrate no double counting, unknown versus known zero, invalid numbers/provenance and missing legacy attribution. Check incomplete tail/identity/scan limits, unsafe paths, empty Session and no Provider dispatch/state mutation.
- Shared SSE fixtures split every relevant UTF-8/line/event boundary, use multiline data, LF/CRLF/CR, comments/pings, and bounded oversized events/responses. Prove first output precedes terminal events. Check malformed UTF-8/JSON, unterminated final event, early EOF, conflicting terminal fields and proper resource closure.
- Provider-specific fixtures: OpenRouter's repeated finish on usage frame and HTTP-200 error, OpenAI empty choices with final usage, two interleaved indexed Tools, Anthropic block/Tool JSON/thinking/signature events and cumulative input/cache/output usage, Gemini multiple text/thought/function parts including empty signature-only trailing parts. Missing usage remains unknown; malformed final usage retains earlier valid accounting but fails completion. An invalid completed Tool JSON reaches existing validation without a side effect.
- Deliver a known key at every chunk split, overlapping/prefix keys and an old protected key after credential change; test success and failure during an undecidable prefix. Capture text, errors and logs for leakage. Exercise split controls and Unicode. Demonstrate that partial Tool arguments/errors/cancellation never execute a Tool or add an incomplete turn.
- Use existing pipe-input/controlled-thread tests for the real Input Box: stream while busy, queued next-task text, Shift+Tab before/after first text, cancellation during a read/output transition, Question and mutating Tool confirmation, EOF and renderer/callback failure. Assert owned readers/resources are closed, output is not duplicated/erased and piped/NO_COLOR paths retain policy.
- End-to-end native replay test: streamed Gemini Tool completion with vendor and generated ids, partial failure on follow-up, Resume + `/retry`, current mode/credential configuration and one valid correlated follow-up request. Preserve original signature parts through continuation/context rebase without rerunning completed Tools.

## Out of Scope

Historical `/report` selectors, dashboards, percentiles, inferred latency causes, per-model rankings, hidden reasoning display, token-generation benchmarks, background jobs, MCP Tools, file checkpoints, tier-policy changes, monetary caps, configurable streaming opt-in, new vendor APIs/SDKs/dependencies, new thinking features or new Anthropic replay, detection of unknown secrets, log migration/retention, concurrency guarantees for multiple Runs, paid live verification, Git pushes.

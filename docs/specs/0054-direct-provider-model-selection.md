# 0054: Direct Provider and model selection

## Problem Statement

Choosing easy, medium or complex hides the actual model and adds evaluator calls, policy state and configuration that the user no longer wants. The user wants to choose one Provider/model pair from a searchable public catalog, use it consistently, and retain the reliable task, reporting and recovery behavior delivered by 0053.

## Solution

Configure `PA_PROVIDER` and `PA_MODEL`, with only that Provider's API key required. Browse Models.dev through a local cache and select an exact pair with `/model <provider> <model-id>` or `/config`. All ordinary work and Compression use that pair. No evaluator, complexity tier, automatic model substitution or legacy migration remains.

The catalog is metadata, not proof of account access or complete runtime compatibility. Startup uses a valid cached catalog without a network request. Missing/corrupt cache causes one bounded public fetch; explicit refresh replaces it only after validation. Failed refresh preserves the last valid cache and route.

This is an intentional development-format break. Existing files stay on disk; old Sessions are clearly refused by Resume. New Sessions retain Resume, continuation, reports and exact file recovery.

## User Stories

1. As a user, I want four explicit Provider choices, so that configuration matches the adapters actually installed.
2. As a user, I want to search models by ID or display name, so that I can find an exact selectable pair.
3. As a user, I want to browse or refresh without Provider credentials, so that setup does not require an inference call.
4. As a user, I want useful offline startup from my last valid catalog, so that a catalog outage does not block an established setup.
5. As a user, I want malformed downloads to preserve my catalog and settings, so that refresh cannot destroy a working setup.
6. As a user, I want rejection reasons for absent or locally unsupported models, so that I can distinguish metadata admission from remote access.
7. As a user, I want to save Provider/model together, so that changing Provider cannot accidentally save a model belonging to another Provider.
8. As a user, I want only my selected Provider's key required, so that I need not configure unused accounts.
9. As a user, I want tasks, Tools, retries and Compression to use my chosen pair, so that there are no hidden model decisions or evaluator costs.
10. As a user, I want explicit route changes to affect the next task or Retry, so that current work keeps its immutable snapshot.
11. As a user, I want live Agent Mode independent of model selection, so that existing execution gates remain predictable.
12. As a user, I want new Sessions to Resume with Conversation, Todo and pending work intact, so that removing tier policy does not remove continuity.
13. As a user, I want ordinals and separate Retry execution identity retained, so that reports and recovery identify the correct work.
14. As a user, I want actual Provider/model and honest unknown usage/cost, so that reports remain evidence rather than inferred savings.
15. As a user, I want budgets, overflow handling, streaming and cancellation preserved, so that a simpler selector does not weaken execution safety.
16. As a user, I want the latest file-changing execution recoverable after restart with the same privacy and conflict rules, so that removing evaluator state does not risk my files.
17. As a maintainer, I want current help/docs and deterministic prompt fixtures to agree with the direct route, so that historical tier decisions do not appear current.

## Requirements

### Catalog and selection

- **R1 — Fixed Provider set:** Accept exactly `openrouter`, `openai`, `anthropic`, `gemini`; reject unknown values with these choices. Map only our `gemini` key to Models.dev `google`; preserve the offering's exact model ID on the wire. Never infer Provider or capability from an ID prefix. Remote `env`, `api`, `npm`, headers and body metadata cannot configure adapters, credentials or endpoints.
- **R2 — Catalog admission:** Use the selected Provider's offerings, not provider-independent canonical IDs. Eligible models require explicit `tool_call: true`, `text` in both input/output modality arrays, positive integer context/output limits, and no `deprecated` status. Missing/malformed required capability evidence is locally unsupported, not remotely nonexistent. Reject specialized `type` offerings, model-level nonempty Provider overrides, and interleaved reasoning metadata on the OpenAI/OpenRouter adapters whose normalized replay cannot retain it. Native Anthropic/Gemini replay stays unchanged. Alpha/beta labels may remain selectable and must be shown. Missing cost, release metadata, optional input limit or System/Streaming declarations does not by itself disqualify a model. There is no catalog proof of System/Streaming support or account entitlement; selection/help state that remote errors remain possible. No custom Provider, free-form bypass, endpoint override or inference preflight is added.
- **R3 — Cache lifecycle:** Use the fixed public endpoint `https://models.dev/api.json?type=all` and a user-global `~/.personal_agent/models-dev.json` cache. Load a valid cache first, of any age, showing its fetch timestamp and refresh guidance; no TTL, scheduled request or background polling. With no usable cache, attempt one bounded fetch. Fetch/parse/cache failure with no usable catalog stops route setup/dispatch with the explicit refresh command; never substitute LiteLLM, a bundled list or a guessed model. Explicit refresh keeps the last valid disk/in-memory catalog and route on failure and visibly reports failure, even if listing can still use the cache.
- **R4 — Bounded replacement:** Catalog network and cache reads are bounded before parsing; reject oversize, malformed JSON, invalid consumed schema, duplicate identities and incomplete four-Provider envelopes. Fully validate before replacing cache through a private same-directory temporary file and atomic replacement. Failed download, validation or write leaves the prior cache bytes usable. Ignore unknown optional fields without executing them. Fixed limits and schema are specified below; do not reuse the bounded text `webfetch` Tool.
- **R5 — Explicit pair and credentials:** `PA_PROVIDER` and `PA_MODEL` are required, with no automatic default pair. Preserve existing precedence: exported environment, starting-directory `.env`, home `.env`. Only the selected Provider's existing key is required (`OPENROUTER_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`). Retain safe key editing/redaction, context settings and Tool-round settings. `TIER_*` settings are no longer parsed, validated, written, migrated or consulted; old-only setup receives missing-new-settings guidance. Do not delete old files or rewrite unrelated dotenv entries.
- **R6 — Commands and atomic settings:** `/model` shows actual current pair; `/model <provider> <exact-model-id>` validates both fields and the selected credential before saving both settings with one atomic dotenv replacement and then activating them. `/models [provider] [query...]` shows a deterministic searchable eligible list, defaulting to current Provider; query is a literal case-insensitive substring of ID/display name. `/models refresh` explicitly refreshes all four catalog sections. `/config` offers the same pair selection, fixed Provider choices, search/listing, hidden key entry and existing context settings; it cannot bypass catalog validation or save a half pair. Invalid input, cancellation or settings-save failure preserves active route and saved settings. Completion/help follow this grammar and remove tier values and `/model auto`.
- **R7 — Catalog changes:** Refresh does not change selected pair or an in-progress snapshot. If a successfully refreshed catalog omits or disqualifies that pair, retain selection/settings, warn with the local reason, and reject subsequent task/Retry/manual-Compression dispatch until an eligible pair is explicitly chosen or a later valid catalog admits it. Startup uses the same admission rule. Never call an absent model, switch silently, or assert that catalog omission proves account inaccessibility.

### Runtime and durable identity

- **R8 — One route:** Ordinary tasks, Tool follow-ups, transient retries, explicit Retry and all manual/preventive/overflow Compression use the task's selected Provider/model. Manual Compression snapshots the current pair. Remove Tier/TierConfig, evaluator input/prompts/calls, session-tier/policy/checkpoint/keep-raise/fallback logic and their production/test-only compatibility paths. No evaluator cost, purpose, notice or automatic route change remains in newly written Sessions. Preserve no monetary cap and single-route retry exhaustion behavior with direct-selection guidance.
- **R9 — Immutable snapshots:** Capture Runtime Configuration, relevant catalog capacities and Project Instructions at each accepted task/explicit Retry boundary and hold them through Tool follow-ups, same-route retries and automatic Compression. Explicit route/config changes affect later tasks/Retry; live Agent Mode keeps its existing immediate behavior. A Retry retains its original task/ordinal and may use the newly selected pair; pending normalized messages remain usable, while Provider-specific replay is reused only for the same compatible pair. Cancellation, Clear, Undo and Compression retain their established Conversation/pending-work semantics.
- **R10 — Independent execution identity:** Persist original submission text/monotonic ordinal independently of evaluator state. A new submission increments once, including failed/interrupted work; Retry opens a distinct execution with its original ordinal. Tool follow-ups, local commands, Question answers and Compression add no submission. Preserve count across Clear/Undo/Compression/Resume; retain the request needed for Retry/recovery without maintaining a cumulative evaluator-input array. Attempts never open turns. Keep execution identity `(run_id, opening record position, ordinal)` and existing task-digest/contributor lineage; create no new identity scheme.
- **R11 — New persistence contract:** New Call Logs declare `log_version: 3` with direct route, project/Session/Run identity and no tier policy. Start/resume records and explicit submission/Retry openings record Provider/model without secrets; openings establish the execution route even if no Attempt occurs. Continue to record actual per-Attempt routes and execution/compression purpose. Strict replay restores Conversation, Summary, Todo, submission count and pending continuation. Resume uses current validated Runtime Configuration; recorded routes are historical evidence, not overrides of current settings. Unsupported older log versions are refused clearly before append, migration or Tool execution; files remain untouched. New malformed/contradictory state fails visibly rather than guessed replay. Existing append-prefix restoration, durable-before-live/action ordering and fatal audit/persistence errors remain.
- **R12 — New-Session continuity:** New format Sessions support `--resume <id|last>`, current-project recency/discovery, completed/failed/interrupted turns, explicit Retry, clear/undo/compression replay and pending continuation. New Runs retain the same Session Id and reset Run spend and Run-local active Skills. Session discovery remains a bounded read-only recorded timeline; old files may remain historical evidence but cannot become resumable through inference. Keep unsupported-format failure explicit when `last` selects an old Session; do not silently substitute an older/newer Session.

### Preserved execution, evidence and recovery

- **R13 — Capacity and counting:** Models.dev supplies declared limits for the selected offering; exact manual capacity overrides retain priority, then Models.dev per-field limits, then locked local LiteLLM per-field metadata where a field is absent, then the existing labeled assumptions. Optional input limits must be positive integers within context when present; malformed/inconsistent consumed limits cannot increase a budget. Preserve complete prepared-input counting, approximate-tokenizer labeling, stop-on-unmeasurable behavior, context-budget minimum, safety margin, output reserve/allowance and total/input/output constraints. Freeze resolved inputs to these decisions with the task. No tokenizer/metadata download during report or exchange. An eligible catalog model absent from local pricing can still run with unknown Estimated Cost.
- **R14 — Provider behavior:** Preserve all four existing REST adapters/protocols, streaming/nonstreaming translation, normalized failures/partial usage, transient limits, termination protection, Tool execution gates, overflow recovery and cancellation. No catalog metadata is a request instruction. Keep ordinary OpenRouter `session_id` exactly the durable Session Id and Compression `<Session Id>:compression`, across retries/Resume and streaming/nonstreaming; remove the obsolete evaluator suffix. Other Providers accept/ignore optional affinity as before. Keep existing OpenRouter host preferences and diagnostics. Affinity remains best effort per model.
- **R15 — Honest costs and reports:** Footer, startup/piped notices, `/usage`, `/report`, Call Log, audit and discovery show actual Provider/model, with no current tier grouping. Keep bounded Session/purpose aggregates and latest-20 explicit execution rows with at most 16 route/purpose groups, omission notices and 16 KiB rendering bound; route comparison uses Provider/model. Preserve first-text/Provider timing, failed Attempts, cache sample coverage and independent unknown/invalid/zero distinctions. `/report` remains local-only and leaves selection, Conversation, pending state, `/usage` and spend unchanged except its existing Audit Event. OpenRouter reported cost remains authoritative; direct estimates remain flagged and use the locked LiteLLM cache-aware path, never Models.dev prices. Missing pricing/evidence yields unavailable cost, not zero. Run spend charges physical Attempts once and resets on Resume. Do not broaden this feature into the pre-existing Gemini thought-token accounting issue.
- **R16 — Prompts and agent features:** Preserve stable prompt order, full complete-input budgets, deterministic Tool/schema order, Memory, immutable active Skills, Todo, Project Instructions reload/snapshot and live Agent Mode/confirmation behavior. Maintain the complete production `plan`, `build`, `auto` prompt/schema fixtures with isolated synthetic configuration and blocked network. Model-selection simplification does not justify changing prompt instructions; review any necessary fixture diff explicitly and retain execution-gate tests.
- **R17 — Exact recovery:** Preserve ADR-0010 and 0053 R21–R28 for newly created Sessions, including successful mutations in failed/interrupted executions: latest-only exact bytes/absence/modes/leaf-link identity; private bounded owner-only companion; intent-before-write; crash reconciliation; plan preview only; literal `yes` confirmation; whole-set pre/post-confirm conflict and exclusion checks; safe rollback/unresolved reporting; durable completion before success; no shell/Git recovery or older-checkpoint stack. Repeated canonical paths coalesce first before/final after. Keep hard-link refusal and supported in-root leaf links.
- **R18 — Recovery lineage:** Before restoration, durably invalidate continuation for the exact execution and every continuation that includes its contributed results. Preserve the request/original ordinal for a fresh Retry; discard obsolete Tool results, fetched URLs, Todo effects and Gemini replay. Retain unrelated later pending work. Invalidation remains even if restoration later fails. Route attribution for recovery before the first Attempt comes from the explicit opening, never a removed easy route or a guessed Attempt. Images remain absent from prompts, reports, discovery and Call Log; Undo remains Conversation-only.
- **R19 — Current documentation and removal proof:** Update concise README, `docs/ENV_VARS.md`, current `CLAUDE.md`, project metadata, relevant research delivery status and `.notebook` navigation/contracts. Implementers must use `writing-for-agents` for CLAUDE edits. Main owns `docs/CONTEXT.md` current truth at implementation approval and `.ai/PROJECT_STATE.md`; coordinate its update without editing those files. Preserve historical briefs/specs/tickets/reviews; add ADR supersession pointers rather than rewriting history. Remove obsolete-only tier/evaluator/migration tests, replace fixtures/fakes through current contracts, and preserve unrelated behavioral coverage. Search current production/docs for stale tier/env/evaluator dependencies, classifying historical mentions separately.

## Implementation Decisions

### Small interfaces and existing seams

Use one small `model_catalog` module to hide fetch, cache parsing/replacement, eligibility reasons, deterministic search and exact lookup. It returns immutable offering metadata; callers do not interpret remote fields independently. Use stdlib HTTP/JSON/filesystem facilities already available, a fixed URL and no SDK/new dependency. Inject/patch the existing HTTP/file boundaries for offline tests; do not add a generic catalog backend, plugin system or capability framework.

Replace tier configuration/store with direct Runtime Configuration/store in the existing routing area, retaining one immutable configuration snapshot operation and the existing atomic settings writer. Router/Compression receive direct configuration, not a tier selector. Replace SessionRouting policy with only the small submission-progress state still required by explicit Call Log records. Recovery/report/discovery reuse those records and their current readers; no second session-selection file or historical policy adapter.

The canonical selected pair lives in Runtime Configuration and saved dotenv, matching the existing rule that Resume uses current configuration. Historical opening/Attempt routes remain in Call Log for attribution. Successful local selection writes settings atomically before activation; audit/persistence failures remain fatal and must never become a model fallback. Credentials are never persisted in Call Log or catalog.

### Catalog cache and response contract

- Fixed endpoint above; no auth/Provider key, user headers or configured remote URL. Request JSON without compressed transfer; validate HTTP success and JSON media type. Redirects may stay on HTTPS `models.dev` only; reject other destinations.
- Bound response and cache reads to **16 MiB**, counting actual bytes even without a truthful Content-Length. Bound each network operation to **10 seconds** and total fetch work to **30 seconds**, with no automatic retry loop. Parse only after the bounded read completes.
- Cache envelope: integer `version: 1`, fixed source URL, valid UTC `fetched_at`, and a normalized map for exactly our four Providers (mapping upstream `google` once). Store only consumed listing/eligibility/limit metadata, not the entire upstream catalog/prices/descriptions. Validate cache through the same consumed-data contract as network normalization; version/schema failures make it unusable.
- Require each relevant upstream Provider object to have its matching `id` and a model mapping; reject a missing/empty relevant section rather than replace a useful cache with a partial document. Limit each section to **10,000 offerings**, IDs to **256 characters**, names to **256 characters**, and modality lists to **16 entries**. Reject duplicate JSON keys, mismatched map/model IDs and invalid types of consumed fields; unknown optional fields are ignored. Missing capability/limit fields are represented as unknown and ineligible, not fabricated. A well-formed known-incompatible offering is retained with its rejection reason; it is not a malformed whole download.
- Publish cache only after the full four-Provider document validates. Use owner-only temporary file, flush/fsync, same-directory atomic replacement and cleanup; reject linked/nonregular cache targets. Validate bounded content before adopting it in memory. On failure retain the old cache; if an initial successful fetch cannot be saved, report the cache-write failure and retry guidance instead of claiming offline availability.
- Search returns eligible offerings sorted by exact ID and displays ID/name, alpha/beta when present, limits, source/fetch time and a concise metadata-versus-access caveat. Bound rendered lists to **100 rows / 16 KiB** with visible omission and narrower-search guidance. Terminal sanitize untrusted display values; validation always uses the original exact ID. Exact selection distinguishes unknown Provider, missing offering, known-incompatible/incomplete metadata, unavailable catalog, missing selected key and save error.
- A successful refresh can invalidate a selected offering locally without mutating the selection. Validation at the next task/Retry/manual-Compression boundary blocks dispatch with the local reason. Automatic Compression and Tool follow-ups use their already captured route/limits and perform no fresh catalog access.

### Capacity versus accounting

Normalize `limit.context` to total, optional `limit.input` to input and `limit.output` to output. Require total/output positive integers and output no greater than context for eligibility; optional input is positive and no greater than context. Per-field provenance is `manual`, `Models.dev`, existing published LiteLLM provenance or `unknown; assumed`. Existing context-budget/output-reserve/margin calculation remains the behavior contract. Models.dev metadata can change future snapshots' limits, but does not change historical measurements/costs or choose a route.

Do not import Models.dev prices into cost calculation. Retain the currently locked LiteLLM utility/tokenizer/cost semantics and existing Provider-specific normalization, including unknown cost when an otherwise eligible model lacks local pricing. This extends ADR-0002's metadata role without changing Provider dispatch.

### User-visible command contract

| Surface | Behavior |
| --- | --- |
| `personal-agent --models <provider> [--search <text>]` | Credential-free bounded catalog listing; exits before Session/Tool initialization |
| `personal-agent --refresh-models` | Explicit bounded refresh; no Session or model call; nonzero on failure |
| Both CLI options together | Refresh, then list requested Provider; failure remains visible/nonzero |
| `PA_PROVIDER`, `PA_MODEL` + selected API key | Explicit startup pair; missing values show setup/list/refresh guidance |
| `/model` | Show pair and metadata/access distinction |
| `/model <provider> <model-id>` | Validate and atomically save/activate the complete pair |
| `/models [provider] [query...]` | Search selected/named Provider's eligible offerings |
| `/models refresh` | Refresh catalog without selecting a route |
| `/config` | Edit one pair, keys and retained context controls, using the same validation |
| `/mode plan|build|auto` | Existing live Agent Mode behavior; unrelated to model selection |

No new interactive framework, positional task CLI, free-form endpoint or route alias is needed. Provider lookup may trim/lowercase its fixed key; model IDs remain exact/case-sensitive. Invalid CLI option combinations and unsupported Provider choices print actionable usage without Session effects.

## Testing Decisions

Test public behavior through existing CLI/REPL, Router/Provider, Call Log/Resume, report and recovery seams. Catalog transport/file fakes exercise the real parser/cache/lookup, while representative checked-in small JSON fixtures exercise the actual Models.dev provider-map fields. Use a synthetic exact offering for offline router/prompt tests, admitted through the same catalog interface; never fetch a live catalog or real home/credential in ordinary tests. Do not clone the entire public catalog into fixtures or assert today's model count/names/prices.

Catalog matrix: all four mappings and exact IDs; case-sensitive model identity; duplicate/mismatched IDs; modality/Tools/missing metadata/deprecation/specialized type/overrides/interleaved rules; missing pricing; partial providers; valid unknown optional fields; malformed types/limits; cache hit makes zero requests; absent/corrupt/oversize cache; timeout/HTTP/media-type/redirect/oversize/truncated JSON; atomic write/replace failure; failed refresh byte preservation; offline old cache; selected model removed after refresh; safe terminal/bounded search output. Use request/replace fault injection at owned seams, not internet timing tests.

Cutover matrix: selected-key-only startup and dotenv precedence; missing new settings with old `TIER_*` present; pair selection/cancellation/save failure; new-format startup/Resume/last and old-format refusal before append; no evaluator even on first/5th/15th task; one immutable pair through Tools/transient retry/all Compression; changed pair on explicit Retry and replay compatibility; independent ordinals/executions across failures/Clear/Resume; streaming/error/cancel/overflow; exact prepared-input/output limits and provenance; unknown local price; all four normalized cache counters; local-only report route changes/coverage/redaction/bounds; all three production prompt/schema fixtures.

Retain and adapt the existing recovery fault-injection suite: exact create/edit/delete/mode/link restoration, conflict before/after confirmation, privacy/limits, interrupted journals, rollback/completion-write failure, original Retry ordinal, exact execution and contributor-lineage invalidation, unrelated pending continuation, and recovery before any Attempt. Reference 0053's behavioral tests rather than rewriting its algorithms in new tests.

Run focused meaningful tests for each increment, then the complete installed `.venv/bin/pytest` suite at the end of each ticket. Localhost/MCP tests need sandbox escalation from the outset. Existing `uv run --offline` cannot rebuild because hatchling is absent from cache; installed pytest is accepted. No install, paid/model call, model benchmark or network-dependent regression suite is required. Review deletion of obsolete tests against retained behavior rather than preserving obsolete tier API wrappers to make tests pass.

## Out of Scope

Old Session/tier-policy replay, configuration migration, compatibility wrappers, file deletion, inference entitlement probes, automatic route fallback, fifth/custom Providers/endpoints, SDK/API migrations, new dependencies, background refresh/polling, catalog pricing for accounting, model benchmarks, Gemini thought-cost correction, new UI framework, publishing/pushes and unrelated refactors.

### Interim state after ticket 02

The pair comes only from `PA_PROVIDER`/`PA_MODEL` settings and changes by editing settings and restarting. `/model` shows the pair and takes no arguments; there is no in-session `/models`, `/models refresh` or `/config` pair editing (`--models`/`--refresh-models` from ticket 01 remain). Startup and dispatch do no catalog admission and exchange limits keep the existing manual, local LiteLLM and labeled-assumption resolution. Everything else in this spec except R6, R7, the catalog-capacity part of R9 and R13 already holds: Call Log v3, Resume, reports, discovery and recovery. This is a working, fully tested state with no compatibility shims, not a delivered feature.

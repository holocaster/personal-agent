# 0037 — Context Window

Brief: `docs/briefs/0037-context-window.md`. Vocabulary: `docs/CONTEXT.md`. Research: `docs/research/done/2026-09-29-context-window-routing.md`. ADR-0001 governs Escalation, ADR-0002 (including its feature 0037 amendment) permits LiteLLM cost/metadata utilities and local token counting while preserving hand-rolled REST dispatch, and ADR-0005 governs Conversation replay. No new ADR or dependency is needed.

## Problem Statement

The fixed 20-turn Context Window silently omits older conversation without measuring the complete request. Conversely, a single large task, Skill or Tool result can overflow a route even inside that window. Auto-Compress runs too late, relies on reported usage and a conflated input/context limit, and launches an unsolicited Continuation Turn. Compression itself can overflow the easy route. Users cannot distinguish their chosen budget, actual route restrictions and assumed capacity.

## Solution

Keep all retained complete turns available to the Router. Before every Provider exchange, estimate the complete input locally and enforce a user-persistent total Context Budget, route restrictions, output reservation and estimation margin. Preventively summarize eligible older context through bounded easy-route exchanges, retaining the two latest complete turns and the entire in-progress turn. Commit a replacement only when the complete operation succeeds, then proceed with the pending exchange, not a new task. Stop visibly when preserved input cannot fit, or when Compression fails for input above the mandatory ceiling or during recovery; a failed optional soft-trigger Compression is reported and the fitting pending exchange proceeds unchanged. Recover once from a positively classified context-overflow rejection without repeating any executed Tool.

## User Stories

1. As a user, I want a default total budget of 250000 tokens, so that my history is not arbitrarily cut at 20 turns.
2. As a user, I want to edit and persist that budget through `/config`, so that later tasks and Runs use my choice.
3. As a user, I want a task to retain its starting Runtime Configuration, so that its Tool follow-ups and Compression cannot unexpectedly change routes or budgets.
4. As a user, I want smaller route capacities to constrain my budget, so that choosing a large budget does not claim my model supports it.
5. As a user, I want exact Provider/model capacity overrides, so that missing or mistaken metadata can be corrected without changing my global budget.
6. As a user, I want unknown capacity explicitly labeled and a conservative assumed 128000-token value, so that I can distinguish assumptions from verified restrictions.
7. As a user, I want input restrictions and output restrictions accounted for separately, so that input and output maxima are never added into an invented total and an input limit stands in for total capacity only as a conservative lower bound.
8. As a user, I want output capped at the reserved allowance, including reasoning where it shares that allowance, so that requests cannot consume unreserved output space.
9. As a user, I want System Prompt, Memory, Conversation Summary, Todo List, active Skills, Tool definitions, task and Tool exchanges measured together, so that hidden input does not escape budgeting.
10. As a user, I want local LiteLLM token estimates rather than byte proxies or additional paid token-counting requests, so that prevention uses the existing library without counting-call cost.
11. As a user, I want preventive Compression before the first exchange, retries, Tool follow-ups and Escalation, so that checks cover the route actually called.
12. As a user, I want the two most recent complete turns and current turn preserved intact, so that recent intent and Tool call/result correlation remain usable.
13. As a user, I want older context compressed toward 60% input occupancy after the 80% trigger, so that ordinary growth has headroom.
14. As a user, I want large older context summarized in fitting blocks, so that the easy route need not accept the entire original Conversation at once.
15. As a user, I want unsuccessful, empty, non-reducing or interrupted Compression to leave my prior Conversation unchanged, so that failures do not silently lose content.
16. As a user, I want a visible stop if protected content still cannot fit, so that instructions, task and Tool results are never silently cut to force a request through.
17. As a user, I want executed Tool outcomes retained in the Call Log even if a later exchange stops, so that a workspace effect is never confused with work not performed.
18. As a user, I want one safe retry of an exchange rejected for context overflow, so that imperfect estimates can recover without restarting the task or repeating Tools.
19. As a user, I want preventive Compression to continue only my pending exchange and `/compress` to remain a local summarization action, so that neither invents another routed turn.
20. As a user, I want Resume, Undo, Clear, Todo List and ordinary cost accounting to retain their established meanings, so that context management does not create another Conversation record.
21. As a user, I want `/usage` to distinguish configured/effective budgets, capacity provenance, input ceiling, output reserve, estimate and reported usage, so that cached tokens and missing counters do not mislead me.
22. As a user, I want a route's published input limit used as its known capacity when no total is published or overridden, so that my 250000 default actually applies to large-window models instead of an assumed 128000.
23. As a user, I want a Conversation holding only a previous summary and the two protected turns sent unchanged while it fits the mandatory ceiling, so that I do not pay to re-summarize that summary on every exchange above 80%.
24. As a user, I want a failed optional Compression to be reported while my fitting pending exchange is still sent, so that a best-effort optimization cannot block a task that would have fit.

## Requirements

- **R1 — Persistent configuration.** Default `PA_CONTEXT_BUDGET_TOKENS` to 250000; accept positive decimal integers only. Extend the existing home `.env` configuration store and `/config` menu with a `context` choice for the budget and capacity overrides. Preserve existing environment precedence (exported environment, current-directory `.env`, home `.env`, default), override-source notices, atomic save behavior and credential handling. A cancelled, invalid or failed save changes neither active nor persisted configuration. Accepted changes apply to the next task; copy the full task configuration, including override data, once at task start and use it for every exchange and easy-route Compression in that task. Resume uses current settings, not logged old settings.
- **R2 — Capacity provenance and overrides.** Resolve limits by exact `(Provider, model)` identity, not Complexity Tier alone. Represent positive integer total, separate input and output limits independently with their provenance. A manual field replaces that metadata field, including same-field published bounds; unspecified input/output fields retain valid metadata restrictions. When neither a total override nor a published total exists, a valid published `max_input_tokens` is the route's known total capacity: a conservative lower bound, since the real window is never smaller than its input limit. It applies to every Provider and carries that metadata's actual scope label (`published`, or `published model-wide` on OpenRouter); it also remains the separate input limit. Never interpret `max_tokens` as total merely because of its name, or add input/output maxima to invent a total. Reject booleans, non-integers and non-positive metadata values without claiming they are limits. Only when no total override, published total or valid published input limit exists, label the total `unknown` with an `assumed` 128000-token total. Keep any usable smaller published ceilings not superseded by a manual field as additional bounds. The user's configured budget is unchanged. Model-wide OpenRouter metadata is not verified capacity of its unpinned upstream: it is used as the labeled lower bound above, and R8 recovery covers a smaller unpinned upstream; a diagnostic lookup after a response cannot verify the next request. No new catalog service or upstream-pinning policy.
- **R3 — Budget arithmetic and explicit output caps.** For configured total `B`, resolved route total `C` (known, manual or assumed), any additional published total ceiling `P` not superseded by a total override, output limit `Lout` if known, and separate input limit `Lin` if known: `E = min(B, C, P when present)`, `O = min(16000, Lout when present)`, margin `M = 10000`, and mandatory input ceiling `I = min(E - O, Lin when present) - M`. Unknown output capability uses the explicit 16000 cap, not unlimited output. Do not shrink the margin or silently reduce output reserve to force protected input to fit. A non-positive ceiling produces a visible local stop. A 250000 total with no tighter input/output restrictions gives `O = 16000`, `I = 224000`; an assumed 128000 total gives `I = 102000`. With the default budget and no overrides, a published input limit of 200000 (output 64000) gives `E = 200000`, `I = 174000`; published input limits of 272000 or 1048576 give `E = 250000`, `I = 224000`. Pass the computed cap explicitly for every exchange on all four Providers, including Compression and retries; any smaller Compression-specific cap reduces its own reservation consistently. Enforce shared visible/reasoning output allowance using the Provider's supported field, not a text instruction. Where a route has separate reasoning allowances that count toward total occupancy, account for them within the reserved output or stop visibly if a bounded request cannot be constructed; do not silently send an unbounded request.
- **R4 — Complete local input measurement.** Use the already-installed LiteLLM `token_counter()` to estimate the complete prepared input that the Provider will send, including System Prompt with Memory/Summary/Todos/Skills, all retained history, current task, assistant Tool calls, results, full Tool definitions and active Provider replay parts. There is no 20-turn suffix cut or cache-token deduction. Estimates are local, deterministic for the same prepared input/tokenizer settings and explicitly approximate, not Provider-reported counts or guaranteed upper bounds. Identify the actual encoding and generic fallback when applicable; a known capacity does not imply a model-specific tokenizer. Construction/counting failure, disabled counting or an invalid/non-positive count for non-empty input stops visibly, never zero/unknown-as-zero or unchecked dispatch. Use local bundled/cached tokenizer assets only, without implicit asset downloads, paid count requests, byte/character proxy fallback, new dependencies or LiteLLM completion/routing calls.
- **R5 — Preventive scheduling.** Check each actual route immediately before dispatch, including initial exchange, each transient retry, Tool follow-up and changed route on Escalation. Trigger at `estimated_input >= floor(0.8 * E)` (the soft trigger) only when completed turns older than the latest two are eligible, or whenever estimated input exceeds `I`, independently of Provider-reported usage. Output reserve and estimation margin constrain `I` separately; do not add them to estimated input for the 80% trigger. Aim for estimated input at or below `T = min(floor(0.6 * E), I)`. With `E = 250000` and no tighter input restriction, the trigger is 200000 estimated input tokens, the target is 150000 and the mandatory ceiling remains 224000; 174000 does not meet the soft trigger. This is an input target, not 60% of an old turn count. Compression replaces all eligible completed turns older than the latest two and incorporates the previous summary. A previous summary is itself older context and is incorporated whenever Compression runs, but a previous summary with no further eligible complete turns is reduced only when estimated input exceeds `I` or during R8 recovery, never by the soft trigger alone. Never summarize the two protected complete turns or the in-progress turn. The 60% target is best-effort when preserved input dominates; the mandatory input ceiling is not. If nothing is eligible and input fits `I`, proceed without a synthetic call; if it does not fit, stop. Do not repeatedly run preventive Compression for the same unchanged exchange just because the protected suffix keeps it above the soft threshold. If Compression started by the soft trigger alone (estimated input at or above the 80% trigger but within `I`, outside recovery) fails before commit, print a visible failure notice with its reason, commit nothing and send the unchanged, already measured pending exchange; a transient retry of that same unchanged request does not rerun it. Failure before commit means summarization, summary validation (R6), candidate measurement or the reduction/fit checks. Interruption, detailed-audit and Call Log persistence failures, including a failed final-summary append, keep their existing stop/fatal semantics. When estimated input exceeds `I` or during R8 recovery, Compression failure still stops the exchange.
- **R6 — Bounded, transactional Compression.** Use the task snapshot's easy route, no Tools, no Escalation and no Turn End for summarization. Include every part of eligible older turns and previous summary in ordered, labeled, fitting blocks; recursively combine partial summaries under the same easy-route input/output/margin constraints. A single oversized old turn or summary may be split as rendered summarization data, without cutting it out of the source record. Budget the summarization instruction and System Prompt/Memory too. Validate each returned summary and measure the final candidate in the pending route before commit. Empty, length-truncated, context-truncated (including Anthropic `stop_reason=model_context_window_exceeded`), malformed, non-reducing, unfittable or interrupted construction is failure; no intermediate summary replaces live state. This validation applies to every block and combination response for manual, preventive and overflow-recovery Compression, even when the returned text is non-empty and reducing. Combination rounds must make strict measured progress toward a fitting root; do not loop on equally large summaries. Target misses caused by preserved content may succeed if the complete candidate fits the mandatory ceiling. On failure, retain the prior turns, summary and Todo baseline, report the failure, and stop the pending exchange rather than sending unchecked input, except R5's soft-trigger-only failure, which sends the unchanged exchange already measured within `I`. All summarization Attempts, including failed/transient-retry Attempts, remain normally logged and charged.
- **R7 — Hard stops and executed Tools.** After safe older-context reduction, if complete preserved input cannot fit, stop visibly without sending that exchange, truncating instructions/task/results, dropping Tool call/result pairs, switching to a larger tier as a workaround, or automatically restarting a routed task. Budget diagnostics identify the route, estimate, ceiling and preserved-content obstruction without dumping private content. Tool execution Call Log entries already written, their validated arguments, call ids and outcomes remain intact; failed/interrupted turns remain failed/interrupted, not successful Conversation turns. Retain in-progress call/result data for the pending exchange while attempting reduction/recovery. No new partial-turn Resume: existing error Turn Ends do not become replayable successful turns, and an explicit user `/retry` retains its existing task-rerun meaning (not automatic recovery).
- **R8 — Provider overflow recovery.** Classify only positive Provider-specific context-window/input-token overflow evidence as context overflow. At most one recovery retry per rejected logical exchange, on the same Provider/model, after strictly smaller safe older context and a fresh complete budget check. A second rejection, unsuccessful Compression, no safe reduction, or an unrelated failure of that retry is surfaced, not fed into another recovery or Escalation loop. This retry limit is separate from ordinary transient-error retry accounting. Tools already executed before the rejected follow-up are not re-executed, re-confirmed or logged a second time. Generic HTTP 400, authentication failures, unsupported output parameters, Tool support errors, timeouts, rate limits and answer-quality judgments are not context overflow; ordinary technical-retry/Escalation behavior otherwise remains ADR-0001's existing behavior. Compression exchanges also surface their own overflow rather than recursively invoking Compression/recovery.
- **R9 — Conversation/Call Log commit and replay.** A complete successful Compression writes exactly one existing `conversation_compressed` entry with its final summary, then applies the matching in-memory two-complete-turn reduction and Todo baseline. Do so before the pending routed Turn End; the in-progress turn is not yet among the complete turns being reduced. Failed construction writes no such entry. A failed commit must not first mutate live Conversation or publish a success notice; preserve the valid prior log prefix on an observable append failure, and stop fatally if recording cannot be made safe. A later pending-turn error/interruption does not undo an already committed Compression. Resume still replays the original two-turn rule with `log_version: 2`, successful Turn Ends only, no alternate conversation file or heuristic Attempt replay. Successful pending Turn End appends the current turn afterward (so there can then be three retained turns). Undo/Clear/Todo semantics and Tool evidence are unchanged. Existing detailed audit redaction and fail-closed behavior apply to every summarization, retry and actual replay input.
- **R10 — Notices and no Continuation Turn.** Print a concise automatic-Compression notice and success/failure outcome through existing terminal presentation in interactive and piped modes. A soft-trigger-only failure notice states that the prior Conversation was retained and the pending exchange is being sent; other failure notices state that it stopped. Preventive Compression proceeds only with the task/exchange already pending. Remove the old post-success usage trigger and synthetic Continuation Turn path. Manual `/compress` uses the same bounded construction and commit, reports nothing eligible when appropriate, and never calls `route()` afterward. No new monitoring UI or Status Footer expansion.
- **R11 — Usage and cost observability.** `/usage` shows configured total budget and, for the latest ordinary-task exchange assessed this Run, Provider/model, effective total budget, capacity source/status with known (including a published input limit used as total) or manual values, or `unknown; assumed 128000`, separate input/output limits when known, mandatory input ceiling, output reserve, last-request estimated input with estimator label, and Provider-reported input usage when available (otherwise `unknown`). Show assessed/rejected/locally blocked state rather than reusing stale last-success counters. Internal Compression must not overwrite the ordinary-task diagnostic; distinguish a new configured budget from the latest exchange's task snapshot after `/config`. Before any ordinary exchange, show configured settings and that no exchange has been assessed, not invented request usage. Preserve existing spend/completion/cost-estimated reporting and retained/sent turn counts with their actual meanings. Normalize Provider input usage to all context-occupying input, including cache read/write where the Provider reports those separately; never subtract cached tokens or add them twice. Additional Compression and recovery Attempts count toward normal spend and the Budget Guardrail.

## Implementation Decisions

### Configuration and metadata

- Extend Runtime Configuration rather than introducing another configuration service. Add `context_budget_tokens` and copied `capacity_overrides` with defaults so existing programmatic construction remains valid. Extend all `/config` candidate construction paths, managed-variable source tracking and test environment isolation; editing a model or credential must not reset context settings.
- Use `PA_CONTEXT_CAPACITY_OVERRIDES` as one JSON array of records: `{"provider":"openai","model":"exact-model-id","total_tokens":250000,"input_tokens":230000,"output_tokens":16000}`. Provider/model/total are required; input/output are optional. Reject unsupported Providers, empty model ids, duplicate identities, unknown keys, booleans, non-positive/non-integer limits and optional limits greater than that record's total. An empty array clears overrides; removing one identity preserves the others. `/config` edits/removes the record for a selected configured Provider/model, not a stale per-tier number. Route changes leave prior identity records inactive but available if that route is selected again. Save valid single-line JSON using the existing atomic home `.env` store.
- Keep `get_model_info()` as the only capacity metadata dependency. Replace the old scalar `cost.context_limit` meaning with an explicit limit/provenance record in the context-budgeting capability. Normalize only fields whose total/input/output semantics are documented for that source and Provider; `max_input_tokens` and `max_output_tokens` can provide those separate ceilings, and a valid published `max_input_tokens` is also the known total when no total is published or overridden (R2). An ambiguous `max_tokens` contributes no total capacity. Direct-Provider published model limits and OpenRouter model-wide bounds must be labeled at their actual scope; a route with neither total nor valid input metadata falls back as R2 specifies. The correction lives in the context-budgeting capability's limit resolution only; no new metadata field, label vocabulary or dependency. Do not add paid discovery calls, remote catalogs, or infer verified limits from a successful small request.

### Exchange measurement and Provider Contract

- Concentrate policy in one small routing context-budgeting capability shared by normal exchanges and Compression. Pass complete-turn structure to routed execution; flattened messages alone cannot identify the preserved two-turn suffix. The REPL continues to own completed Conversation state, summary, Todo baseline and durable commit. Use a single Compression commit callback/shared state operation so a reduction during a Tool loop is visible to the REPL and later Escalation; do not maintain independent divergent histories.
- Reuse each Provider's wire translation in a pure request-input preparation function, also used by dispatch. This small Provider seam is needed because actual replay input differs on Gemini; measuring normalized messages plus all replay would double-count, while measuring normalized messages alone misses opaque parts. Do not introduce a generic calling framework or a second serialization implementation just for estimation.
- Count a deterministic JSON rendering of the complete prepared model-facing input with `litellm.token_counter(model=tokenizer_model, text=rendered_input)`. JSON is the text being tokenized, not a byte/character proxy. Preserve message order and content; use stable object-key ordering, Unicode text and strict JSON validation. Include the System Prompt, every Tool schema field, call ids/names/arguments/results and original replay parts exactly once. Exclude credentials, HTTP headers and transport/routing/output-control settings. This rendered-input estimate includes JSON framing but cannot reproduce proprietary prompt templates or an opaque signature's internal occupancy; the separate 10000 margin remains unchanged, with R8 recovery for actual overflow. Do not claim exactness or a conservative bound.
- Use LiteLLM's locally available encoding selection, preferring a recognized model's encoding when the installed library supports it. Keep route/capacity identity separate from tokenizer identity: direct OpenAI uses its canonical model id; strip a namespace only for an explicitly verified tokenizer alias (for example an OpenRouter OpenAI model), never to infer upstream capacity. Other/unknown models may use the library's generic encoding, labeled `LiteLLM local JSON-input estimate; generic cl100k_base` rather than a claim to use that Provider's exact tokenizer. Recognized model estimates still carry `approximate` and the encoding name. No user-selectable tokenizer, library Router or new dependency. Use this same estimator for block fitting, candidate reduction and all ordinary/recovery exchanges.
- Keep counting offline: LiteLLM 1.102.0 bundles `cl100k_base` and `o200k_base` assets. Disable HuggingFace downloads before counting and use valid local assets; ensure first LiteLLM import for this capability uses its bundled cost map rather than inducing a metadata refresh. The HF-disable flag alone does not prevent tiktoken from fetching a missing/corrupt cache asset. Handle custom cache paths, missing/corrupt assets and initialization failures with a locally usable library generic fallback, labeled approximate, or a visible local stop if none is usable. Do not download a tokenizer or send conversation data to an asset/counting endpoint. Do not accept `disable_token_counter` returning zero or supply a fabricated `default_token_count` after failure. Library chunked encoding and long-text sampling remain approximate library behavior, not authorization for our own characters/4 fallback.
- The `text` path deliberately avoids feeding arbitrary Provider wire dictionaries to LiteLLM's structured `messages`/`tools` counter: that interface estimates chat framing, but skips unsupported fields, counts only argument strings within Chat Completions Tool calls and formats only selected schema fields. It does not understand Gemini `contents`/`thoughtSignature`. Passing the already prepared input as text covers these parts without double-counting normalized history; never pass `tools` or `messages` alongside `text` (the library rejects that combination). Validate serializability before counting; failure retains Conversation/Tool evidence and stops. Keep this one small estimator, not another serializer for dispatch or a plugin framework.
- Add an explicit positive `max_output_tokens` allowance to `Provider.call`, carried from routing policy; all internal paths supply it. OpenAI Chat Completions uses `max_completion_tokens` (visible plus reasoning), OpenRouter uses its supported output-cap field with parameter enforcement even without Tools, Anthropic Messages uses `max_tokens` instead of the fixed 1024, and Gemini uses `generationConfig.maxOutputTokens`. Verify model-specific shared/separate thinking behavior against the current REST contract before finalizing payloads; do not infer a reasoning cap from an effort label. Preserve response termination information so Compression can reject a length-truncated summary. No new reasoning controls for users and no general Provider feature expansion.
- Decode HTTP error evidence once at the Provider seam, preserving readable diagnostics. Context-overflow detection must precede the existing broad `"tool"`-substring unsupported-Tools detector: an overflow description mentioning Tool tokens is not proof that Tools are unsupported. Positive vendor error code/type or a narrowly tested input/context-limit message suffices; status alone does not. Do not consume the HTTP body in one classifier and leave the next with empty evidence.

### Compression, replay and persistence

- Reuse the Provider Contract's `AssistantMessage.termination`/`truncated` status and the shared Router `compress()` validation to reject Anthropic `model_context_window_exceeded` summaries. The Anthropic Provider already preserves `stop_reason`; extend the existing truncation classification, not the HTTP rejection taxonomy or a caller-specific guard. Report unfinished construction through the existing Compression failure path before any commit. Keep length-truncation and complete-response behavior, ordinary routed-answer policy and Attempt usage/cost semantics unchanged. No new interface, retry policy, dependency or persistence schema is needed.
- Render only eligible older Conversation data for summarization, keeping call names/ids, arguments and results associated and every piece covered in chronological order. When an old turn exceeds easy-route capacity, use labeled contiguous pieces of its rendered text. These are summarization data, not cut/replayed live Tool messages. Keep the previous summary in this same bounded input pipeline, not an unlimited prefix repeated in every block. Active Skills/Todos remain pending-request instructions/state, not newly baked into the summary; existing Memory accompanies easy-route calls and is measured.
- Pack fitting blocks, summarize, then combine fitting groups until one reduced candidate remains. Re-measure all prompts and responses; do not concatenate summaries into an unchecked final exchange or shorten a returned summary by slicing. Require strict reduction at combination levels; preserve original state and stop on no progress. Cap outputs to the root's available summary space when appropriate and reject truncation rather than claiming complete success. Manual `/compress` has no pending ordinary exchange: its final summary must satisfy the bounded easy-route construction and reduction checks, while the next task's full input is checked against that task's actual route when it starts. No recursive preventive-Compression hook inside summarization calls.
- Gemini's current replay holds a full old `contents` prefix and a normalized-message `consumed` index. Rebase that prefix after successful Compression: drop only wire content belonging to removed completed turns, retain exact in-progress model parts (including `thoughtSignature`) and Tool response correlation, rebuild retained normalized historical content with the existing translator, and update `consumed` to the new normalized positions. Track the active-turn start explicitly rather than subtracting turns from Gemini contents (message grouping differs). Never clear all replay, reuse the stale index, replay the removed prefix, or fabricate missing signatures. Other Providers keep their established translation behavior.
- Build candidate summary, turns and Todo baseline without mutation. Append the existing final-summary event before swapping live state, with no subsequent fallible operation between successful main-record commit and in-memory application. For observable partial append failure, use the existing Call Log lock and recorded append offset to restore the prior valid prefix; if restoration fails, stop with a fatal persistence error, never continue with questionable records. This is an observed-error transaction, not a new crash-proof storage promise; ADR-0005's malformed-log refusal remains. Detailed-audit failure before commit leaves the old Conversation; any failure after a durable commit stops further work and must not pretend that commit did not occur.
- The Router's existing preventive gate implements R5's eligibility and soft-failure rules with the smallest change: the soft trigger requires eligible older complete turns; the ceiling and recovery triggers keep accepting a previous summary alone. A soft-trigger-only failure before commit reuses the original measured system/input/estimate and replay, records the unchanged request as already attempted (the existing same-exchange no-repeat state) and dispatches it; the assessment keeps the original estimate. No new configuration, interface, persistence schema or Call Log event.
- Keep ordinary Tool execution records as the evidence for executed effects on a failed turn. Do not make error Turn Ends successful/replayable or create a partial-turn recovery store. Log each rejected/recovery Attempt normally, retain sequential per-tier Attempt numbers, and use a separate exchange-local one-recovery flag rather than restarting `route()`.

## Testing Decisions

- Primary seam: scripted `run_repl` with the existing fake shared HTTP transport, temporary home/config/Call Log and harmless Tools. Assert actual serialized requests, visible output and replayed state, not private helper call counts. Use existing `tests/test_repl.py`, `tests/test_runtime_config.py`, `tests/test_routing.py`, `tests/test_call_log.py`, `tests/test_provider.py` and `tests/test_detailed_audit.py` as prior art. No paid Providers, real credentials, destructive Tools or new test framework.
- Test budget/limit arithmetic with supplied metadata and estimator fixtures: 250000/224000; 128000/102000 assumed; smaller route total/output/input; input-only metadata as a known total; ambiguous output-like `max_tokens`; invalid/missing metadata; manual set/reset and exact-identity changes; nominal OpenRouter versus unknown upstream. For effective total 250000, assert no soft trigger at estimated input 174000 or 199999, trigger at 200000/200001, target 150000 and mandatory ceiling 224000. Also assert a tighter separate input ceiling enforces reduction or a visible stop below the 80% threshold, and target is capped by that ceiling. Use integer boundary cases at/below/above the soft trigger and mandatory ceiling, including totals not divisible by five. Boundary tests inject token estimates, never derive them from byte counts or depend on exact BPE sizes.
- Separately exercise the real locked LiteLLM utility with network access forbidden and local model-map/tokenizer assets: recognized OpenAI encoding, generic non-OpenAI/unknown-model fallback with honest labels, repeatable Unicode/code counts distinct from UTF-8 byte length, and complete System Prompt/Tool schema/call/result/replay coverage. Use substantial constituent additions to verify counts respond, including fields the structured counter would ignore; capture the exact rendered input and compare it with dispatch's prepared input to prove once-only coverage. Cached usage must not reduce occupancy. Inject disabled/zero/invalid counts, malformed input, custom cache miss/corruption, tokenizer initialization and counting exceptions. Assert locally usable library fallback or a visible stop with unchanged state/evidence and no unchecked Provider call, counting request, tokenizer download or proxy estimate. Summarization and recovery use this same estimator; fake estimator boundary tests do not replace this real-library contract test.
- Capture all four Provider payloads with explicit caps, including no-Tools, Tool follow-up and easy-route calls; test termination/truncation classification and reasoning-cap contracts with documented fixtures. Verify prepared input and sent input agree, especially Gemini grouping, generated ids and rebased replay with more than one Tool round. Test unrelated errors and overflow descriptions mentioning Tool tokens separately.
- Manual and automatic integration tests use long history exceeding 20 turns, different easy/target capacities, oversized old turns/prior summary, multiple blocks and combination levels, best-effort target with preserved suffix above 60%, and hard overflow from task/Memory/Skills/Tool definitions/results. Inspect each summarization request for fitting input plus output/margin and complete source coverage. Assert one final commit, no intermediate replacement, no synthetic task and normal spend for every Attempt.
- Inject failures in middle blocks, combining, empty/non-reducing/length-truncated responses, local estimation, interruption and final-summary append (including partial append). Compare `/history`, Todo baseline and `load_conversation` to pre-operation state on failed construction/commit. Test Compression before pending successful/error/interrupted Turn End, Resume and subsequent Undo/Clear. Detailed-audit failures remain fatal, with no later Provider/Tool/action.
- For the review-discovered R6 correction, send actual Anthropic-shaped HTTP responses with non-empty, reducing text and `stop_reason=model_context_window_exceeded` through the Provider to scripted `run_repl`, not a mocked `truncated` property. Cover manual first-block, later-block and combination failure, with an existing summary and non-empty Todo baseline, proving live `/history`/Todo state and `load_conversation`/Resume remain unchanged and no new `conversation_compressed` or success notice appears. Exercise the shared validation from preventive and overflow-recovery Tool-follow-up paths: stop visibly before the pending dispatch/recovery retry, retain prior completed state and once-only Tool execution evidence, and do not recurse or Escalate.

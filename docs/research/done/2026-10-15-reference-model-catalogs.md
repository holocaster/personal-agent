## OpenCode

**Providers e modelos não formam uma allowlist fixa.** O plugin de catálogo registra providers e métodos de credencial a partir dos dados. Configuração pode criar Provider e Model, herdar aliases e sobrescrever pacote, endpoint, capabilities e compatibility; overrides tardios podem recriar/reabilitar modelos. Fontes: [ModelsDevPlugin](https://github.com/anomalyco/opencode/blob/a448d5b987d01887e1597269b57ae2f259f5725b/packages/core/src/plugin/models-dev.ts#L29-L66) e [Provider config transforms](https://github.com/anomalyco/opencode/blob/a448d5b987d01887e1597269b57ae2f259f5725b/packages/core/src/config/plugin/provider.ts#L54-L163).

**Origem e atualização.** `ModelsDev.layer` prioriza arquivo opcional, cache, snapshot embutido e, se necessário, rede. O endpoint padrão deste commit é `https://models.opencode.ai/api.json`, não uma suposição sobre a API atual de models.dev. Refresh periódico: cinco minutos; falha de refresh é registrada/ignorada, conservando o catálogo já carregado. Fonte: [defaultSource, populate e refresh](https://github.com/anomalyco/opencode/blob/a448d5b987d01887e1597269b57ae2f259f5725b/packages/core/src/models-dev.ts#L279-L434).

**Filtro comprovado.** `snapshots` exclui aliases de Provider específicos, modelos deprecated e modelos sem texto na entrada/saída, além de exceções Bedrock. `Model.supportsText` aceita metadado de modalidades vazio. `tool_call` vira `capabilities.tools`, porém `snapshots` não o exige. Não há nesse caminho um filtro geral de suporte a system, streaming ou cada endpoint. Fontes: [snapshots](https://github.com/anomalyco/opencode/blob/a448d5b987d01887e1597269b57ae2f259f5725b/packages/core/src/plugin/models-dev.ts#L90-L115), [supportsText](https://github.com/anomalyco/opencode/blob/a448d5b987d01887e1597269b57ae2f259f5725b/packages/core/src/model.ts#L289-L295) e [model metadata normalization](https://github.com/anomalyco/opencode/blob/a448d5b987d01887e1597269b57ae2f259f5725b/packages/core/src/models-dev.ts#L205-L247).

**Credencial não significa acesso a todos os modelos.** `Provider.snapshot` usa presença de conexão para disponibilidade, ou ativação explícita pela configuração. O próprio caminho posterga resolução OAuth para execução. A interface lista modelos dos Providers conectados e aplica preferências de visibilidade, recência e família; isso não consulta permissões individuais da conta para cada Model. Fontes: [snapshot](https://github.com/anomalyco/opencode/blob/a448d5b987d01887e1597269b57ae2f259f5725b/packages/core/src/provider.ts#L444-L477) e [createModelsController](https://github.com/anomalyco/opencode/blob/a448d5b987d01887e1597269b57ae2f259f5725b/packages/app/src/providers/models/models.tsx#L21-L129).

**Entrada inválida e fallback.** Uma sessão com seleção explícita ausente do catálogo disponível recebe `ModelUnavailableError`; sem seleção, tenta default e falha com `ModelNotSelectedError` se nada resolve. ID custom precisa ser definido pela configuração/plugin. O default pode escolher primeiro modelo textual disponível; isso é resolução inicial, não evidência de troca automática após erro de inferência. O transporte possui fallback WebSocket→HTTP, que preserva o modelo. Fontes: [SessionRunnerModel.resolve](https://github.com/anomalyco/opencode/blob/a448d5b987d01887e1597269b57ae2f259f5725b/packages/core/src/session/runner/model.ts#L75-L91), [ModelResolver.resolve](https://github.com/anomalyco/opencode/blob/a448d5b987d01887e1597269b57ae2f259f5725b/packages/core/src/model-resolver.ts#L412-L429) e [streamFailure](https://github.com/anomalyco/opencode/blob/a448d5b987d01887e1597269b57ae2f259f5725b/packages/core/src/session/model-transport.ts#L186-L197).

## Hermes Agent

**Universo extensível.** `provider_catalog` unifica a lista canônica, registry de auth e profiles de plugins para CLI/desktop. `resolve_provider_full` também resolve `providers.<nome>`, `custom_providers` e models.dev. Provider explicitamente desconhecido gera mensagem de erro no switch; não há necessidade de inserir todo endpoint privado na lista canônica. Fontes: [provider_catalog](https://github.com/NousResearch/hermes-agent/blob/60f56a6b13c8eb9a9e088c6fc1165257c92f7e11/hermes_cli/provider_catalog.py#L72-L124), [resolve_provider_full](https://github.com/NousResearch/hermes-agent/blob/60f56a6b13c8eb9a9e088c6fc1165257c92f7e11/hermes_cli/providers.py#L534-L583) e [explicit Provider resolution](https://github.com/NousResearch/hermes-agent/blob/60f56a6b13c8eb9a9e088c6fc1165257c92f7e11/hermes_cli/model_switch.py#L1216-L1222).

**Catálogo híbrido.** `provider_model_ids` tenta fetcher específico, profile e fallback estático; providers selecionados mesclam models.dev. Há manifest curado remoto próprio, cache e cópia local. OpenRouter combina a seleção curada com catálogo público live. OpenAI e Anthropic têm fetchers autenticados próprios; Anthropic pode mesclar aliases curados mesmo ausentes do listing. Portanto nem toda sugestão veio da conta nem toda ausência prova indisponibilidade. Fontes: [provider_model_ids](https://github.com/NousResearch/hermes-agent/blob/60f56a6b13c8eb9a9e088c6fc1165257c92f7e11/hermes_cli/models.py#L1826-L1857), [manifest defaults](https://github.com/NousResearch/hermes-agent/blob/60f56a6b13c8eb9a9e088c6fc1165257c92f7e11/hermes_cli/model_catalog.py#L26-L38), [Anthropic/OpenAI catalog fetchers](https://github.com/NousResearch/hermes-agent/blob/60f56a6b13c8eb9a9e088c6fc1165257c92f7e11/hermes_cli/models.py#L1521-L1570).

**Tools tem filtro real, mas não uniforme.** `list_agentic_models` exige `tool_call=true` e remove nomes classificados como ruído. O merge mantém extras curados. No OpenRouter, `supported_parameters` sem `tools` exclui a sugestão quando é uma lista; campo ausente/malformado passa. Se a filtragem não produz nada, retorna cache/fallback. `chat_catalog` remove geração de imagem/vídeo por metadados ou nome e aceita metadado desconhecido. Não existe aqui uma prova geral de Tools/Text/System/Streaming para cada ID sugerido. Fontes: [list_agentic_models](https://github.com/NousResearch/hermes-agent/blob/60f56a6b13c8eb9a9e088c6fc1165257c92f7e11/agent/models_dev.py#L911-L918), [_merge_with_models_dev](https://github.com/NousResearch/hermes-agent/blob/60f56a6b13c8eb9a9e088c6fc1165257c92f7e11/hermes_cli/models.py#L1371-L1381), [OpenRouter filtering](https://github.com/NousResearch/hermes-agent/blob/60f56a6b13c8eb9a9e088c6fc1165257c92f7e11/hermes_cli/models.py#L593-L722) e [chat catalog admission](https://github.com/NousResearch/hermes-agent/blob/60f56a6b13c8eb9a9e088c6fc1165257c92f7e11/hermes_cli/chat_catalog.py#L68-L143).

**Seleção manual e validação.** `_validate_switch` recusa geração conhecida; depois consulta `validate_requested_model`. Listing live genérico rejeita ID ausente, com exceções curadas; o código trata o host oficial OpenAI como listing autoritativo. Custom admite modelo não listado com aviso; em modos chat/Anthropic aceita também quando `/models` não responde. Fallback de catálogo indisponível pode aceitar e persistir ID desconhecido. Modelo declarado em configuração pode superar uma rejeição do validador. Similaridade gera sugestões, sem corrigir silenciosamente o ID. São regras de admissão, não um teste de inferência bem-sucedida. Fontes: [_validate_custom](https://github.com/NousResearch/hermes-agent/blob/60f56a6b13c8eb9a9e088c6fc1165257c92f7e11/hermes_cli/models_validate.py#L358-L392), [live listing e outage fallback](https://github.com/NousResearch/hermes-agent/blob/60f56a6b13c8eb9a9e088c6fc1165257c92f7e11/hermes_cli/models_validate.py#L619-L742) e [_validate_switch](https://github.com/NousResearch/hermes-agent/blob/60f56a6b13c8eb9a9e088c6fc1165257c92f7e11/hermes_cli/model_switch.py#L1598-L1650).

**Conta, UI e overrides.** O catálogo disponível sinaliza autenticação via status de Provider; auto-detecção evita migrar para um Provider sem credenciais, exceto quando nomeado explicitamente, para então falhar claramente. Cache de modelos inclui identidade de credencial/endpoint. Há aliases só para busca, sem alterar ID no wire, e overrides de capabilities por Provider/Model. Isso permite corrigir metadado, mas torna inadequado chamar a lista de garantia universal. Fontes: [provider credential status](https://github.com/NousResearch/hermes-agent/blob/60f56a6b13c8eb9a9e088c6fc1165257c92f7e11/hermes_cli/models.py#L819-L846), [detect_provider_for_model](https://github.com/NousResearch/hermes-agent/blob/60f56a6b13c8eb9a9e088c6fc1165257c92f7e11/hermes_cli/models.py#L1116-L1155), [credential fingerprint](https://github.com/NousResearch/hermes-agent/blob/60f56a6b13c8eb9a9e088c6fc1165257c92f7e11/hermes_cli/models.py#L1953-L1962), [model_search_text](https://github.com/NousResearch/hermes-agent/blob/60f56a6b13c8eb9a9e088c6fc1165257c92f7e11/hermes_cli/model_search.py#L25-L37) e [get_model_capabilities](https://github.com/NousResearch/hermes-agent/blob/60f56a6b13c8eb9a9e088c6fc1165257c92f7e11/agent/models_dev.py#L847-L869).

**Fallback significa outra rota quando configurado.** Há cadeia explícita `fallback_providers`/`fallback_model`, com Provider, Model e base URL; não confundir com fallback do catálogo/cache ou retry da mesma chamada. Esta pesquisa não auditou todos os gatilhos de recuperação. Fonte: [get_fallback_chain e scoped_fallback_chain](https://github.com/NousResearch/hermes-agent/blob/60f56a6b13c8eb9a9e088c6fc1165257c92f7e11/hermes_cli/fallback_config.py#L117-L163).

## DeepSeek Harness

**Plugins e rotas configuradas.** O caminho multi-provider `llm-pi-ai` usa catálogo instalado de `@earendil-works/pi-ai` (`^1.1.0` neste pacote), não uma consulta runtime a models.dev demonstrada pelo Harness. Cria coleção vazia e registra rotas configuradas. Catálogo conhecido filtra providers que só têm modelos não-chat; novas rotas podem declarar IDs próprios. Configuráveis e rotas utilizáveis são conceitos separados. Fontes: [pi-ai dependency](https://github.com/deepseek-ai/deepseek-harness/blob/86a402200d95fecef4529d969836f1fe13c6cb0d/packages/llm/llm-pi-ai/package.json#L47-L55), [createModels](https://github.com/deepseek-ai/deepseek-harness/blob/86a402200d95fecef4529d969836f1fe13c6cb0d/packages/llm/llm-pi-ai/src/models.ts#L25-L30), [catalogProviders/catalogModels](https://github.com/deepseek-ai/deepseek-harness/blob/86a402200d95fecef4529d969836f1fe13c6cb0d/packages/llm/llm-pi-ai/src/catalog.ts#L168-L220) e [configurable provider directory](https://github.com/deepseek-ai/deepseek-harness/blob/86a402200d95fecef4529d969836f1fe13c6cb0d/packages/llm/llm-pi-ai/src/index.ts#L118-L150).

**Descoberta tem limites explícitos.** `discoverModels` retorna catálogo instalado primeiro quando conhece o Provider; para demais rotas, lista endpoint por protocolos suportados: OpenAI Chat/Responses ou Anthropic Messages. Sem endpoint/protocolo apropriado, devolve erro e orienta entrada manual. Parser remoto extrai IDs, nomes e limites; não demonstra validação geral de Tools/System/Streaming. Anthropic lê uma página, sem seguir `has_more`. Fonte: [listing constraints](https://github.com/deepseek-ai/deepseek-harness/blob/86a402200d95fecef4529d969836f1fe13c6cb0d/packages/llm/llm-pi-ai/src/discovery.ts#L31-L49) e [readListing/discoverModels](https://github.com/deepseek-ai/deepseek-harness/blob/86a402200d95fecef4529d969836f1fe13c6cb0d/packages/llm/llm-pi-ai/src/discovery.ts#L181-L305).

**Compatibilidade de configuração é verificável, serviço remoto não.** `resolveRouteModels` exige IDs únicos/não vazios, protocolo/endpoint resolvíveis e limites positivos; valida chaves compat segundo protocolo. Escritas strict rejeitam; leituras deferred preservam diagnóstico e retiram modelos inválidos. `models` substitui o catálogo servido; `modelOverrides` modifica entradas existentes. Rotas manuais suportam explicitamente três protocolos; Provider instalado pode reutilizar implementação nativa de outros protocolos. Não há nesse resolver teste universal de Tools nem preflight de inferência. Fontes: [resolveRouteModels](https://github.com/deepseek-ai/deepseek-harness/blob/86a402200d95fecef4529d969836f1fe13c6cb0d/packages/llm/llm-pi-ai/src/catalog.ts#L857-L985) e [PROTOCOLS](https://github.com/deepseek-ai/deepseek-harness/blob/86a402200d95fecef4529d969836f1fe13c6cb0d/packages/llm/llm-pi-ai/src/provider.ts#L44-L49).

**Credenciais e seleção exata.** `apiKeyEnv` nomeado mas não resolvido causa `MISSING_CREDENTIAL`, sem aproveitar outra chave ambiente; `listModels` então retorna vazio. Sem referência explícita, auth nativa pode resolver depois. ID não configurado causa `UNKNOWN_MODEL`; Provider que o adapter não possui causa `NO_ADAPTER`. GUI agrupa modelos anunciados, isola falhas por Provider e verifica seleção por associação exata. A busca ordena/filtra por nome. Nada disso verifica toda autorização remota da conta. Fontes: [resolveApiKey](https://github.com/deepseek-ai/deepseek-harness/blob/86a402200d95fecef4529d969836f1fe13c6cb0d/packages/llm/llm-pi-ai/src/index.ts#L189-L210), [profileOf/modelOf/listModels](https://github.com/deepseek-ai/deepseek-harness/blob/86a402200d95fecef4529d969836f1fe13c6cb0d/packages/llm/llm-pi-ai/src/adapter.ts#L263-L312), [buildModelCatalog/modelAvailable](https://github.com/deepseek-ai/deepseek-harness/blob/86a402200d95fecef4529d969836f1fe13c6cb0d/packages/api/session-controller/src/catalog.ts#L20-L90) e [search filtering](https://github.com/deepseek-ai/deepseek-harness/blob/86a402200d95fecef4529d969836f1fe13c6cb0d/packages/client/ui-model-selection/src/client/ModelSelect.tsx#L103-L115).

**Exceção relevante: conta DeepSeek.** Há listing autenticado e cache por token+endpoint, conservando último resultado bom. `resolveAccountCatalog` filtra requisitos de versão e capabilities utilizáveis. O decoder exige capacidade `anthropic_messages`, texto de saída e modalidades de entrada conhecidas; desconhecidos sem requisito de versão apropriado ficam indisponíveis. Sem listing bem-sucedido, usa catálogo suportado embutido. Este filtro específico não deve ser atribuído a todos os Providers pi-ai. Fontes: [AccountCatalogCache](https://github.com/deepseek-ai/deepseek-harness/blob/86a402200d95fecef4529d969836f1fe13c6cb0d/packages/llm/llm-deepseek-account/src/catalog.ts#L75-L124), [capabilitiesOf](https://github.com/deepseek-ai/deepseek-harness/blob/86a402200d95fecef4529d969836f1fe13c6cb0d/packages/llm/llm-deepseek-account/src/listing.ts#L88-L109) e [gateOf/resolveAccountCatalog](https://github.com/deepseek-ai/deepseek-harness/blob/86a402200d95fecef4529d969836f1fe13c6cb0d/packages/llm/llm-deepseek-account/src/resolve-catalog.ts#L66-L145).

**Retry.** `llm-retry` agenda recuperação segundo política do Provider e retorna decisão `retry`; esse executor não escolhe outro Model. Não é evidência de cadeia automática de modelos como a configuração explícita do Hermes. Fonte: [request-error recovery](https://github.com/deepseek-ai/deepseek-harness/blob/86a402200d95fecef4529d969836f1fe13c6cb0d/packages/llm/llm-retry/src/index.ts#L195-L245).

## Proposta original para a feature 0054 — histórico de discovery

Atualização de discovery em 2026-10-15: após esta comparação e a consulta ao endpoint público, o usuário escolheu explicitamente **Models.dev com cache local**. A recomendação inicial de usar LiteLLM para o catálogo de seleção, abaixo, foi superada por essa decisão; LiteLLM permanece responsável pela estimativa de custo existente. O [brief 0054](../../briefs/0054-direct-provider-model-selection.md) registra o escopo aprovado. Naquele checkpoint a implementação ainda não havia começado; a entrega posterior está registrada no status inicial deste documento.

Para nossos quatro adapters nativos (OpenRouter, OpenAI, Anthropic e Gemini), a parte reaproveitável é separar: Provider executável; Model conhecido; capabilities adequadas ao nosso contrato; credencial configurada; acesso remoto confirmado quando houver evidência. São estados diferentes.

Recomendação de escopo: aproveitar os metadados LiteLLM já fixados no projeto para IDs e capabilities, mantendo a allowlist dos quatro Providers executáveis. Não adicionar models.dev só para reproduzir a origem usada pelo OpenCode. Sugestões devem filtrar o contrato realmente exigido pelo personal-agent; um requisito de Tools precisa ser decidido pelo nosso produto, não importado do Hermes. Preservar ID completo e mostrar claramente quando um ID manual não possui metadado suficiente. Escolher no discovery se esse caso será recusado ou exigirá declaração explícita, em vez de fingir compatibilidade comprovada.

Um listing pode melhorar sugestões e validação, porém não substitui metadados de capacidades nem garante inferência futura. Erros de seleção devem explicar o motivo; uma falha de catálogo não deve provocar troca silenciosa da rota escolhida. Estas são conclusões de desenho propostas a partir da comparação, não mudanças realizadas.

## Limites

Não foram executados agentes nem acessadas contas; comportamentos são leitura de código, não testes live. Foram examinados os caminhos citados, não todos os plugins/adapters. Não foi rastreada a geração interna do catálogo da dependência pi-ai; sua origem última pode diferir da origem de consumo no Harness. Não se provou filtro geral de System/Streaming/Tools em toda seleção de nenhum dos três. A UI OpenCode foi verificada no controlador de lista/visibilidade; não foram auditadas todas as superfícies de autocomplete. Datas e branches publicados foram revalidados; o comportamento descrito fica preso aos SHAs citados.

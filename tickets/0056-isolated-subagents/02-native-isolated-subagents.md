# 02: Execute named native Subagents with isolated state and parent boundaries

**What to build:** The parent can call `agent(name, task, references?)` for an actually discovered named role, execute it natively in a fresh process/Session, and receive its handoff. The child shares the parent's immutable route and workspace while preserving role permissions, live Agent Mode, confirmation, Call Log, spend and cancellation boundaries. Prove the three installed SDD roles can reach their required instructions/resources offline.

**Blocked by:** 01 — Read bounded Skill resources and expose installed SDD dependencies.

**Spec:** `docs/specs/0056-isolated-subagents.md` — R04-R21, Module and interface choices, Testing Decisions. **ADRs:** ADR-0014; ADR-0002/0003/0005/0008/0010/0011/0012/0013.

- [x] Discover bounded named Markdown/TOML definitions in the six workspace/global locations with the exact valid-source precedence from R04-R06. Preserve one complete definition, diagnostics and revalidation; permit legitimate global role-file symlinks under home. Cover invalid higher-priority fallback, conflicting formats, invalid size/text/path and changed/retargeted advertised roles.
- [x] Parse explicit YAML/TOML metadata only. Actual complete Claude Markdown SDD roles beat the lower-priority literal TOML pointer instructions; those pointers are never imported. Model metadata cannot affect routing. Native and mapped allowlist names follow R12; absent, empty, unknown-only, narrowed and unsupported parameterized permissions fail closed as specified.
- [x] The parent sees effective role metadata in `agent` and dispatches only advertised names with bounded task/references. Missing role, stale definition or invalid arguments fails before child Provider work. Result/error text is bounded, names role/Session and preserves the child's opaque final handoff, including product questions. No generic substitute, separate `/agents` command, or SDD-stage hardcoding is introduced.
- [x] A small fresh-process runner calls the production Router with the transferred Runtime Configuration and capabilities, existing credentials and exact Workspace Root/limits. It does not reload selection/settings, launch a REPL/external agent CLI, or share process-global Session/Registry/Todo/Job state. Subsequent child retries/follow-ups/Compression retain the original route/capacity snapshot even if configuration changes elsewhere.
- [x] Child requests contain Project Instructions, selected role, execution boundaries, task and reference locators, without parent Conversation/Summary/Todo/Memory/pending state/replay/active Skills or automatic `sdd-main` activation. A second child starts fresh after either success or failure.
- [x] Child Tool schemas and execution both intersect parent configuration with the role allowlist and live Agent Mode. `agent` and `question` are always removed. Test fabricated forbidden requests before validation/confirmation/side effects, including explicit parent-disabled shell/websearch/MCP and attempts to delegate or contact the user. Skill resources remain available only when `skill` is permitted.
- [x] One synchronous child runs at a time; a batch of delegates finishes them in order and rejects concurrent/reentrant use. The guard releases on success, error, interruption and spawn failure.
- [x] Child confirmations relay through the sole parent terminal with role/Session attribution. Existing approve/reject/EOF, dangerous-shell Strong Confirmation and Network/MCP policies apply. Live plan/build/auto changes synchronize at execution boundaries; plan blocks a pending mutation even after approval and auto does not approve a pending prompt. Missing/closed confirmation IPC refuses the operation.
- [x] Child file Tools retain workspace/secret/recovery exclusions and their own execution checkpoint. Test real allowed mutation, rejected confirmation, traversal/global-file refusal, child recovery provenance and shared-file checkpoint conflict refusal. Parent checkpoint images are not merged with child images; shell recovery policy stays intact.
- [x] Each child has a distinct self-contained Call Log v3, explicit `session_kind: subagent`, parent Session/execution/Tool-call/role metadata, an opening and Turn End. Parent start/finish records link the same identities. Readers accept valid Subagent logs and unchanged normal/Fork logs; malformed Subagent metadata and malformed Fork seeds are refused without weakening existing Fork rules.
- [x] Physical Attempts occur only in child logs. Durable compact parent receipts credit original child Attempt identities once, including failures, retry and Compression. Prove duplicate delivery/completion cannot double-charge. Parent visible totals, `/usage`, footer and Run-end totals include available child spend; `/report` separates delegated subtotal/coverage/child links from its existing own-Attempt/token/latency groups. Missing/invalid costs remain unknown and no historical receipt is charged on Resume.
- [x] Attempt receipts arrive before final child success. An interrupted/crashed child reconciles bounded available Call Log evidence without duplicate credits and reports incomplete coverage explicitly when needed. Credentials travel only through private IPC/existing configuration and remain redacted from errors, results and audit/log payloads. Persistence/audit failure stops dependent dispatch.
- [x] Ctrl+C during child Provider/Tool/confirmation/wait stops and reaps the child plus its foreground shell descendants/Background Job groups before terminal control returns. Success/error also cleans remaining child jobs. Worker crash/channel loss cannot leave known child jobs detached; bounded graceful and forced shutdown are tested with readiness synchronization. Existing parent-owned jobs survive child-only cleanup.
- [x] Parent interruption records a terminal delegation outcome in its pending Tool prefix and never automatically reconnects/resumes/replays that child on Retry/Resume. Any subsequent fresh delegation mints a new Session. No automatic child recovery loop is added.
- [x] Offline smoke checks select `sdd-planner`, `sdd-implementer`, and `sdd-reviewer`, show fresh expected role prompts/Tool sets, load required Skills/support files, and return representative handoffs through a fake Provider inside a real worker process. Synthetic homes make tests reproducible; separately record production discovery of the installed symlinked definitions/dependencies. This verifies execution and boundaries, not paid model quality.
- [x] Tests follow the spec's production Router/REPL, real-process and evidence-reader seams. A narrow process/bootstrap injection may install the fake Provider inside a test worker; no test-only production environment switches or child-policy bypass is added. Regenerate/review all intentional prompt-surface changes. Focused checks and the complete available suite pass; record precise environment-restricted reruns and counts, leave unrelated tests unchanged, and run `git diff --check` before the authorized ticket commit.

This slice is substantial because isolation, capability enforcement, lifetime and accounting must work together at the first runnable child boundary. Use small red/green increments: one read-only role/answer, then permission and evidence cases, then confirmation/mutation and cancellation cases, and finally SDD smoke coverage. Do not broaden into Provider rewrites, an RPC framework, a shell sandbox, an installer or parallel execution. Keep README changes concise if needed to document the Tool/definition formats.

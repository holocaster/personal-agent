# 02: Stream OpenRouter and OpenAI text safely through the terminal

**What to build:** Ordinary OpenRouter/OpenAI tasks and Tool follow-ups deliver safe flushed text before response completion, while validated completed messages, usage, Tool execution, Retry and terminal keyboard ownership retain their contracts.

**Blocked by:** 01 — Report recorded activity across the current Session's Runs.

**Spec:** `docs/specs/0052-session-report-streaming.md`, Streaming contract and transport (R06–R09), Output safety and failure behavior (R10–R13), Accounting and completed state (R16), Isolation and user documentation (R17), and Testing Decisions. **ADRs:** 0002, 0005, 0008.

- [x] Extend the synchronous Chat Completions Provider calls with an optional text callback; streaming calls still return a single completed AssistantMessage/usage pair. Buffered calls remain available for maintenance/direct callers. Retain prepared input/auth/output allowances, OpenRouter host preferences and optional diagnostics. OpenAI uses Chat Completions with stream options for final usage; no API/SDK migration.
- [x] Shared urllib SSE reader emits events incrementally across split UTF-8/read/line boundaries, LF/CRLF/CR, multiline data/comments and optional event names. Enforce 256 KiB per event and 8 MiB new assembled response bounds without sparse unbounded Tool indices or whole-body reads. Pending unterminated event/UTF-8 at EOF fails. Close HTTP resources on success/error/interruption/callback failure.
- [x] Assemble selected-choice text and interleaved indexed Tool id/name/argument fragments into the existing final shape. Require valid finish reason and `[DONE]`, consume final usage, accept OpenRouter's repeated identical finish on its empty accounting frame and OpenAI's usage-only empty choices. Early EOF, error finish, malformed required fields or contradictory finish cannot complete an answer. Reasoning/argument metadata is never ordinary text.
- [x] Separate complete-message termination from optional accounting. Missing usage remains unknown; supplied invalid known usage fields fail completion, retaining earlier valid normalized fields on the exception. Snapshots replace present cumulative fields rather than adding; HTTP-200 stream errors use Provider error classification and preserve usage. Ctrl+C also retains latest known usage.
- [x] Router supplies `start/text/end` notifications for each dispatched ordinary exchange, including Tool follow-ups, and always settles a started exchange. Evaluator and manual/automatic Compression receive no visible stream callback. Raw deltas never write Conversation, Turn End, partial Tool results or separate delta log records.
- [x] Incremental Router secret filtering protects every existing known key snapshot, including old protected keys after configuration changes, across arbitrary/overlapping chunk splits. Redact before control sanitization. On error/interruption discard undecidable secret-prefix tails; on success safely flush them. Keep filtering state per Attempt and preserve completed-message/detail/error protections.
- [x] New streamed Attempts record `streamed: true` and nullable `first_text_latency_ms`, measured from actual dispatch to successful synchronous delivery of the first nonempty safe ordinary text. Buffered/textless/unmeasured Attempts are correctly labeled; controls, header, Tools, thinking and empty deltas do not count. Preserve zero and measurements/usage on errors/interruption; `/report` displays measured coverage.
- [x] Retain transient/context recovery only before safe text delivery in the current exchange. After visible partial text, stop without automatic retry or recovery, mark incomplete and permit explicit `/retry`. A final accounting failure obeys the same rule. Retry/Resume retains completed Tool prefixes and never converts a partial stream into completed Conversation or repeats completed Tools automatically.
- [x] REPL emits one lazily opened plain `llm>` text segment per text-bearing exchange, flushes before completion and closes it before Tools/prompts/notices/errors. Tool-only exchanges do not fabricate output. Successful final answer is not printed twice and metadata/footer/Turn End still update once. Piped/NO_COLOR output has no newly introduced animation/control codes.
- [x] Existing Input Box busy keyboard reader and supported prompt-toolkit output primitives coordinate text/redraws, preserve queued next-task input, Shift+Tab and Ctrl+C, and yield ownership to Question/Tool Confirmation. No competing reader, unbounded queue, deadlock, lingering output callback/thread or Spinner clear overwrites text. Mode switches keep current in-flight dispatch and affect subsequent policy.
- [x] Controlled HTTP/output/clock fixtures prove first safe output and flush precede the final wire event, exact final message/usage and one completed log turn. Test both Providers' terminal/error/usage variants, interleaved Tools and invalid completed arguments with no side effects, malformed/split/capped SSE and resource cleanup. Existing buffered fixtures remain valid for Evaluator/Compression.
- [x] Capture every key split/overlap and failing prefix, controls/Unicode, first-text error/cancel, failure before first text, later Tool-round retry, pipe input, real busy Input Box cancellation/mode changes, Question/confirmation transitions and Detailed Audit leakage. Focused Provider/Router/REPL/Input Box/Call Log/report/continuation/context/evaluator tests pass before independent review.
- [x] Concise README/help explains streaming and explicit Retry after incomplete output, locally measured first text and internal maintenance isolation. Describe only the Providers implemented at this checkpoint; ticket 03 completes default streaming everywhere.

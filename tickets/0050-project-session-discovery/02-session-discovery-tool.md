# 02: Discover, read and search recorded Sessions through one bounded Tool

**What to build:** A model can find its previous Session, read the actual recorded timeline and search literal historical evidence in this project or explicitly across projects, including interrupted Sessions and explicitly selected audit payloads.

**Blocked by:** 01 — Keep each Run's logs in its starting project and Resume the latest Run.

**Spec:** `docs/specs/0050-project-session-discovery.md`, Shared filesystem/read seam (R06–R08), Model-facing Tool contract (R09–R15), Tests and documentation (R20), and Testing Decisions. **ADRs:** 0003, 0005, 0008.

- [x] Register one `session_logs` Tool with R09's exact schema, combination validation, defaults (20 list, 100 read, 20 search; maximum 100), and no extra arguments. Available in plan/build/auto without confirmation; preserve busy execution, correlation and ordinary Tool invocation logging.
- [x] Omitted project means captured Workspace Root, `all` explicitly spans project folders, and absolute original-project selectors compute the folder without inspecting the project directory itself. Relative/traversal selectors are errors. Old flat files are ignored. Cross-project evidence includes validated original directories; invalid headers report unknown identity and attributed diagnostics.
- [x] List candidates by project id ascending then Session Id descending; audit companions are not separate Sessions. List/search include the current Session. Explicit-id reads/searches can inspect it. Only last/previous aliases exclude the current Session, including a resumed current Session; shared R05 Run recency picks the latest previous Session.
- [x] Read requires a Session selector; search optionally narrows to it. Across-all explicit ids must be unique or error with project-selection guidance. Resolve aliases once per paging operation and bind continuation to that concrete Session. Empty/missing catalog scope is honest empty output; unsafe selected files and other access failures are explicit errors.
- [x] Read/search reuse ticket 01's safe candidate and bounded record reader; no file paths from metadata/cursors become read roots. Check no-follow directory/file boundaries through open, avoid opening FIFOs, and validate ids. Meaningful symlink/replacement/forged-selector tests demonstrate no escape or blocking.
- [x] R12 timeline shows each submitted user request once, assistant Attempt answers/Tool intents, actual Tool results/errors, Turn End outcomes, Run and Conversation changes, and maintenance provenance. Do not replay/duplicate successful or pending Conversation snapshots or repeat submitted task text across Attempts.
- [x] Actual execution is distinct from Tool intent; failed/interrupted/dangling/missing-close activity is explicitly unresolved. Malformed JSON/UTF-8/non-object/wrong-id records and incomplete tails are attributed evidence; valid following records remain readable. Page boundaries report partial inspection rather than falsely declaring missing outcomes. A malformed readable log still fails strict Resume.
- [x] Search uses redacted bounded record JSON with literal casefold matching, at most one match per physical record, up to 200-character first-match excerpts and exact source references. It includes ordinary fields not rendered in the default timeline, with R10 candidate/line ordering. No regex, index, semantic service or extra model request.
- [x] Return `{content, has_more, next_cursor}` with readable untrusted-history labeling and original project/Session/source/1-based-line/timestamp attribution. The existing Tool Output Cap bounds UTF-8 text including diagnostics; no new configurable cap. Cursor metadata is bounded separately as specified, contains no historical text/keys, and binds selectors/query safely.
- [x] Directory enumeration and per-invocation byte/record/parse bounds hold even for rejected candidates, no-match scans and enormous single lines. Read/search stop with advancing continuation on scan exhaustion. Oversize lines are skipped incrementally with attributed warnings, not fully allocated; individual over-cap rows are marked truncated and advanced without looping.
- [x] On unchanged sources, paging yields all untruncated rows/matches without gaps/duplicates and terminates. Validate invalid/changed-binding cursors, source replacement/truncation and stale catalog handling. Append growth is allowed; EOF differs from an empty page with continuation. Test UTF-8 boundaries and tiny caps using deterministic work counts.
- [x] Explicit `source: audit` reads/searches only safe companion records with recorded enabled coverage and available correlation ids. Missing/unrecorded/unverifiable coverage errors for a selected Session, or gives attributed unavailable diagnostics during multi-Session search; mixed enabled/disabled Runs and partial coverage stay visible. Ordinary default discovery does not open audit companions or enable/create them.
- [x] Reuse invocation `result_secrets` and existing recursive redaction before matching/excerpts/caps and across metadata, JSON keys, diagnostics and errors. Current provider/Tavily keys and keys protected before configuration changes never reappear in returned, displayed or newly logged Tool results; do not claim detection of unknown old credentials.
- [x] Malicious historical instructions and recorded calls have no effects: no Provider request from the reader, Tool execution, instruction/Skill activation, memory mutation, Conversation replacement or Resume. Historical source files remain unchanged; only present Tool invocation logging occurs normally.
- [x] Update concise supported README sections/examples for scope, schema/defaults, last behavior, timeline/strict Resume distinction, source evidence, audit availability and limits/cursors. Focused `test_session_logs` plus affected Registry/audit/Call Log tests pass. One fake-provider REPL regression requests previous history through this Tool, receives an attributed result and continues the current turn without repository searches or extra clarification.

## Implementation notes

Reuse storage/recency from 01 and existing output-cap/redaction/Tool handling. Keep the new reader in one small module unless existing ownership requires otherwise. The result is evidence, not a restored Conversation. Preserve other agents' changes; validate each increment. No new dependencies or unnecessary code comments.

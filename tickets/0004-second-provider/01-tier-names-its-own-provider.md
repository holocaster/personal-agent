# 01: Each Complexity Tier names its own Provider

**What to build:** the Router stops knowing OpenRouter exists. Each Complexity Tier gets an optional `TIER_<TIER>_PROVIDER` naming the Provider it runs on, defaulting to `openrouter` when unset or empty, and the Router calls whatever that name resolves to through the Provider Contract instead of importing `call_openrouter`. A typo'd Provider name is a startup error before the first prompt, naming the variable, the bad value and the accepted names. The Call Log and the REPL's routing line say which Provider answered. OpenRouter is still the only Provider that exists, so a user who changes nothing sees no behaviour change whatsoever — that invariance is the point of this slice, and the existing test suite passing largely untouched is the proof.

**Blocked by:** None (can start immediately).

**Spec:** `docs/specs/0004-second-provider.md` — Solution; Implementation Decisions (Providers become a package; Provider Contract; Registry and dispatch; Shared HTTP helper; Tier Config; Validation returns problems, not variable names; Required keys are the union of referenced Providers; Router; Call Log schema; REPL); Testing Decisions (One seam, still; Fixture extension; Coverage for Tier Config, Startup, Routing and dispatch, Call Log, REPL). **ADRs:** `docs/adrs/0002-hand-rolled-provider-contract.md`.

- [x] The Provider module becomes a Providers package: OpenRouter moves into its own module with its URL, payload, parsing, timeout and retryable codes carried over unchanged, alongside a shared HTTP helper and a registry. No compatibility shim is left at the old import path.
- [x] The shared HTTP helper owns the POST (JSON encode, headers, shared timeout, decode) and the retryable-HTTP-code predicate that each Provider parameterises with its own code set. `urlopen` is imported there and nowhere else — that single import is the seam for every Provider added later.
- [x] A Provider is a module exposing `call(model, system, messages) -> (answer, usage)` and `is_retryable(exc)`. The registry maps a Provider name to that module; no Protocol class, ABC or wrapper object is introduced.
- [x] Resolving an unknown Provider name raises rather than falling back to OpenRouter — startup validation is the only guard against it happening.
- [x] Tier Config reads `TIER_<TIER>_PROVIDER` per tier: unset, empty or whitespace means `openrouter`; the value is stripped and lowercased, so `OpenRouter ` resolves. It exposes a Provider accessor alongside `model_for`.
- [x] Tier Config's single `api_key` field becomes a mapping from Provider name to the value of that Provider's key environment variable. Providers still read their own key from the environment at call time; Tier Config holds keys for validation only.
- [x] `validate()` returns human-readable problem strings instead of bare variable names: one per missing model ID, one per missing key for a Provider a tier actually references, one per unrecognised `TIER_<TIER>_PROVIDER` naming the variable, the offending value and the accepted names. All problems are reported together in one pass.
- [x] `__main__` prints those problems under a generic configuration-error heading, one per line, and exits non-zero before any prompt — same error class, same moment, same exit code as today's missing-variable message, which this replaces.
- [x] A tier whose Provider name is unrecognised contributes a name problem and no key requirement.
- [x] `route()` resolves each tier's Provider name from Tier Config and its module from the registry, and calls `call` / `is_retryable` through the Contract. The Attempt loop, backoff schedule, Escalation ladder and Budget Guardrail rules are untouched.
- [x] `RouteResult` carries the Provider name, and the REPL's routing line names the Provider alongside the tier and model. The failure line is unchanged.
- [x] The Call Log gains `provider` and `cost_estimated` (`false` on OpenRouter entries — no estimation exists yet). Every existing key keeps its name, type and meaning, one entry per Attempt.
- [x] `install_fake_urlopen` is repointed at the shared HTTP helper's `urlopen` and gains the ability to build a response in the shape of whichever Provider the outgoing request's URL identifies, with a bare string still meaning "the answer text" and the dict form still carrying neutral `prompt_tokens` / `completion_tokens` / `cost`. No fake Provider, fake registry or second seam is introduced.
- [x] Existing tests keep passing essentially unchanged apart from the moved import path and the new configuration-error message — that is the regression test for "unset `TIER_<TIER>_PROVIDER` behaves exactly like today".
- [x] Tests cover: the default resolving to `openrouter`; empty/whitespace/mixed-case values; an unrecognised value exiting non-zero at startup with a message naming the variable, the value and the accepted names, including when only the `complex` tier is misconfigured; a missing key for a referenced Provider doing the same; several problems reported together.
- [x] A Call Log test reads the written file and asserts `provider` and `cost_estimated: false` on every entry of a retried-and-escalated chain, with the existing key set intact; a REPL test through `StringIO` asserts the routing line names the Provider.
- [x] The README documents `TIER_<TIER>_PROVIDER`, that it is optional and defaults to `openrouter`, and the new `provider` / `cost_estimated` Call Log keys.

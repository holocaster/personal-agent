# 02: Anthropic as a second Provider, with Estimated Cost

**What to build:** the user can point a Complexity Tier at Anthropic — `TIER_EASY_PROVIDER=anthropic` with an Anthropic model ID and `ANTHROPIC_API_KEY` — and get an answer, with retry, Escalation and the Budget Guardrail behaving exactly as they do on OpenRouter. A user routing everything to Anthropic needs no `OPENROUTER_API_KEY`. Because Anthropic reports token counts but no cost, the Call Log entry carries a cost computed from those counts and `cost_estimated: true`, so an estimate is never mistaken for a bill; an Escalation from an Anthropic tier to an OpenRouter one crosses upstreams mid-chain with no special case anywhere. Anthropic is deliberately first: it is the new Provider least like OpenRouter, so the Contract from ticket 01 is proven against the hardest case before the easy ones arrive.

**Blocked by:** 01 (there is no Contract, registry, shared HTTP helper, per-tier Provider config or `cost_estimated` log key to hang this on until that lands).

**Spec:** `docs/specs/0004-second-provider.md` — Solution; Implementation Decisions (Per-Provider specifics; Usage normalisation; Retryable codes per Provider; Estimated Cost; Pricing model names; `cost_estimated` is a property of the Provider; Dependency); Testing Decisions (One seam, still; Cost estimation is tested against the real utility; Coverage). **ADRs:** `docs/adrs/0002-hand-rolled-provider-contract.md` (hand-rolled Provider, `litellm` for pricing only), `docs/adrs/0001-escalate-on-technical-failure-only.md` (Escalation trigger unchanged).

- [x] An Anthropic Provider module implements the Contract as a thin `urllib` caller through the shared HTTP helper — no vendor SDK, no `litellm.completion()` — and is registered under `anthropic`.
- [x] Its request and response shape are confirmed against Anthropic's current official API documentation (Context7) before the parser is written, not assumed from the spec's table. Known specifics to honour: the Messages endpoint, `x-api-key` plus a version header, `system` as a top-level field rather than a message, a required `max_tokens` held as a module-level constant (not a configurable knob), the answer read from the first content block, and usage reported as input/output token counts.
- [x] `call()` normalises usage into the keys the Router already consumes — `cost`, `prompt_tokens`, `completion_tokens` — plus `cost_estimated: true`. No Anthropic field name reaches the Router.
- [x] `is_retryable` states Anthropic's own code set explicitly: the shared transient codes plus 529 (overloaded). Auth/bad-request codes, parse-shaped exceptions and unrecognised exception types stay non-retryable.
- [x] A cost module exposes one function taking a pricing-qualified model string and the token counts and returning a float or `None`. It imports `litellm` lazily inside that function so an OpenRouter-only session and REPL startup never pay for the import.
- [x] Any failure from the pricing utility — unknown model, missing token counts, a moved signature — is caught and returned as `None`. The session continues, the Budget Guardrail records nothing, and the entry logs `cost: null`.
- [x] `litellm` is used only for its pricing utility (`completion_cost()`, or `cost_per_token()` if the pinned version's signature demands raw token counts); its `completion()` and routing surface is untouched, per ADR-0002.
- [x] Each Provider owns the pricing-qualified model string it passes to the estimator; Anthropic's is its raw model ID.
- [x] `cost_estimated` is a property of the Provider, not of the estimate's success: Anthropic entries carry `true` even when the cost came back `None`; OpenRouter entries stay `false` with its reported cost.
- [x] `litellm` is added to the project dependencies and the lock file; the Provider modules themselves stay stdlib-only.
- [x] Validation requires `ANTHROPIC_API_KEY` only when a tier references `anthropic`, and stops requiring `OPENROUTER_API_KEY` when no tier references it — a single-Provider Anthropic setup validates with exactly one key present.
- [x] Tests through the existing `urlopen` seam assert that an Anthropic-configured tier sends its request to Anthropic's URL with its auth and version headers, `max_tokens`, the system prompt in the right place, and that the response shape is parsed into `(answer, usage)`; a response missing usage fields yields `None` for them rather than raising.
- [x] Tests cover retry at an Anthropic tier (repeat requests to the same host, 529 treated as transient) and a cross-Provider Escalation: an exhausted Anthropic `easy` tier sends the next requests to the `medium` tier's OpenRouter host in order, a success there returns normally, and a Budget Guardrail ceiling blocks that Escalation exactly as it blocks a same-Provider one.
- [x] Cost estimation is tested against the real `litellm` — no fake: a widely-known model ID with plausible token counts yields a positive float (asserting type and positivity, never an exact price), and an unknown model ID yields `None` without raising.
- [x] A Call Log test reads the written file for a chain crossing both Providers and asserts each entry's `provider`, `model`, `cost` and `cost_estimated`, including the unpriceable-model case logging `cost: null` with `cost_estimated: true`.
- [x] The README documents `anthropic` as an accepted Provider, `ANTHROPIC_API_KEY`, that keys are required only for Providers your tiers reference, and that cost on non-OpenRouter Providers is an estimate rather than a billed figure.

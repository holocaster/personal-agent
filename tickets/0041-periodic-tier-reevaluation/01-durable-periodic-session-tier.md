# 01: Deliver durable periodic Session-tier selection

**What to build:** A fresh Session can recover from a weak initial tier choice before tasks 5 and 15 using cumulative user requests, while manual control, Clear, Retry, cancellation and Resume preserve predictable progress. Deliver the complete path through REPL acceptance, Evaluator, Call Log replay and visible routing, with old-log compatibility and runnable acceptance checks.

**Blocked by:** None (can start immediately).

**Spec:** `docs/specs/0041-periodic-tier-reevaluation.md` — Requirements R1–R16; Implementation Decisions (Ownership and interfaces, Call Log contract, Execution and input formatting, Presentation and compatibility choices); Testing Decisions. **ADRs:** ADR-0007; ADR-0006's retained single-route/persistence/spend guarantees; ADR-0005's single durable Session record; ADR-0002's Provider boundary.

## Acceptance criteria

- [x] **R1:** With a fresh automatic Session executing at least 16 new tasks, evaluator calls precede ordinary tasks 1, 5 and 15 only. No startup or post-15 scheduled call; a complex tier still evaluates at remaining checkpoints.
- [x] **R2:** Captured evaluator payloads decode to exact cumulative arrays 1, 1–5 and 1–15 (or all accepted messages since Clear). Include failed/cancelled/manual-period tasks; exclude assistant/Tool/Question answers, Memory, Skills, Todo, summary, ordinary instructions and replay. Unicode, multiline and JSON-like text round-trip without omission.
- [x] **R3:** Durable submission ordinals advance once per new routed task, including failures and cancellation. Identical new texts count separately. Local commands, blank input, Provider retries, Tool follow-ups, Compression and `/retry` do not add an ordinal or corpus entry. Retry reuses its original position, remains Run-local and does not appear solely because of Resume.
- [x] **R4:** Initial evaluation can select each tier; later higher/equal/lower candidates dispatch at max(current, candidate), including after `/model auto`. Only explicit manual commands can downgrade.
- [x] **R5:** Manual selection before first task and across checkpoints suppresses evaluation, can lower the tier, cancels an outstanding request, and keeps accumulating texts/count. Passed suspended checkpoints are skipped; invalid `/model` arguments leave all state unchanged.
- [x] **R6:** Auto at count 8 evaluates the next execution and retains scheduled 15; auto at count 4 then task 5 runs one evaluation; auto after 15 runs once without restarting the schedule. Repeated commands queue no duplicates. Auto followed by an available Retry evaluates without advancing count. The selected tier is retained until completion.
- [x] **R7:** Undo/Retry's Undo and manual/preventive Compression preserve corpus/progress. Clear empties corpus, not tier/count/mode/checkpoint/request, including after Resume. Clear then auto plus Retry uses the empty array rather than resurrecting discarded task text. Agent Mode/config edits do not reset selection policy.
- [x] **R8:** Real-log Resume restores policy, exact accumulated input and progress before 5/15, after failed or cancelled evaluation, after manual/auto followed immediately by exit, for an empty new Session, and after a persisted submission lacking Turn End. Retained Conversation size does not affect timing and no evaluation runs at startup.
- [x] **R9:** Actual policy-less v2 fixtures retain saved tiers without scheduled calls; saved pending gets its old one-off only; no-tier gets the existing medium warning once. Misleading Attempts/command audits never infer origin/history/count. Policy initialization starts empty at ordinal zero and is persisted; auto activates remaining checkpoints in newly tracked progress, including across another Resume. Malformed new data is not legacy absence.
- [x] **R10:** Invalid/truncated/Tool-bearing results, exhausted retries and non-retryable/preparation/counting failures choose initial medium but preserve later easy/complex with visible warnings. Complete/consume the checkpoint/request once, then assess ordinary dispatch normally; later ordinary failure or Retry does not repeat a completed evaluation.
- [x] **R11:** Cancellation during initial/later preparation, dispatch and backoff records interrupted Turn End and prevents ordinary dispatch. Count/input survive and evaluation stays due through Retry, next task and Resume. A new task still advances count; one later completion satisfies all already-due checkpoints if cancellation spans another checkpoint.
- [x] **R12:** Test full easy-route input within and beyond its measured ceiling including serialization/fixed-instruction overhead. Overflow sends no evaluator request and follows the completed failure policy; no truncation, summaries, splitting or recursive Compression. Existing route output reserve remains in use and ordinary budget checks stay independent.
- [x] **R13:** New start/state/submission records and Clear follow the spec schema and write-before-mutation/dispatch ordering. Persist completed progress even when tier stays unchanged. Replay rejects invalid policy/version/types, ordinal gaps/repeats and missing policy on post-initialization tier changes. Inject partial submission, policy/completion and Clear writes plus failed restoration: preserve prior prefix where restoration succeeds; CLI fails visibly with status 1 and no dependent dispatch/fallback. Preserve fatal evaluator Attempt/detail write handling.
- [x] **R14:** Evaluator Attempts/details retain `purpose: "tier_selection"` and current-task attribution. Retry/failed costs are charged once, unknown usage remains unknown, Estimated Cost stays labeled and Resume resets Run spend. Evaluator output never enters Conversation or replaces ordinary `/usage`, including evaluation-only cancellation.
- [x] **R15:** Evaluation and ordinary dispatch share a configuration snapshot and current tier mappings; later `/config` edits affect later tasks only. Relevant ordinary same-route retry/recovery, Compression, Tool follow-up, Question and Agent Mode/confirmation regression checks remain green. No model configuration edits, new Provider or Escalation.
- [x] **R16:** Interactive/piped notices show kept/raised tier, warnings and manual guidance. `/model` shows mode/checkpoint/outstanding request; footer retains selected tier while pending separately from last answer. Help and Clear notice explain behavior. Correct concise README/package identity, CLAUDE.md and CONTEXT.md when implemented; do not rewrite historical research decisions as current facts.

## Execution guidance

Reuse the existing REPL, routing Evaluator, shared Provider exchange, Call Log loader and CLI fatal path. Separate task acceptance from execution so Retry is explicit, not inferred from string equality. A small routing state value/pure transition helper is enough; do not add a framework or a separate durable file. Extend the loader's routing return component and update actual callers/test fixtures together.

Use `routed_task_submitted` deltas plus the spec's `routing_policy` fields on existing tier-state records. Validate new state and persist completed transitions atomically as single records. Keep full accepted input in the durable replay contract and existing secret-redaction behavior in diagnostic/Attempt/detail paths. Apply the initial/later failure choice in the Session owner, not as an unconditional medium return from the Evaluator.

The evaluator request is a fixed instruction plus one stdlib-JSON array of task strings; keep the current executed task separately for Attempt attribution. Reuse the actual easy-route budget and existing HTTP seam, without sending Conversation or compressing evaluator text.

Work incrementally inside this ticket: acceptance/schedule and replay, command/lifecycle behavior, then failure and persistence cases. Each increment gets focused checks, but no separately incomplete schema/command tickets are needed. Planning artifacts are authoritative; do not edit the brief or orchestrator-owned PROJECT_STATE.md. Implemented-behavior documentation may be updated as behavior lands.

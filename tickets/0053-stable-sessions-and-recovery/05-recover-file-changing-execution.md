# 05: Recover the latest file-changing execution

**What to build:** `/recover` previews and confirms exact file recovery for the latest routed execution changed by `write`, `edit` or `apply_patch`, including failed/interrupted work and Resume. It refuses external edits and makes Retry safe after restoration.

**Blocked by:** None (can start immediately).

**Spec:** `docs/specs/0053-stable-sessions-and-recovery.md` — File checkpoints and recovery R21–R28, Delivery R32, Existing ownership and seams, File checkpoint persistence contract, Testing Decisions. **ADRs:** 0010; existing 0005 and 0008 remain in force as amended.

- [x] One submitted/explicit-Retry opening is one execution identified by Session/Run/opening position and original ordinal. Keep latest execution with successful actual file mutations, even error/interrupted/no Turn End. A Retry's set excludes previous executions' changes; no-op/reject/fully-rolled-back operations retain the previous eligible set.
- [x] Coalesce canonical files within that execution to first exact before and final exact after, including creation/deletion absence, mode and validated path/leaf-link identity. Check repeated-mutation continuity; never silently adopt an external intervening edit.
- [x] Persist version-1 exact base64 snapshots and hashes in owner-only `recovery-<Session Id>/` under existing project storage. Validate identity/schema/encoded and decoded bounds before loading; directories 0700, files/temp 0600, safe descriptor-relative no-follow/regular opens. Refuse unsafe owner/permissions, storage links/nonregular files and wrong Session/project/root.
- [x] Enforce image limit min(current PA_MAX_WRITE_BYTES, 4 MiB), 64 canonical paths, 16 MiB combined snapshot bytes, 24 MiB per manifest and 80 MiB latest/active/temp Session storage; reject would-exceed mutation before changing files. Latest-only retention plus bounded staging; do not evict within a recoverable set or introduce config knobs.
- [x] Exclude supplied/resolved `.env`, `*.pem`, `*.key` and checkpoint storage inside Workspace Root. Snapshot bytes remain exact and never enter Call Log/detail/report/session discovery/Provider input. Diagnostic previews use existing credential redaction and sanitization.
- [x] Integrate capture at existing prepare/approved-apply boundaries for three file Tools. After confirmation recheck live mode, path, prepared before-state and bounds; durable journal intent precedes first mutation, observed after-state/promotion precedes successful availability and dependent Tool/Provider exchange. No model/rejected/prepared-only action creates a checkpoint.
- [x] Preserve patch all-or-nothing rollback and restore partial single-file failed writes where possible. Capture failure before write leaves files unchanged; after-state/promotion failure halts with retained intent and uncertainty, never reports an available complete checkpoint. Successful earlier mutations remain recoverable when later Tool/Provider work fails/cancels.
- [x] `/recover` previews current latest set with outcome/uncertainty, exact execution identity/ordinal, paths and reverse diff. Bound/redact/sanitize preview, show omissions, exclusions/bounds/shell scope and older-Retry limit. No Provider call, no Conversation change, no checkpoint consumption during preview.
- [x] Require full `yes` after preview in build and auto, piped and interactive. Other text/EOF/Ctrl+C cancels unchanged. Plan previews but refuses restore with mode guidance, including a live switch to plan while confirmation is pending. Add help/completion and reject unexpected arguments.
- [x] Compare every current after-state before preview/confirmation and again before apply. Any content/existence/mode/link/parent/project/integrity mismatch refuses whole set without overwrite. Preserve unchanged supported in-root leaf symlinks, reject replaced/outside links, hard-linked mutation targets and nonregular paths. Untouched files/directories remain unchanged; no new parent directories.
- [x] Restore creation/removal, modification/exact bytes and modes, deletion/recreation. Persist restoration intent and perform safe rollback to known after-states on partial failure; name paths/error. Failed rollback/persistence halts and leaves explicit unresolved metadata blocking further unsafe mutation/dispatch. Success recorded then consumes availability; repeat recover never walks older history.
- [x] Write compact `file_recovery_started`/`file_recovery_finished` Call Log records with exact execution reference, no images. Append-prefix restoration/fatal behavior ensures intent precedes first restore and success never appears before durable completion; inject intent and completion failures.
- [x] Before restoration writes durably invalidate only matching target continuation. Retain request/ordinal for fresh Retry, discard obsolete Tool/assistant prefix, fetched URLs and Gemini replay and reset Todo to completed Conversation. Fresh `/retry` works after Resume using current route/config/mode, does not reuse undone success results. Preserve unrelated later pending execution, completed Conversation/Summary/evaluator corpus and successful task's existing retry Undo behavior. Invalidation remains conservative after later restore failure.
- [x] Resume never auto-restores or executes Tools. Reconcile interrupted mutations equal to exact before (not changed) or intended-after (observed); any third state is unresolved/refused. Reconcile partial restoration against recorded per-path progress and before/after; never claim success prematurely. Old Sessions without companions Resume normally with no invented original files.

Tests cover repeated same-file Tools, patch add/update/delete, restore after failed Provider/cancelled confirmation, and actual bytes/modes in isolated workspaces.

# 02: Safe calculator and clock Tool loops across all Providers

**What to build:** A user can ask any configured Tool-capable model to calculate or read the clock, let the model consume the results and answer, and continue the Conversation with complete Tool history. Tool safety, Provider replay, retries, and spending are part of the same working path.

**Blocked by:** 01 — Session Conversation, Context Window, and local commands.

**Spec:** `docs/specs/0005-agentic-repl.md`, Provider Contract and translation (R07–R09), Built-in Tools and execution (R10–R13), Reliability and accounting (R14–R16), complete Tool turns under R04–R06, Tool history under R02, Testing Decisions. **ADRs:** ADR-0001 and ADR-0002.

- [x] Every Provider implements the extended common request/response shape from R07, preserving text, ordered calls, stable IDs, arguments (including invalid ones for local rejection), matching results/errors, and Provider-owned replay data. Router control flow has no vendor wire-schema branches. Plain text remains a valid response with Tools enabled.
- [x] Each Provider request advertises both built-ins and serializes its native schemas from R08. Fake HTTP tests run calculator and clock exchanges to a final answer through OpenRouter, OpenAI, Anthropic, and Gemini.
- [x] OpenRouter sends `provider.require_parameters: true`; rejected Tool capability produces an explicit non-retryable error identifying Provider/model. There is no retry with Tools omitted, silent downgrade, Escalation on permanent capability failure, model-name heuristic, or paid startup probe (R09).
- [x] Chat Completions requests preserve assistant `tool_calls`, JSON-string arguments, and subsequent `tool_call_id` results. Anthropic keeps assistant blocks and places one result for each `tool_use` in the immediately following user message, marking errors. Gemini translates `functionDeclarations`, `functionCall`, and `functionResponse`, preserves returned IDs/names, and normalizes absent legacy IDs internally without mutating the original payload.
- [x] Gemini's same-model follow-ups preserve full original model parts and `thoughtSignature` fields in order, across multiple Tool rounds. Opaque metadata is neither displayed in `/history` nor passed to another Provider/model; completed foreign turns serialize from normalized content without losing text, requests, or results. Test a cross-Provider next turn and IDs both present and absent.
- [x] `calculator` implements precisely the restricted grammar, input shape, and character/node/value limits in R10 using no dynamic evaluation. Direct boundary tests reject code-like expressions, disallowed operators/types/keys, division by zero, non-finite values, and oversized inputs; ordinary signed/parenthesized arithmetic succeeds.
- [x] `current_time` accepts only an empty argument object and returns a timezone-explicit UTC ISO-8601 value under `utc_time`; prove the result with a deterministic clock (R11).
- [x] Only the fixed two-Tool mapping is executable. Invalid JSON, unknown names, incorrect/missing arguments and extra keys return a correlated error without invoking a Tool. Valid batches execute serially in order and produce exactly one result per call; repeated names with distinct IDs work. Invalid correlation fails the entire batch before any Tool runs (R12).
- [x] The loop retains mixed assistant text/Tool calls, all results, and final text. It executes no more than 8 Tool rounds or 16 calls in one response, allows a final answer after round 8, and stops before executing an over-limit batch. Tests prove the exact limits, readable errors, no incomplete committed turn, and a usable next request (R13).
- [x] Initial calls retain existing retry/backoff, technical-failure Escalation, and budget gating. After the first successful Tool request, subsequent calls remain on its Provider/model with their own retry budget; exhaustion ends the request without Escalation. Retry reuses computed results rather than re-executing Tools. Model-correctable Tool errors do not directly trigger retries or Escalation (R14).
- [x] Log every completed HTTP Attempt once, retaining original task text and existing cost provenance. Continue Attempt numbering within the tier across Tool exchanges, reset it on Escalation, and keep a separate per-exchange retry counter. Account for all reported costs once, including costs preceding later failure or interruption; local Tool work adds no Attempt. Preserve the interrupted in-flight Attempt behavior and `/clear` spending invariants (R15).
- [x] `/history` displays complete Tool calls/results without opaque metadata. A Tool turn at the 20-turn boundary is included/excluded as a unit, and follow-ups carry the entire pending turn with the originally selected prior context. A failed/interrupted loop leaves earlier turns intact (R02, R04–R06).
- [x] Concise README documentation covers the two Tools, arithmetic/loop bounds, UTC time, Tool-capable model requirement, completed-turn rollback, and pinning/accounting behavior. No new calling SDK, framework, transcript store, or API family is introduced (R16).
- [x] The full offline suite passes, including Provider wire fixtures, successful and malformed multi-call rounds, capability failures, pinned transient failure/exhaustion, initial Escalation, interruption, cost/log accounting, and mixed-Provider Conversation continuity.

**Implementation guidance:** Extend the existing Provider modules together so one contract works everywhere. Keep provider serialization local, Tool validation in one small module, and loop/retry/accounting in the existing Router path. Both built-ins are small; prefer stdlib arithmetic parsing and datetime to dependencies. HTTP fixtures should include complete vendor-shaped responses rather than bypassing translation with Provider mocks.

**Validation:** `uv run pytest`; inspect captured request sequences and temporary JSONL entries in focused behavior tests. This slice is independently demoable with deterministic fake Provider responses and requires no paid smoke test.

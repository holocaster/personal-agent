# 03: Isolate the offline test suite from ambient environment values

**What to build:** `uv run pytest` passes deterministically on any developer machine, regardless of what real values that machine's repo-root `.env` holds. Today the suite is red on a machine with a populated `.env` and can echo real API keys into pytest assertion diffs.

**Blocked by:** None (can start immediately). This ticket is independent test infrastructure, not part of the agentic REPL feature: it neither gates nor is gated by tickets 01 and 02, and it predates feature 0005 entirely.

**Spec:** none (fast path). The checklist below is normative. **ADRs:** ADR-0002 (hand-rolled provider contract) — do not add a runtime dependency to solve this.

**Root cause (already proven, do not re-litigate):** `model_router/cost.py` imports `litellm` lazily inside `estimate()`. `litellm` runs its own `dotenv` auto-load at import time, so the first test that reaches a cost estimate loads the repo-root `.env` and injects real `TIER_*_PROVIDER`, `TIER_*_MODEL`, `ROUTER_BUDGET_USD` and `*_API_KEY` values into `os.environ` **mid-run**, corrupting every later test that asserts on configuration. Trace confirmed with an `os.environ.__setitem__` tracer: `model_router/cost.py:5` -> `litellm/__init__.py:30` `_dotenv.load_dotenv(override=...)` -> `dotenv/main.py:108` `os.environ[k] = v`. `model_router/dotenv.py` is **not** the cause (an earlier hypothesis from the ticket 01 implementer); it only does `setdefault` and is not called from the test suite.

- [x] Reproduce first: with the repo's actual `.env` in place and unmodified, `uv run pytest` currently reports 7 failed / 153 passed at `59474a8` — in `tests/test_call_log.py`, `tests/test_main.py`, `tests/test_repl.py` and `tests/test_tier_config.py`. Confirm that baseline before changing anything.
- [x] After the fix, `uv run pytest` reports 0 failures with that same populated `.env` still present, and still 0 failures with no `.env` file at all (the CI-like case). Both runs must be checked. The fix must not require a developer to delete, rename, or empty their `.env`.
- [x] Isolation is automatic, not opt-in: a test does not have to remember to clear the environment, and a newly added test inherits the isolation for free. Clearing must happen before each test body runs, so no real secret can reach a pytest assertion diff even when a test fails.
- [x] Isolation covers every environment variable `model_router` reads: `TIER_EASY_MODEL`, `TIER_MEDIUM_MODEL`, `TIER_COMPLEX_MODEL`, `TIER_EASY_PROVIDER`, `TIER_MEDIUM_PROVIDER`, `TIER_COMPLEX_PROVIDER`, `OPENROUTER_API_KEY`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `ROUTER_BUDGET_USD`, and `ROUTER_LOG_PATH` (the existing `_isolate_router_log` autouse fixture must keep winning for the latter — order the fixtures so its `setenv` is not undone).
- [x] Guard against drift: prefer deriving the cleared set from the names `model_router` already declares (e.g. `tier_config`'s model/provider/API-key maps, `budget`'s and `call_log`'s constants) over a second hand-maintained list. A hardcoded list is acceptable only if a test fails when a new router env var escapes isolation.
- [x] Mechanism is the implementer's call (an autouse `conftest.py` fixture that snapshots and clears these vars, `tier_env` setting every `TIER_*_PROVIDER` it needs explicitly rather than leaning on the default fallback, or another approach) as long as the criteria above hold. Keep it simple; do not build a test-config framework.
- [x] Test-infrastructure change only. `model_router/cost.py`, `model_router/dotenv.py` and the `litellm` import stay as they are; no production behavior changes and no new dependency is added.
- [x] Do not weaken existing assertions to make them green. In particular `tests/test_tier_config.py`'s exact `api_keys` equality checks and `tests/test_main.py`'s missing-variable check are correct as written — the ambient environment was wrong, not the assertions.

**Validation:** `uv run pytest` twice — once with the populated repo-root `.env` present, once with it temporarily moved aside — both clean. Use no real API keys and make no paid calls.

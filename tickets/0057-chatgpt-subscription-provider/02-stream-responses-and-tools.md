# 02: Run streamed ChatGPT tasks and local Tools

**What to build:** A selected account model completes ordinary streamed tasks and Tool follow-ups through the existing Router, with explicit plan errors, correct input planning and no API fallback. This is the first inference checkpoint and validates the new wire protocol independently of durable cross-Run continuity.

**Blocked by:** 01 — Connect ChatGPT and explicitly select an account model.

**Spec:** [0057](../../docs/specs/0057-chatgpt-subscription-provider.md), D1, D2 admission, D4 dynamic secret protection, D5–D7 and D8 Attempt identity; **ADRs:** [0015](../../docs/adrs/0015-chatgpt-subscription-provider.md), [0002](../../docs/adrs/0002-hand-rolled-provider-contract.md).

**Areas:** ChatGPT Provider/registry, shared transport/error seam where necessary, Runtime Configuration/task admission, context budget, Router exchange/Tool loop, Call Log Attempt evidence and protocol tests. Keep OAuth implementation behind ticket 01's lifecycle interface. Durable Conversation changes belong to ticket 03.

- [ ] Every new task, Retry and manual Compression admits a usable account/model, captures immutable registration/session generation and capacity, and resolves current credentials for that pinned session. Current tasks/follow-ups do not retarget after another process changes accounts/settings. Missing authorization/model blocks without a browser or fallback.
- [ ] The Provider prepares complete Responses input and posts to the public `/v1/responses` with OAuth bearer, `store=false`, `stream=true`, instructions/developer context and allowed fields only. Omit unsupported preview fields, explicit system messages and remote continuation/storage; leave API-key OpenAI unchanged.
- [ ] Use D5's exact per-field provenance and configured budget/reserve/margin calculation, including complete prompt/Tool/input assessment. Missing capacity stays labeled assumed, not borrowed from a similar API model. ChatGPT omits `max_output_tokens` and identifies output reservation as an estimate without guaranteed remote cap; API Providers still enforce their existing output parameters.
- [ ] Consume bounded SSE with and without display callback/Content-Type. Assemble ordered items from deltas and item-done snapshots; retain items when completion output is empty and avoid double-appending duplicate snapshots. Stream only protected ordinary text. Correctly preserve reasoning/encrypted state, message phase, function IDs/namespace and measured first-text behavior.
- [ ] Only coherent completed output succeeds. Failed/error/incomplete terminal events, EOF/truncated UTF-8, inconsistent/malformed items, oversized event/aggregate and invalid Tool arguments do not execute provisional Tools or append a completed answer. Available valid usage remains evidence even after failure/interruption.
- [ ] Namespaced local Tool definitions/calls/results round-trip by `call_id`; unknown namespaces/names cannot alias allowed Tools. Existing schema validation, raw argument evidence, Agent Mode, confirmations, 16-call batch and Tool-round ceilings remain enforced. Existing built-in/MCP/resource/skill/job/question/agent functions use ordinary client execution, never unsupported hosted features.
- [ ] HTTP and SSE errors share correct classification, including HTTP-200 plan exhaustion/context overflow and nonstandard `detail` shapes. One physical Attempt produces one evidence/usage charge even for `error` followed by `response.failed`; preserve safe code/param/status/request ID.
- [ ] Plan exhaustion displays `Cota atingida`, stops further plan inference/Compression/child dispatch in that execution and preserves retryable work. Guidance gives Manage usage and explicit wait or select another Provider then Retry; no automatic waiting/fallback or invented reset. Permission, unsupported route/capability and policy failures are nonretryable; supported temporary failures retain bounded same-route backoff. Positive overflow follows the existing single strictly shrinking Compression recovery.
- [ ] ChatGPT Attempt evidence includes `chatgpt_plan`, opaque registration reference, observed input/output/cache/reasoning detail and independent unknown/invalid evidence; `cost=null`, `cost_estimated=false`, with no API-price lookup. API Attempt cost estimation/reporting remains unchanged. A minimal plan-safe footer/usage rendering must avoid displaying plan `$0` before ticket 05 adds the full presentation.
- [ ] Newly acquired/refreshed/retired tokens and auth-attempt secrets are protected before diagnostics, text callbacks and Tool results. Adversarial echo tests split a credential across stream chunks and cover errors, Call Log/detailed audit and model input. No token string is persisted as account attribution.
- [ ] Add synthetic contract fixtures for streamed text, parallel/sequential Tool results, unknown namespace, reasoning, empty terminal output, incomplete/failed after text, duplicate terminal usage, malformed/oversized frames and plan exhaustion after a Tool batch. Run focused Provider/streaming/Router/context/accounting tests and the full suite; current API Provider requests, cost/cache and prompt surfaces stay covered.

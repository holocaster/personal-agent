# 03: Preserve ChatGPT continuity through Retry, Resume, Fork and Compression

**What to build:** A ChatGPT Conversation resumes and forks with valid account-bound reasoning/Tool replay, while route/account changes keep portable text and safely retire incompatible opaque state. This is a separate durability checkpoint because replay and pending Tool effects must survive restart without cross-account leakage or duplicate execution.

**Blocked by:** 02 — Run streamed ChatGPT tasks and local Tools.

**Spec:** [0057](../../docs/specs/0057-chatgpt-subscription-provider.md), D2 route transitions, D7 explicit Retry, D8 and D10 assessment invalidation; **ADRs:** [0015](../../docs/adrs/0015-chatgpt-subscription-provider.md), [0005](../../docs/adrs/0005-call-log-is-the-conversation-record.md), [0013](../../docs/adrs/0013-fork-copies-into-a-new-session.md).

**Areas:** Provider replay hooks, Router completed/pending normalization/rebase, continuation validation, Call Log read/write/Resume, REPL Retry/Fork/Compression/clear/Undo and File recovery integration. Do not create another Conversation store or rewrite earlier Sessions.

- [ ] Extend Call Log v3 additively with access-method/opaque registration provenance on relevant Run/opening/Attempt/Turn End state. Represent unready startup honestly; task openings contain admitted routes. Existing v3 API Sessions and version-1 Gemini/API continuation still read unchanged; older Session formats remain refused before append.
- [ ] Persist validated versioned Responses replay with exact Provider/model/registration binding alongside normalized completed Conversation and pending prefix. Choose and document the concrete new ChatGPT continuation schema/version. Reject malformed/missing binding, bad consumed/history indices, unbalanced/uncorrelated call/result graphs or unsupported replay shape before Resume append; preserve strict Gemini validation.
- [ ] Same-model/same-registration requests replay ordered encrypted reasoning, message phase and namespaced calls/results using existing prepare/rebase seams. Refresh or later reauth to the same verified registration does not unnecessarily destroy compatible model state; credentials and identity claims never enter replay or normalized text.
- [ ] After failed/exhausted/interrupted work, explicit Retry retains original task ordinal and new execution identity, rebases on current older Conversation/Summary, restores Todos/fetched URLs and includes actual completed Tool outcomes. Partial batches explicitly identify interrupted/unexecuted calls. No Tool is repeated merely from replay/Resume and no provisional response is promoted into completed Conversation.
- [ ] Changing Provider/model/account drops incompatible opaque replay, preserves normalized Conversation/Summary/pending text and keeps the newly selected route explicit. Before sending retained text to a different ChatGPT registration, print the safe-account notice on task, Retry, Resume, Fork and Compression paths, including after restart; no extra approval or forced clear is added. Same-email/different-registration is still a change.
- [ ] Fork copies validated compatible replay/provenance and portable text into the child, retains parent linkage/empty spend and refuses pending work as today. Parent evidence is unchanged. Resume uses current admitted configuration rather than restoring an old credential/route automatically.
- [ ] Automatic/manual/overflow Compression use the same pinned route/account, complete supported context and existing reduction/ceiling rules; saved Summary retires compressed opaque items and correctly rebases the two retained turns. Compression output is internal. Clear/Undo/File recovery rebase or invalidate replay/pending state consistently with existing semantics and invalidate stale occupancy.
- [ ] Failed durable pending/replay/evidence writes halt further actions visibly. Redaction covers new fields and historical/rotated secret echoes; raw tokens/authorization URLs never appear in Call Log or detailed audit. Session logs/report readers tolerate the additive valid v3 fields without exposing private replay as ordinary visible answer text.
- [ ] Tests round-trip a real temporary Call Log through tool failure/exhaustion, Retry, restart/Resume, Fork, Compression, Undo/clear and recovery; cover same account reauth, API → ChatGPT → API and different ChatGPT registration. Check malformed replay rejection before append and unchanged legacy v3 Gemini/API paths. Run focused continuation/Call Log/Resume/Fork/Compression/recovery tests and the full suite.

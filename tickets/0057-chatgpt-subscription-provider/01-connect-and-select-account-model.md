# 01: Connect ChatGPT and explicitly select an account model

**What to build:** A user can open the REPL without a usable route, securely connect their own ChatGPT account, choose an account model and disconnect again without affecting an API route. This slice earns a separate checkpoint because authorization, persistence and route activation must be correct before any subscription inference is added.

**Blocked by:** None (can start immediately).

**Spec:** [0057](../../docs/specs/0057-chatgpt-subscription-provider.md), D1–D5 and D10 first-use/status obligations; **ADRs:** [0015](../../docs/adrs/0015-chatgpt-subscription-provider.md), [0011](../../docs/adrs/0011-direct-provider-model-selection.md), [0012](../../docs/adrs/0012-models-dev-selection-catalog.md).

**Areas:** `chatgpt_auth`, account model discovery, Runtime Configuration/readiness, startup, atomic configuration store, `InputBox`, REPL connect/disconnect/config/model/listing commands, dependency manifest/lock and focused tests. Do not add production inference here; an otherwise selected ChatGPT route must fail with a clear unavailable-inference diagnostic until ticket 02 supplies its Provider.

- [x] REPL entry works with missing/unknown route, missing key/session, denied model/catalog or unavailable Models.dev, while surfacing the reason. Fatal malformed context/resource settings and corrupt Session/persistence evidence remain fatal. No invalid route is dispatched or fabricated in Session metadata. API route checks retain their existing behavior at dispatch boundaries.
- [x] `/connect chatgpt` uses the official local browser/127.0.0.1 callback, fresh state/nonce/PKCE, stable host ID, app name, exact callback URI, scopes/resource, dynamic initial registration and issued-client code exchange from D3. Reauthorization reuses its saved registration; explicit different-account connection keeps distinct identity metadata without a saved-account picker. Returning identity mismatch cannot overwrite the earlier account.
- [x] ID tokens are cryptographically verified with trusted JWKS/algorithm policy, issuer, audience, expiry, subject and login nonce. Reject invalid signature/algorithm/issuer/audience/nonce, missing/duplicate/mismatched callback parameters, missing issued client and reused callback. State-validated access denial, cancellation, Ctrl-C/EOF and the five-minute deadline clean up the listener and preserve the earlier selection/connection.
- [x] Valid identity without direct-plan scope is retained as permission-disabled and cannot infer. An explicit enable-plan action can reauthorize with full scopes/supported consent; no routine forced-consent or OAuth loop. Missing permission/ineligible status offers clear own-API configuration guidance.
- [x] Global versioned credential storage is private, bounded, owner-checked, symlink-safe and atomic; no OAuth data enters dotenv or project settings. Declare `PyJWT[crypto]` directly, update the dependency lock and use existing prompt-toolkit/stdlib dependencies. Storage failures stop dependent work.
- [x] Valid-credential resolution pins opaque registration/session generation. Serialize refresh, activation and disconnect across processes, reread inside the lock and persist rotated tokens before use. Test two real processes racing refresh and disconnect so stale writes cannot resurrect or overwrite a new session. Validate refreshed identity and grant, honor supplied expiry, preserve temporary-failure credentials and clear terminally invalid tokens with reconnect guidance.
- [x] Disconnect attempts discovery-based trusted server revocation with issued client ID/refresh token, handles empty-200 idempotence and bounded temporary retries, clears local tokens and marks the generation unavailable. Unconfirmed remote revocation is visible with settings guidance. Retain host/registration metadata and API keys; selected ChatGPT becomes unready without fallback.
- [x] Account models come from OAuth `GET /v1/models`, `models[]`, visible exact slugs/display names in server order, with bounded/validated parsing and registration-generation isolation. Do not import remote instructions or admit ChatGPT via Models.dev. Missing public capacity allows labeled assumptions; undocumented account capacity is not verified evidence. Listing never performs inference.
- [x] After login the picker uses arrow keys, Enter and Escape, sanitizes remote text and requires deliberate selection. `/model chatgpt <slug>` offers connect-now before browser launch, then validates/confirms the exact model. Successful selection saves both settings atomically before activation. Login alone, cancellation, empty list, failed listing, invalid slug and failed save preserve the old route; successful sign-in survives picker/catalog failure with a clear remaining action.
- [x] Existing `/model`, `/models`, CLI model listing and `/config` expose the account path/status while API-key credentials coexist. The chosen route determines authentication. Refresh/listing failure does not hide other Providers or silently switch a route. No auth/status CLI is added. Noninteractive commands never open a browser/picker/modal or wait for setup; exact commands can reuse existing acknowledged authorization.
- [x] First permission-enabled login displays a dismissible plan-use notice with Continue with ChatGPT/Manage usage wording and usage destination; private acknowledgement prevents repeats on routine reauth. `/config` shows safe distinct account label and connection/permission/readiness, without secrets. Models/tasks cannot run before the first notice acknowledgement.
- [x] Tests use synthetic OAuth/JWKS/browser/model-list responses and temporary storage, including same email/different identity, unsafe permissions/links, failed atomic rotation and echo/redaction of newly issued/retired secrets. Run focused auth/entry/config/input/catalog tests and the full `.venv/bin/pytest -q` suite. No real account, credential inspection or live inference.

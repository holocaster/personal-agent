# 02: Evaluate and persist Session tier across commands and Resume

**What to build:** A fresh Session evaluates its first routed task on easy and keeps the chosen tier. `/model` changes that choice or requests a new evaluation. Exit/Resume, conversation editing, failures and cancellation preserve the confirmed Session-state rules, while all evaluator usage appears in Run spend.

**Blocked by:** 01 — Keep failed tasks on one route and display uncapped Run spend.

**Spec:** `docs/specs/0039-session-tier-selection.md`, R1–R13; Implementation Decisions: Session state and replay, Evaluator and ordinary Router, Spend and presentation; Testing Decisions. **ADRs:** `docs/adrs/0006-persist-session-tier-and-remove-escalation.md`, `docs/adrs/0005-call-log-is-the-conversation-record.md`.

- [x] **AC1 — R1, R2, R12:** Add evaluation through the configured easy route using only fixed rubric/current task, no Tools/replay/context injection, and the existing bounded route output allowance subject to capacity constraints (including reasoning tokens where applicable). Accept only exact lowercase tier text after surrounding whitespace removal; reject malformed/truncated/Tool-bearing responses. Evaluation and the following ordinary task share a configuration snapshot; the Router receives an explicit Tier. Delete heuristic Classifier and its obsolete tests/callers.
- [x] **AC2 — R3, R4:** Reuse existing transient retry behavior; exhaustion, non-retryable error, local evaluator preparation/input failure and invalid output select medium with a warning (invalid output gets no retry). Cancellation during preparation, dispatch or backoff leaves pending state, writes the normal interrupted Turn End, and sends no ordinary task. Audit/Attempt/persistence errors propagate fatally, never become fallback.
- [x] **AC3 — R5, R6:** `/model <tier>` immediately selects and persists the state, bypassing pending evaluation; `/model auto` immediately persists pending state and evaluates exactly once on the next routed task. No-argument `/model` reports selected/pending; invalid input changes nothing. Clear, Undo, Retry, Compression and mode changes retain that state. Local commands never trigger evaluation; available `/retry` uses its routed task. Retain Run-local retry availability.
- [x] **AC4 — R6, R7, R11:** Extend the existing Call Log replay/CLI Resume path using the spec's explicit `session_start.session_tier` and `session_tier_changed` schema. Restore the latest state independently of Conversation replay, including a manual change then immediate exit, pending auto then exit, automatic selection followed by ordinary failure, and fresh exit before any task. Valid legacy logs with no state warn, select/persist medium and never evaluate automatically. Ignore old Attempts/command audits for selection; malformed new state errors instead of falling back.
- [x] **AC5 — R4, R11:** Persist transitions before live mutation or ordinary dispatch. Use existing append restoration for observable partial writes; failed state persistence stops the Run with no ordinary call. Preserve CLI exit 1 and fatal error without traceback for evaluator Attempt/detail writes and tier-state failures, including failed prefix restoration. Do not turn write failures into provider fallback or continue accepting commands.
- [x] **AC6 — R9, R10:** Evaluator Attempts and enabled detail are marked `purpose: "tier_selection"` and use shared retries, redaction, accounting and diagnostic paths. Charge all reported evaluator costs once, including retries and invalid outputs; preserve unknown usage/Estimated Cost. No evaluator messages enter Conversation, no extra successful Turn End is added, and evaluator assessment never overwrites ordinary `/usage` context information. Resume still resets spend.
- [x] **AC7 — R8, R12:** Later tasks on selected state make no evaluator call. Configuration edits retain tier but use current mappings on later tasks; Compression stays on easy and keeps selected/pending state. Ordinary retries, overflow recovery and Tools never switch tiers automatically; all mandatory context and existing safety checks remain.
- [x] **AC8 — R13:** In interactive and piped output, announce automatic selection or fallback and `/model` guidance. Footer and `/model` expose selected/pending state even before an answer and after Resume/manual changes. Keep ordinary `/usage` assessment semantics and total spend. Update concise README behavior, CLAUDE.md identity and CONTEXT.md terminology/decisions (Session tier/evaluator replacing Classifier/Tier Pin, no Escalation/Budget Guardrail) when this slice lands.
- [x] **AC9:** Add behavior tests through existing REPL/CLI, temporary-log and scripted Provider seams covering the complete Testing Decisions matrix. Verify payload isolation, call counts/routes, replay, warning/error output, accounting and fatal persistence paths.

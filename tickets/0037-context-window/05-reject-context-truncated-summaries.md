# 05: Reject context-truncated summaries without changing Conversation

**What to build:** An unfinished Anthropic summary must fail Compression rather than replace older conversation. Manual `/compress`, preventive Compression and context-overflow recovery retain the prior live/replayed Conversation and surface the failure without sending the pending exchange or repeating Tools. This corrects an existing R6 violation, not a new product decision.

**Blocked by:** 04 — Recover one rejected exchange and verify final observability (`0037/04`). No other direct blocker.

**Spec:** `docs/specs/0037-context-window.md` (R6 context-truncated construction; R7-R10 failure preservation, recovery and notices; R11 existing costs; Implementation Decisions: Compression/replay/persistence; Testing Decisions: review-discovered R6 correction). **ADRs:** ADR-0002, ADR-0005. **Evidence:** `docs/briefs/0037-context-window.md` (Review-discovered correction); `tickets/0037-context-window/04-recover-rejected-exchanges.review.md` (Out-of-scope finding).

The review reproduced manual Compression accepting non-empty Anthropic output stopped with `model_context_window_exceeded`, printing success and writing `conversation_compressed`. The Anthropic Provider already passes `stop_reason` into `AssistantMessage.termination`; `AssistantMessage.truncated` omits this value, and the Router's shared `compress()` only rejects recognized truncation. Fix that existing classification/validation path once, not separate manual/automatic guards. Do not edit tickets 01-04 or their reviews, change ordinary routed-answer policy, widen HTTP overflow classification, add retries/dependencies/Call Log schemas, or address the unrelated known Gemini accounting issue.

- [x] **AC1 — Termination contract and shared validation.** Recognize Anthropic `model_context_window_exceeded` as truncated via the existing Provider Contract and reject it in shared Compression validation at every block and combination response, even when its text is non-empty, reducing and otherwise fits. Surface a clear unfinished/truncated-summary error before commit; a generation stop is not a rejected request to recursively recover. Preserve existing length/max-token classifications and acceptance of complete Anthropic `end_turn` summaries. Test the real Anthropic response translation rather than manufacturing a `truncated` property.
- [x] **AC2 — Manual transaction preservation.** Add Provider-to-REPL regressions using Anthropic-shaped fake HTTP responses for truncation on the first block, a later block after earlier successful summaries, and a combination response. No new `conversation_compressed`, Compression success notice, routed Turn End or continuation task may be produced; partial summaries never replace state. Verify the failing request is a tools-free easy-route summarization and no further summary request is sent after the invalid response.

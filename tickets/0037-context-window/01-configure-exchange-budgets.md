# 01: Configure and enforce complete exchange budgets

**What to build:** A user sets a persistent total Context Budget and exact route capacity overrides through `/config`; every normal exchange receives an explicit output cap and complete local input check. All retained history is available, with visible stops instead of the 20-turn omission, and `/usage` explains configured versus effective limits and estimates. This is a usable safety checkpoint before preventive Compression is added.

**Blocked by:** None (can start immediately).

**Spec:** `docs/specs/0037-context-window.md` (R1, R2, R3, R4, R7 local-stop behavior, R10 legacy-path removal, R11; Implementation Decisions: Configuration and metadata, Exchange measurement and Provider Contract; Testing Decisions). **ADRs:** ADR-0001, ADR-0002, ADR-0005.

- [x] Extend Runtime Configuration with `context_budget_tokens` (default 250000) and copied exact-identity `capacity_overrides`. Load `PA_CONTEXT_BUDGET_TOKENS` and the JSON-array `PA_CONTEXT_CAPACITY_OVERRIDES` using the spec's validation and existing environment/home-store precedence. Extend `/config` with `context` budget/override set/remove actions, source notices, safe Audit Events and atomic persistence. Invalid, cancelled and failed writes change neither active nor saved settings. Empty-array/reset, two tiers sharing a route, changing Provider/model, inactive overrides and unrelated model/key edits preserve the right settings. Capture a full immutable task snapshot for all Tool follow-ups and easy-route calls; Resume uses current configuration. Do not edit orchestrator-owned context/state documents.
- [x] Replace the scalar context-limit assumption with explicit total/input/output limits and provenance from `get_model_info()` plus manual records. Document the normalized metadata field semantics in the implementation's tests/reference notes; never infer total from `max_input_tokens`, ambiguous `max_tokens`, or sum of independent maxima. Keep OpenRouter model-wide bounds distinct from unknown upstream capacity; unknown total uses visibly assumed 128000 and preserves smaller valid ceilings. Reject booleans, non-positive/non-integer metadata and invalid override records. No new remote catalog, upstream pinning or SDK; LiteLLM's local token counting is authorized by amended ADR-0002, but its completion/routing/auth/retry surfaces remain excluded.
- [x] Implement the R3 formulas with integer-safe boundaries: effective total, up-to-16000 output reserve, 10000 margin and separate input restriction. Prove 250000 → 224000 and assumed 128000 → 102000 input ceilings, plus smaller total/output/input limits and non-positive resulting ceiling. Extend the hand-rolled Provider Contract with explicit output allowance and response termination information. Capture REST payloads for OpenRouter, OpenAI, Anthropic and Gemini, including no-Tools and Compression calls; enforce the output cap on the wire, not by prompting. Verify current primary REST documentation for shared/separate reasoning allowances, especially Gemini, and attach source/evidence to the implementation handoff. Never treat an effort level as a bounded reasoning-token count or send an unbounded request when a cap cannot be supported. Keep REST dispatch hand-rolled per ADR-0002.
- [x] Reuse each Provider's pure prepared model-facing input in estimation and dispatch. Feed a deterministic, strictly validated Unicode JSON rendering of that complete input to the installed `litellm.token_counter(model=tokenizer_model, text=rendered_input)`; count tokens, not UTF-8 bytes or characters/4. Include System Prompt/Memory/Summary/Todos/Skills, all retained history, task, every Tool schema field/call id/name/argument/result and actual Gemini replay exactly once. Exclude credentials/headers and transport/output controls. Do not feed arbitrary wire dictionaries to the structured counter or pass `tools`/`messages` with `text`: unsupported fields can be ignored and text/tools is rejected. Known-model encoding selection and generic fallback follow the verified library behavior in the spec; keep tokenizer aliases separate from route capacity. `/usage` labels the estimate approximate, names its encoding and explicitly identifies generic fallback, never exact Provider usage or a guaranteed upper bound. Test Unicode/code, full schemas, malformed arguments, grouping, generated ids and opaque signatures against the rendered and dispatched input.
- [x] Initialize counting with local bundled/cached assets only: prevent import-time remote cost-map refresh, disable HF tokenizer downloads and handle tiktoken asset/cache behavior, including `CUSTOM_TIKTOKEN_CACHE_DIR`. HF-disable alone is not a no-network guarantee. Missing/corrupt assets may use a valid local library generic fallback with an honest approximate label; if no local tokenizer is usable, or rendering/counting fails, stops visibly before Provider dispatch. Reject disabled-counter zero, invalid/non-positive counts for non-empty input and fabricated `default_token_count` values. Preserve prior state/Tool evidence and blocked-exchange diagnostics; no fake Provider Attempt. No paid counting requests, implicit tokenizer downloads, new dependencies or byte/character proxy fallback. Use the existing locked LiteLLM 1.102.0, tiktoken 0.14.0 and tokenizers 0.23.2; no lockfile/version change for this feature.
- [x] Remove the fixed `HISTORY_WINDOW` omission and pass complete-turn structure to routing while retaining existing normalization and successful/error Turn End meanings. Gate every dispatch (initial, transient retry, Tool follow-up, Escalation and existing manual Compression call) at its actual route ceiling. In this slice an over-ceiling ordinary exchange stops visibly; automatic safe reduction is ticket 03. Do not escalate because a local budget check fails. Preserve already written Tool execution evidence and do not rerun/re-confirm Tools on a blocked follow-up. Remove the legacy post-success usage-triggered Compression and synthetic Continuation Turn path now; ticket 03 supplies replacement prevention, not another post-success hook.
- [x] Extend `/usage` to R11's configured/task-snapshot budgets, route/capacity provenance, input ceiling/output reserve, estimated versus reported input, outcome and actual retained/sent turns. Handle no assessed task, unknown usage, local rejection, Provider failure and subsequent `/config` without stale last-success counters. Internal Compression does not replace the ordinary-task diagnostic. Normalize all context-occupying reported input, including Anthropic cache counts where separate, without subtracting OpenRouter cached tokens or double-counting an inclusive prompt total. Preserve existing cost/completion semantics; no Status Footer expansion.
- [x] Add scripted interactive `/config` and piped REPL/HTTP tests using temporary home/Call Log, metadata fixtures and harmless Tools. Isolate both new environment variables and tokenizer settings. Use supplied token-estimate fixtures for exact budget boundaries, not byte lengths; separately run a real locked-LiteLLM contract test with network access forbidden and bundled assets. Verify recognized/generic encodings and labels, repeatable counts distinct from byte length, complete constituent coverage and local asset/counting failure behavior (including custom cache, disabled/zero/invalid counts). Use more than 20 small turns to prove all retained turns are sent below budget; use a large task/Skill/Tool result to prove no unchecked request or silent cut. Inspect explicit caps and prepared input across Providers, missing metadata and changed Escalation routes. Update only obsolete fixed-window/post-success-Continuation assertions, retaining unrelated behavior. Run focused runtime-config/Provider/routing/REPL/audit tests and `uv run --offline pytest -q`; record counts, no-network counting evidence and any documentation-proven cap constraints in the handoff.

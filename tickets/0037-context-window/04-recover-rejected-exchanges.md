# 04: Recover one rejected exchange and verify final observability

**What to build:** If a Provider positively rejects one request for context overflow despite local prevention, Personal Agent safely reduces older context and retries that same exchange once. Already executed Tools are never rerun; an impossible reduction, second rejection or other retry failure is visible. Final user documentation and usage tests explain the complete budgeting behavior and its assumptions.

**Blocked by:** 03 — Compress preventively without losing pending Tool exchanges (`0037/03`).

**Spec:** `docs/specs/0037-context-window.md` (R4 recovery measurement, R8, R7 recovery preservation, R9 retry/commit order, R11 failure observability and costs; all requirements for final feature validation; Implementation Decisions: HTTP evidence, Compression/replay/persistence; Testing Decisions and Further Notes). **ADRs:** ADR-0001, ADR-0002 (feature 0037 amendment), ADR-0005.

- [x] Add narrow positive context-overflow classification at each Provider seam using documented vendor code/type or specific context/input-limit message fixtures. Detect overflow mentioning Tool tokens before the existing broad unsupported-Tools classifier, without mislabeling true Tool-support errors. Test OpenAI, OpenRouter (including nested upstream evidence), Anthropic and Gemini. No new calling library, remote discovery or content-based Escalation.

Second rejection, no eligible/safe reduction, summarization error or an unrelated failure of the recovery retry surfaces the error without another recovery/transient/Escalation cycle. A later distinct Tool follow-up has its own logical exchange allowance; summarization overflow surfaces directly, never invokes recursive recovery.

# 06: Use published input limits as capacity and make soft-trigger Compression optional

**What to build:** Routes without a manual override get their real known capacity instead of `unknown; assumed 128000`, so the 250000 default takes effect (Claude 200000, gpt-5 and Gemini at the full 250000). Above the 80% soft trigger, a Conversation with only a previous summary and the two protected turns is sent unchanged while it fits the mandatory ceiling. A failed soft-trigger Compression is reported but no longer blocks a pending exchange that fits. Correction of two defects found after the approved whole-feature review (brief settled decisions 13-15); not a new product decision.

**Blocked by:** 05 — Reject context-truncated summaries without changing Conversation (`0037/05`). No other direct blocker.

**Spec:** `docs/specs/0037-context-window.md` (R2 published input limit as known total; R3 worked values; R5 soft-trigger eligibility and soft-failure rule; R6 failure exception; R10 failure notice; R11 capacity display; Implementation Decisions: Configuration and metadata, preventive gate bullet; Testing Decisions: 0037/06 bullet; Further Notes: 0037/06). **ADRs:** ADR-0001, ADR-0002, ADR-0005. **Evidence:** `docs/briefs/0037-context-window.md` (Whole-feature review correction (0037/06)); `tickets/0037-context-window/feature.review.md`.

Keep the diff small: change only the context-budgeting capability's limit resolution and the Router's existing preventive gate in ordinary exchange execution. Add no dependency, abstraction, configuration, interface, persistence schema or Call Log event. Do not edit tickets 01-05 or their reviews. Keep R8 recovery, the mandatory ceiling stop, the transactional commit, R6 summary validation (including 05's context-truncated rejection) and manual `/compress` unchanged.

Before the fix, using real LiteLLM metadata with no override, `resolve()` returns total 128000 `unknown; assumed` and ceiling 102000 for Anthropic `claude-sonnet-4-5` (published input 200000), OpenAI `gpt-5` (272000), Gemini `gemini-2.5-pro` (1048576) and OpenRouter `anthropic/claude-sonnet-4.5` (200000). This is because published metadata never sets the total. Every existing preventive test injects a `total_tokens` override, which hid this defect. Separately, a Conversation with only a summary and two protected turns at an estimated 210000 (effective 250000, ceiling 224000) whose easy-route summary does not reduce input stops as `Context budget blocked: ... Compression failed: the summaries did not make measured progress`, after one paid call and with no answer.

- [x] **AC1 — Published input limit as known total.** When neither a total override nor a published total exists, a valid published `max_input_tokens` becomes the resolved total, for every Provider. Its source label is that metadata's existing scope (`published`, or `published model-wide` on OpenRouter), and it stays the separate input limit. Manual totals still win. Booleans, non-integers and non-positive values still give no limit. `max_tokens` never counts as total. Input and output maxima are never summed. `unknown; assumed 128000` remains only when no override, published total or valid published input exists. R3 arithmetic is otherwise unchanged. `/usage` shows the resolved capacity with its label through the existing rendering.
- [x] **AC2 — Real-metadata resolution.** Add a `resolve()` test using the locked, bundled LiteLLM metadata, with no override and no `model_info` stub, and network access forbidden as in the existing real-library tests. It must show:
  - Anthropic `claude-sonnet-4-5`: total 200000 `published`, effective 200000, reserve 16000, ceiling 174000.
  - OpenRouter `anthropic/claude-sonnet-4.5`: the same values, labeled `published model-wide`.
  - OpenAI `gpt-5` and Gemini `gemini-2.5-pro`: effective 250000, ceiling 224000.
  - None of these routes is `unknown; assumed`.

  Update the fixture cases that encoded the superseded rule, for example input-only 90000 metadata and the OpenRouter model-wide bounds test, to the new expected values. Keep the missing/invalid-metadata cases at 128000/102000 `unknown; assumed`.
- [x] **AC3 — Soft trigger requires eligible older turns.** The soft trigger (`estimated_input >= floor(0.8 * E)` while input is within `I`) fires only when completed turns older than the latest two exist. A previous summary with no further eligible complete turns is reduced only when input exceeds `I` or during overflow recovery. Whenever Compression runs, the previous summary is still included. Tests at the scripted `run_repl` seam with injected estimates (effective 250000, ceiling 224000):
  - A summary-only Conversation at 210000 sends the pending exchange with no summarization call, no Compression notice and no `conversation_compressed`.
  - A summary-only Conversation above 224000 still reduces the previous summary, commits once and sends.
  - Summary-only overflow recovery still reduces.

  Update `test_previous_summary_is_eligible_without_older_complete_turns`, which currently uses the soft-trigger 200000 estimate, so it keeps its summary-coverage assertions above the ceiling. Do not delete it.
- [x] **AC4 — Soft-trigger failure proceeds.** When Compression was started only by the soft trigger (input within `I`, outside recovery) and fails before commit, show a visible notice that includes the redacted reason and says the prior Conversation is retained and the pending exchange is being sent. Before-commit failures are summarization Attempt failure, summary validation failure (empty, length- or context-truncated, malformed, non-reducing), candidate measurement failure, or the candidate not reducing or fitting. After the notice:
  - Commit nothing and send the unchanged, already measured system, input, replay and estimate.
  - Keep the original estimate in the assessment.
  - Record the request as already reduced/attempted, so a transient retry of the same unchanged request does not rerun Compression.

  Interruption, detailed-audit failure and Call Log persistence failure (including a failed or partial final-summary append) keep their existing stop/fatal behavior. Required tests:
  - Eligible older turns at 210000 with a failing (non-reducing) summary: notice, no commit, pending exchange sent and answered. Live `/history` and `load_conversation` are unchanged except for the new successful turn. The summary Attempt is logged and charged once.
  - A transient retry after a soft failure sends exactly one summarization request.
  - A Tool follow-up soft failure sends the follow-up with Tool evidence logged once and no Tool rerun.

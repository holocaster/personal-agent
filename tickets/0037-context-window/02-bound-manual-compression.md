# 02: Make manual Compression bounded and transactional

**What to build:** `/compress` summarizes older conversation even when it exceeds the easy route's capacity, using fitting blocks and bounded combination exchanges. The user sees one successful final replacement or an error with the original Conversation intact, and Resume reproduces that result. This manual checkpoint earns separate review of summarization cost and persistence before automatic use.

**Blocked by:** 01 — Configure and enforce complete exchange budgets (`0037/01`).

**Spec:** `docs/specs/0037-context-window.md` (R3 summarization reservation, R4 shared local token counting, R6, R9, R10 manual action, R11 cost accounting; Implementation Decisions: Exchange measurement and Provider Contract, Compression/replay/persistence; Testing Decisions). **ADRs:** ADR-0002 (feature 0037 amendment), ADR-0003, ADR-0005.

- [x] Replace the one unbounded easy-route Compression request with ordered, budget-fitting rendered blocks from every eligible complete turn and previous summary. Retain the latest two complete turns; previous summary is eligible older context even with no new eligible turns. Cover every source part, including a single oversized old turn/result or previous summary, through contiguous labeled summarization pieces. Preserve association of Tool names/ids/arguments/results and chronological order; these blocks are data, never replayed Tool messages or executed Tools. Active Skills/Todos are not newly inserted into summaries; measure existing Memory/instruction overhead. If even fixed summarization overhead cannot fit, fail visibly before dispatch.
- [x] Summarize each block and combine fitting groups until one complete reduced candidate remains, applying ticket 01's easy-route limits, same local LiteLLM token estimator, explicit output caps/margin and truncation status to every exchange. Count the complete prepared summarization input, including instruction/Memory and labeled source pieces, using that route's local encoding or labeled generic fallback, never byte lengths or a separate proxy estimator. A tokenizer/counting failure stops construction visibly and retains the old Conversation; no paid counting or implicit asset download. Bound smaller output caps consistently with available final-summary space; never send concatenated summaries unchecked or slice a summary into success. Require strict measured reduction at combination levels and fail on empty, malformed, length-truncated, non-reducing or unfittable results. Do not recurse into preventive Compression or Escalation for summarization. Prepare a reusable candidate-building path that ticket 03 can validate against a pending ordinary exchange before commit, not a separate automatic summarizer.
- [x] Keep all partial results in staging, with unchanged live turns/summary/Todo baseline until full success. Every paid summarization/transient-retry Attempt logs and contributes to normal spend/Budget Guardrail, using task-snapshot easy-route configuration, no Tools and no routed Turn End. Interruption or failure in a later block/combination retains the old Conversation and emits no `conversation_compressed` entry. Check previous/active key redaction and detailed-audit fail-closed behavior, including no subsequent exchange after fatal audit failure.
- [x] Centralize the final commit for both manual and future automatic callers: precompute retained turns/new Todo baseline, append one existing final-summary `conversation_compressed` event under the Call Log's safe append operation, then apply matching live state. Preserve the existing event shape and `log_version: 2` two-turn reader semantics. An observable partial append failure restores the valid pre-append log prefix before surfacing failure; a failed restoration halts fatally rather than continuing. Do not mutate or print success before durable commit, create a separate Conversation file, or claim crash-proof storage. Ensure no fallible audit write sits between successful main commit and state application.
- [x] Manual `/compress` shows existing-style success/error/nothing-eligible output, never starts a task afterward, and leaves Tool evidence, Todo state, Undo and Clear semantics unchanged. `/usage` still refers to the latest ordinary task, with accumulated Compression cost included. Resume after failed/successful multi-block construction yields exactly the corresponding live Conversation and Todo baseline.
- [x] Test via scripted `run_repl`, actual fake HTTP payloads and `load_conversation`: small easy capacity versus large older context, multiple blocks and combination levels, single oversized old turn, oversized previous summary, previous-summary-only reduction, full source coverage and fitting requests. Use token-estimate fixtures for deterministic fitting boundaries plus real local LiteLLM coverage of complete summarization inputs with network forbidden. Inject tokenizer/counting failure in a later block/combination as well as middle/final exchange errors, no progress, empty/truncated responses, interruption, append-before-write/partial-write failure and failed restoration. Assert no unchecked exchange/download/counting request, no partial commit, exactly one successful event, no extra Turn End or task, all Attempt costs and matching replay/Undo/Clear. Run focused Compression/Call Log/Provider/detailed-audit tests and the full offline suite; record evidence.

# 01: Load recursive project instructions for ordinary task executions

**What to build:** An ordinary CLI task automatically receives root AGENTS.md or fallback CLAUDE.md, including bounded recursive imports of arbitrary UTF-8 text files. Loaded sources are visible, changes apply on the next task/Retry, malformed graphs stop before model calls and remain repairable, and complete instructions survive Tool exchanges and Compression under the existing Context Budget.

**Blocked by:** None within this feature. Begin implementation only after independent review of feature 0048's traversal fix passes.

**Spec:** `docs/specs/0049-project-instructions.md`, Implementation Decisions R1–R9 and Testing Decisions. **ADRs:** ADR-0005 (Call Log/Resume), ADR-0007 (accepted submissions and Retry).

- [x] R1: Supply one immutable loader result from an explicit Workspace Root. Prefer root AGENTS.md; use CLAUDE.md only when it is absent; both absent works; invalid existing AGENTS.md never silently falls back. Main opts REPL into loading, while omitted REPL/Router arguments preserve existing direct-call behavior without loading stale global workspace state.
- [x] R2: Expand bare, literal bracketed `[@Narquia.md]` and single/double quoted references, including spaces and arbitrary UTF-8 extensionless/non-Markdown filenames. Implement/document the exact token boundaries, quoting and malformed-form behavior. Preserve emails and supported inline/fenced code literally.
- [x] R3: Resolve recursively from each containing source's parent, accepting in-root parent paths and rejecting absolute/URI paths, escapes, excluded named/resolved targets, missing/inaccessible files, directories/special files, invalid UTF-8 and NUL. Perform bounded reads and enforce all fixed byte/file/depth bounds with complete failure rather than truncation. Never evaluate path text or loosen Workspace Tool rules.
- [x] R4: Include sources depth-first in reference order with surrounding text preserved and provenance attached. Canonical aliases/repeated completed imports contribute once; active-chain cycles fail clearly. Print sanitized source paths/diagnostics without file contents.
- [x] R5: Invalid startup/Resume graphs stop startup with zero Provider calls. Reload before each new task and explicit Retry; the immutable successful snapshot stays fixed across transient Attempts, Tools, mode switches, Compression and recovery. Root-file selection updates on later loads.
- [x] R6: A mid-Run reload failure blocks evaluator/ordinary calls, leaves the REPL usable and makes repair plus Retry work immediately and after Resume. Keep accepted-task count/input, ordinal/digest, due evaluation and existing pending prefix/replay/Todo/fetched-content attribution; Retry never duplicates submission input. Preserve fatal persistence behavior and version-1 continuation/schema compatibility.
- [x] R7: Every ordinary prepared request includes full lower-priority instructions. Explicit user requests and existing Agent Mode/Tool Registry/confirmation/workspace enforcement retain precedence; instruction text cannot authorize capabilities. Preserve Skills, Memory and existing Provider behavior.
- [x] R8: Count full instructions and provenance/wrapper in ordinary input, protected baseline and candidate estimates; retain them after Compression/recovery and stop visibly when protected input cannot fit. Evaluator and manual/preventive summary calls and their estimates omit project instructions.
- [x] R9: Keep implementation within the existing loader, main/REPL and Router seams using stdlib and no new settings/dependency/framework. Add concise README syntax, bounds, reload and failure guidance. Respect no unsolicited code comments and no commit/push authorization.
- [x] Add focused behavioral loader and fake-Provider integration checks described in Testing Decisions, including the exact root `CLAUDE.md` containing only `[@Narquia.md]`, recursive source-relative imports, confined/bounded failures, source sanitization, per-execution snapshot, repaired Retry/Resume and protected/auxiliary budget separation. Validate increments, then run existing affected tests, full suite and required repository checks.

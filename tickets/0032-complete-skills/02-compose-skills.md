# 02: Compose multiple skills manually and on demand

**What to build:** A user can keep several effective skills active in one Run and remove one or all; the model can load several effective skills in one `skill` Tool call without changing that Run state. Both paths include global and workspace skills and remain bounded and compatible with single-name use.

**Blocked by:** 01 (effective catalog/provenance and safe two-root resolution must exist before composing selections).

**Spec:** `docs/specs/0032-complete-skills.md` (R2–R7, Implementation/Testing Decisions); **ADRs:** ADR-0005 (Resume and Call Log).

- [x] `/skill <name>` adds an effective validated snapshot in activation order; re-adding an active name is a no-op without reload/reordering, including after a file edit. `/skill off <name>` removes just the active name, `/skill off` clears all. Wrong arguments, missing/invalid skills or unknown off-name report local errors without mutating the set. `/skills` marks every active skill and reports an active snapshot even when absent from the live catalog. `/help` and interactive completion expose command usage; piped input works too.
- [x] Every routed System Prompt carries all active snapshots labeled by name and origin in activation order, including follow-ups, local retries and Escalation. `/clear`, `/undo`, `/retry`, `/compress`, `/mode` and `/model` retain the active set in this Run; Compression's summary request carries none, Continuation Turns use current set, and Resume starts with no active skill even though Conversation/Tool results replay. Skill content cannot change mode, Tool Registry, Workspace Root or confirmation.
- [x] Extend the single existing `skill` Tool schema to accept exactly one of `name` or `names` (nonempty unique ordered list, at most four). Preserve old `name` result verbatim. `names` returns a single `{ "skills": [{ "name": ..., "instructions": ... }, ...] }` in request order, including a one-entry list. Validate every name against the advertised effective catalog, re-read it safely and reject any invalid, changed, missing, newly shadowed or over-32-KiB combined result atomically, as one normal Tool error with no partial instructions. Result enters the Conversation/Call Log, never the manually active set.
- [x] Extend offline scripted REPL/Provider tests for activation order, snapshot idempotence, selective/all off, failure preservation, both input modes, prompts across routing/Resume, old and new Tool schemas/results in plan/build, multi-result bounds and atomic errors, symlink/root safety, and plan denial/build confirmation even with hostile instructions. Run the offline suite.

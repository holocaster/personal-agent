# 02: Trace enabled Runs and Provider Attempts with fail-closed writes

**What to build:** A user starts or Resumes with `PA_DETAILED_AUDIT=1` and can correlate each Attempt with what was sent to the Provider and what came back. Enabled and disabled Runs are distinguishable; if the trace cannot be written, visible failure stops further work while the main Call Log still Resumes.

**Blocked by:** 01 — Audit local decisions in the Call Log (reuse its safe events, command and Tool decision seams for fatal-write ordering).

**Spec:** `docs/specs/0036-auditoria.md` (R3–R7, Implementation/Testing Decisions); **ADRs:** ADR-0003 (per-Session location), ADR-0005 (Call Log replay).

- [x] Accept only unset/`0`/`1` for `PA_DETAILED_AUDIT` at Run startup; invalid values fail before starting. Main Call Log has linked `audit_coverage_start`/`audit_coverage_end` and a fresh `run_id` per Run, including disabled Runs. Enabled Runs append matching `run_start`/`run_end` to an owner-only non-symlink companion path derived from their Call Log; disabled Runs neither append there nor need it to Resume. Old Call Logs have unknown, not asserted, coverage. Incomplete or mixed enabled/disabled Runs are discernible; disabled→enabled and enabled→disabled Resume retain identical Conversation/Spend behavior.
- [x] Every enabled Provider exchange, including each retry, Escalation, follow-up and manual/automatic Compression, writes a pre-call `attempt_start` with the exact System Prompt, ordered messages, offered Tool definitions or empty set, model/tier/provider and relevant model-facing replay data, with known keys recursively replaced in user-controlled/external data. Preserve structural schema fields and fixed controlled values even when equal to a known key; redact credentials in dynamic dictionary keys and values inside Tool arguments and detailed payloads. Its Call Log Attempt gains a unique `attempt_id`; the detailed `attempt_end` is linked to it and carries normalized answer/Tool calls or a caught redacted error. Do not log HTTP headers, raw vendor bodies or new billing requests. A crash/interruption may leave only `attempt_start`; do not invent an answer.
- [x] Enabled local `/remember` content, when needed to understand that submitted action, appears only in the restricted companion record, linked to `run_id` and redacted for known keys; `/config` secret prompt/typed keys never appear even there. Reuse known-key redaction for detailed nested messages, Memory/Skills in System Prompt, Tool definitions, follow-up replay and results. Fix the existing Router redaction regression in Call Log Tool arguments as part of this slice: model-supplied dynamic dictionary keys containing a known key must be redacted too, without changing structural fields or controlled values, and without changing the underlying Conversation/Resume payload merely to sanitize an Audit Event. Unknown private text is explicitly not guaranteed to be detected.
- [x] Write a safe companion `action_start` with unique `action_id` before each submitted REPL Command and requested Tool (including invalid, read-only and auto-approved calls), linking it to its main Call Log Audit Event/`tool_execution` outcome; no success is invented if the process stops. Before further auditable action, failure opening/protecting/writing/flushing the companion (including start, intent, outcome and end) shows a fatal audit error, stops the Run without Provider retry, next Tool, next REPL command or false successful Turn End; preserves a readable main Call Log. On enabled Resume, reject an existing malformed auxiliary tail rather than silently joining JSON to it; disabled Resume still works. Show that a result-write failure may leave an already performed effect with no recorded success and that missing markers expose incompleteness; use fault injection at startup, Attempt, local command/Tool and shutdown boundaries.
- [x] Update `README.md` and `docs/ENV_VARS.md` to describe flag, exact derived path including `PA_LOG_PATH`, JSONL record types/links, local access and sensitivity, partial coverage and shared operator-controlled retention (no automatic pruning). Offline end-to-end tests compare detailed inputs to fake Provider inputs across retries, Tool rounds and Compression; check file permissions, refusal of unsafe existing file, no leakage of known current/replaced keys (including in dynamic Tool-argument and detailed-payload dictionary keys), fixed outcome/mode values and schema fields retained under collisions, bounded/rejected/failed/nonzero `shell` observation and normal Call Log replay. Run the full offline test suite.

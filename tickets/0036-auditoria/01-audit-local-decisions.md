# 01: Audit local decisions in the Call Log

**What to build:** An ordinary, untraced Run writes compact local-command and Tool Confirmation Audit Events to its existing Call Log, without changing how that file rebuilds the Conversation. This ticket is independently useful: it makes local choices auditable without enabling detailed payloads.

**Blocked by:** None (can start immediately).

**Spec:** `docs/specs/0036-auditoria.md` (R1, R2, R5 safe-event fields, R7 compatibility; Implementation/Testing Decisions); **ADRs:** ADR-0003 (Call Log location), ADR-0005 (Resume replay contract).

- [x] Every submitted slash REPL Command, including unknown, invalid, read-only, cancelled and failed forms, records its name, safe arguments/omission and accurate outcome in an `audit_event`; no extra Provider Attempt. `/mode`, `/model`, `/config`, `/skill`, `/remember`, `/forget` and interactive Shift+Tab log actual old/new non-secret state for successful transitions, no false change on failures. `/config` sub-menu accepted/rejected settings are distinguishable without hidden key material; `/remember` text and forgotten Memory Note text never appear in the new always-on event. Do not persist raw command lines first and attempt to mask them afterward.
- [x] Each prompted Tool Confirmation records call id/name, decision and any matched Dangerous Command rule names before apply; approval followed by apply failure differs from rejection, and unprompted auto execution is not labeled human approval. Keep existing Tool result, bounded `shell` output and Attempt entries intact; distinguish whole-batch correlation errors and interruption without fabricating a successful execution. Exercise plan/build/auto and normal/Strong Confirmation with harmless fakes.
- [x] New Audit Events redact known credentials in user-controlled/external values using active and previously entered Runtime Configuration keys and Tavily where relevant, but preserve schema field names and fixed controlled event/outcome/state values even if a known key equals `name`, `ok` or `auto`. A user-supplied value with the same spelling still gets redacted. Check a successful `outcome: ok` and mode transition to `auto` with colliding keys; no false outcome or broken field names. Existing `turn_end`, Tool, clear/undo/compression lines and `load_conversation` behavior remain unchanged; a fresh and Resumed Run retain their normal mode and Conversation despite extra Audit Events. Dynamic keys within Tool arguments belong to ticket 02, not this correction.
- [x] Script both piped `run_repl` and interactive Input Box mode-toggle/`/config` paths with fake Provider and Tool confirmations. Parse the Call Log, check event order, absent sensitive text, failures/rejections and replay after Resume; run the offline tests. Do not implement the opt-in file or add a new REPL reader here.

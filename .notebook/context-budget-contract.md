# Context budget contract (0037/01, updated by 0037/06)

Configuration: `routing/runtime_config.py:load()` validates positive decimal budgets and exact Provider/model records. `RuntimeConfig.snapshot()` copies settings into immutable mappings for a task. `terminal/repl.py:_edit_context_config()` persists before activation.

Capacity: `context_budget.py:resolve()` normalizes only positive integer `max_input_tokens` and `max_output_tokens` from `get_model_info()`, with separate provenance. The locked LiteLLM 1.102.0 `types/utils.py:ModelInfoBase` and bundled `model_prices_and_context_window_backup.json:sample_spec` document these as input/output ceilings; legacy `max_tokens` can mean either, so it is ignored. No documented total-capacity field exists in this source version, so a valid published `max_input_tokens` is used as the known total (a conservative lower bound; 0037/06). 0054/03: a frozen `RuntimeConfig.offering` (Models.dev, same pair only) replaces total/input/output per field before manual overrides, so precedence is manual, `Models.dev`, LiteLLM, then `unknown; assumed` 128000. Models.dev prices are never read. Input and output maxima are never summed. OpenRouter ceilings describe the model, not its unpinned upstream. Manual fields replace their corresponding metadata fields.

Measurement: each Provider's `prepare_input()` supplies the same model-facing input used by dispatch. `token_estimate.py:render_input()` validates and deterministically renders Unicode JSON. `estimate()` calls LiteLLM's text-only counter, identifies o200k/cl100k encoding, and labels generic fallback approximate. Credentials and transport/output controls are absent. Local cl100k/o200k assets are SHA-256 validated before loading; missing/corrupt custom caches use bundled assets or counting stops. Import uses the bundled cost map, disables development dotenv loading and HF downloads, and never supplies fabricated counts. `tests/test_context_budget.py:test_real_locked_counter_is_offline_repeatable_and_counts_tokens` proves zero socket-connect/DNS attempts in fresh processes.

ChatGPT (0057/0058): `runtime_config.admit_chatgpt()` binds account model choices independently of Models.dev; available public metadata can complement capacities. The same local output reservation is an estimate: `providers/chatgpt.py:call()` omits `max_output_tokens`. The account-model reasoning preference is snapshotted with the task and sent separately from prepared input; `auto` omits request effort. See [current decisions](../docs/CONTEXT.md#decisions).

Output/termination REST sources checked 2026-10-01:

- [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create): `max_completion_tokens` bounds visible and reasoning output together.
- [OpenRouter reasoning](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens): request `max_tokens` shares the completion budget; `provider.require_parameters` is sent even without Tools. Gemini thinking guidance below confirms its combined allowance; an effort level is not a token cap.
- [Anthropic Messages](https://platform.claude.com/docs/en/api/messages/create): `max_tokens` is the generation maximum; enabled thinking counts toward it. Separate cache-read/creation input counts are added to input occupancy, preserving existing cost/completion semantics.
- [Gemini generateContent thinking](https://ai.google.dev/gemini-api/docs/generate-content/thinking): the legacy endpoint's token-limit section explicitly documents a hard cutoff including thoughts and visible output for 2.5/3. [REST field reference](https://ai.google.dev/api/generate-content): `generationConfig.maxOutputTokens` and `finishReason=MAX_TOKENS`. The similarly named main thinking guide now describes Interactions and is not the endpoint reference used here.

`routing/router.py:_run_exchange()` enforces the local ceiling on initial/retry/Tool/manual-Compression exchanges before creating an Attempt. Length termination is retained for Compression rejection. Full history is available. Preventive Compression (soft 80% trigger only with eligible older turns; summary-only reduction only above the ceiling or in recovery), soft-only failure that proceeds within the ceiling, and one overflow recovery retry live in the same gate.
